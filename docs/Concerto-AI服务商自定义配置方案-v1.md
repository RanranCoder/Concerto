# Concerto AI 服务商自定义配置方案 v1

日期：2026-10-31。状态：已落地双原生协议与组织级设置，验证与部署说明见 [实施记录](design/ai-services/README.md)。

## 1. 目标与范围

在「系统设置 → AI 服务」中管理 Concerto 的模型服务配置，支持填写显示名称、Base URL、API Key 和请求模型 ID，通过测试后设为当前组织默认服务。保存后无需重启，后续任务使用新配置。

首版采用以下业务约定：

- 配置归属当前组织，由具有 `org:manage` 权限的管理员维护；普通成员使用组织默认服务，不维护个人密钥。
- 支持保存多个配置，每个配置对应一个端点、一把密钥和一个模型；每个组织最多启用一个默认配置。
- 首版同期原生支持 OpenAI Chat Completions 与 Responses 两套协议，配置中显式选择协议；两套客户端独立实现，不互相转译，不做厂商字段映射。
- 未设置组织默认配置时沿用现有部署配置；界面明确显示当前配置来源。
- 本期不加入会话内模型选择、自动服务商轮换、价格统计和模型市场。

上述组织范围及单默认策略是本方案的产品默认值。

## 2. 入口与界面

沿用 `/admin/settings`，新增 `section=ai` 分类「AI 服务」。现有路由已有 `org:manage` 限制；服务端同步检查权限和组织归属。

右侧按以下顺序呈现：

1. 当前服务面板：显示名称、请求模型 ID、来源（组织配置／部署配置）、最近测试结果；测试结果标注时间，不冒充实时健康状态。
2. 服务配置列表：显示名称、Base URL、模型 ID、默认标记、最近测试时间；操作为「编辑」「测试连接」「设为默认」「删除」，面板右上角为「新增服务」。
3. 新增／编辑抽屉：四个字段、测试结果、底部取消和保存按钮。创建成功只保存配置，设置默认是单独动作。

无组织配置时显示「尚未添加 AI 服务，当前沿用部署配置」，提供新增入口；若部署配置也不可用，按实际情况显示规则模式或不可用状态。

### 字段规则

| 字段 | 规则 | 交互提示 |
| --- | --- | --- |
| 显示名称 | 必填，去首尾空格，1–50 字符，同组织唯一 | 用于列表与当前服务标识，不参与模型请求 |
| Base URL | 必填，最长 2048 字符，绝对 URL，无账号密码、查询参数或 fragment | 填 API 根地址，例如 `https://ai.example.com/v1`，不包含 `/chat/completions` |
| API Key | 新增必填；编辑默认留空表示保留；输入新值则替换 | 密码框，已有配置仅显示「密钥已保存」，不回填原密钥或脱敏占位字符串 |
| 请求模型 ID | 必填，去首尾空格，1–200 字符，无换行及控制字符 | 按服务商提供的标识原样填写，区分大小写，与显示名称独立 |

协议类型为必选项：`Chat Completions` 或 `Responses`。Base URL 只移除尾部 `/`，保留路径前缀；按协议追加一次 `/chat/completions` 或 `/responses`。若填写完整接口路径，提示修正，避免重复拼接。默认仅支持 HTTPS，内网 HTTP 服务由部署维护人员显式开放。

### 系统 UI 对齐要求

- 复用 `Settings.tsx` 的 `admin-v6`、`admin-settings-layout`、`admin-rail` 布局。
- 复用 `PageHeader`、`Panel`、`StatusTag`、`LoadError`、现有表单容器及 Ant Design 输入、按钮和抽屉组件。
- 颜色、字号、圆角、间距、边框和反馈状态沿用现有主题 token；同时适配浅色、深色。
- 桌面使用现有管理列表风格，移动端使用记录卡片；抽屉在窄屏采用现有响应式规则，操作区保持可达。
- 校验错误在字段下方呈现；测试结果在表单内持续显示，成功提示可使用现有 message。
- 表单切换分类、关闭抽屉和离开页面时处理未保存修改；键盘可操作，状态不能只靠颜色表达。

## 3. 业务流程

### 新增与启用

管理员新增 → 填写四项信息 → 测试当前表单值 → 保存 → 列表中设为默认 → 后续新任务生效。

允许保存未经测试或测试失败的配置，状态为「未验证」或「测试失败」；设为默认要求当前版本通过普通请求、流式响应及工具调用兼容性测试。测试会发送少量固定测试内容，按钮附近提示可能产生少量调用费用，不携带组织业务数据。

### 连接测试

所有测试由后端发起，不能由浏览器携带 Key 直连。分别验证鉴权及模型响应、SSE 流式返回、工具调用及工具结果回传；工具测试使用固定虚拟工具，不执行真实业务操作。没有推理内容不视为失败。

结果包含测试时间、耗时、各项能力结果和脱敏错误；区分鉴权失败、模型不存在、地址不可达、超时、限流、余额或配额异常、协议不兼容。根据响应可确认的内容展示，无法确定时不猜测错误原因。

未保存的草稿也可测试。服务端将成功结果绑定组织、配置版本或规范化字段摘要及密钥版本，保存时校验一致性；不能信任客户端传入的“测试成功”。地址、Key、模型改变后测试立即失效，单独修改显示名称不失效。建议测试有效期 30 分钟，过期后启用前重测。

### 修改、切换与删除

- 非默认配置可直接保存；默认配置的连接字段修改采用待验证版本，测试并保存成功后原子替换，失败时当前生效版本继续运行。
- 切换默认配置原子执行，界面明确说明影响当前组织后续任务；活动默认配置不可直接删除，需先切换或选择「恢复部署配置」。
- 每次任务启动时固定配置版本；同一任务的工具循环、摘要和子任务使用相同配置。进行中的任务不因设置更新而混用服务商。
- 若恢复会话需启动新的模型任务，使用当时的组织默认配置；记录实际使用版本以便排查。
- 自定义服务调用失败时沿用现有错误／降级机制并明确反馈，不静默把业务数据发送给另一个商业服务商。

## 4. 数据与接口建议

新增组织级 `agent_provider_config`：`id`、`org_id`、`display_name`、`protocol`（`openai_chat_completions` 或 `openai_responses`）、`base_url`、`model_id`、`api_key_ciphertext`、`key_version`、`version`、`last_test_status`、`last_tested_at`、`capabilities`、创建／更新人和时间。

组织默认指针独立保存 `org_id → config_id + active_version`，通过事务或条件更新保证单默认；默认生效版本应有可供活动任务持有的不可变快照。测试记录关联配置版本和字段摘要。删除时保留必要审计信息，不保留已无使用需要的明文或密钥副本。

建议 API（具体前缀对齐现有后端约定）：

| 方法与路径 | 用途 |
| --- | --- |
| `GET /api/agent/providers` | 当前组织配置列表及当前生效来源 |
| `POST /api/agent/providers` | 新增配置 |
| `PUT /api/agent/providers/{id}` | 更新，带 version 防覆盖 |
| `DELETE /api/agent/providers/{id}` | 删除非默认配置 |
| `POST /api/agent/providers/test` | 测试草稿；可携带配置 ID 复用已存 Key |
| `POST /api/agent/providers/{id}/activate` | 校验测试与版本后设为默认 |
| `DELETE /api/agent/providers/default` | 恢复部署默认配置 |

所有接口的组织 ID 从服务端登录上下文取得。返回值只有 `hasApiKey`，不包含密钥密文或原文。编辑时省略 API Key 表示保留，拒绝空白替换值；新增时校验非空。所有配置 ID 操作都检查组织归属，包括复用密钥的草稿测试。

## 5. 接入现有 Concerto

改造前：`AgentProperties` 提供部署级配置；`LlmConfig.primaryProvider()` 在启动时构造 `DeepSeekProvider`；后者使用 `baseUrl + /chat/completions`。本次已替换为双原生协议及任务级配置解析。

建议增加 `AgentProviderConfigService`、`ProviderResolver`、`OpenAiChatCompletionsProvider` 和 `OpenAiResponsesProvider`：

- Resolver 按服务端组织上下文选择组织生效配置，否则选择现有部署配置。避免修改共享 `AgentProperties` 或向单例写入组织密钥。
- 移除 `DeepSeekProvider` 及专用协议逻辑；现有部署地址、密钥和模型作为配置来源迁移到显式选定的原生客户端，保留 Stub 降级。删除 `thinking`、`reasoning_content` 的发送、解析和回传，不以厂商扩展维持旧行为；两套客户端分别实现原生工具调用、SSE、取消、超时和 usage 解析。
- 现有会话上下文和摘要相关调用一并审计接入，不能只替换主聊天调用。
- 缓存按组织与配置版本隔离；多实例通过版本检查或事件失效保证下一任务生效。客户端资源在活动任务结束后释放，避免每轮新建连接池或永久缓存旧密钥。
- 任务记录保存服务配置 ID、版本、请求模型和响应实际模型（若服务返回），界面显示名称不替代内部 provider 标识，兼容已有 `provider/degraded` 判断。
- 延续现有权限、数据分级、脱敏和工具确认策略；更换模型不能绕过这些约束。

## 6. 密钥与端点处理

- Key 在服务端加密保存。默认自动生成并持久保存加密主密钥，无需管理员手动配置环境变量；数据库仅保存主密钥指纹。保留显式环境密钥用于已有部署及多实例场景。已有密文但原主密钥丢失时禁止重新生成覆盖，要求恢复原始密钥。
- 日志、异常、审计、浏览器存储和导出均不记录 API Key；请求头和提供商原始报错统一脱敏。
- 新增、修改、测试、切换默认、删除记录管理员审计；测试接口限流并设置连接、读取与总时限，避免测试占满编排线程。
- Base URL 是服务端外连入口，需要校验 DNS 解析后的目标地址，默认拒绝回环、链路本地、云元数据和私网地址；禁止跳转或逐跳重新校验。内网模型通过部署侧白名单开放，不允许表单自行绕过。
- 并发更新使用版本冲突提示，不能覆盖其他管理员刚保存的密钥或默认配置。

## 7. 实施顺序与验收

1. 数据库迁移、加密及组织权限接口；完成配置 CRUD、测试与原子启用。
2. 通用适配器与按组织解析，贯通主聊天、摘要、工具循环和子任务，保留部署兼容路径。
3. 系统设置「AI 服务」分类、列表和编辑抽屉，接入真实接口。
4. 完成多组织隔离、热更新和 UI 验证。

必须通过的验收：

- 四项信息可维护，显示名称与请求模型 ID 分离；未配置组织服务时原部署行为保持兼容。
- 普通成员无法读取或修改配置；其他组织不能按 ID 查看、修改、测试或使用本组织密钥。
- 返回数据、日志及浏览器存储无明文密钥；编辑留空保留原 Key，替换 Key 后旧测试失效。
- 带 `/v1`、尾部 `/` 的 Base URL 正确拼接；完整接口地址及不允许的网络目标被拒绝。
- 测试覆盖普通响应、流式返回和工具调用往返；仅聊天成功不能标记为可用于完整 Concerto。
- 设为默认无需重启；切换与修改不影响在途任务，不同组织并发请求不串配置。
- 默认配置删除受限；版本冲突可见；失败不会覆盖当前可用配置。
- 使用模拟服务验证鉴权、模型错误、限流、超时、取消和降级，不使用真实密钥进行自动化测试。
- UI 在浅色、深色及移动端与系统设置保持一致，覆盖空、加载、失败、未保存和测试中状态。

## 8. 双原生协议与推理摘要（2026-10-31 修订）

以用户最新要求为准：移除 DeepSeek 专用逻辑及扩展字段映射；Chat Completions 与 Responses 同期开发，独立遵循各自原生协议。不将 Responses 转成 Chat Completions 请求，不自动切换协议掩盖不兼容。

- Chat Completions 原生使用 messages、content、tool_calls 与对应 SSE，不解析 `reasoning_content`。
- Responses 原生使用 input、output items、function_call、function_call_output 和事件式 SSE；按 call_id 关联工具结果，不沿用 Chat Completions 的工具消息结构。
- Responses 支持请求推理摘要并处理 `response.reasoning_summary_text.delta`，界面命名为「推理摘要」，不称为完整思维链。摘要是否可用取决于模型、服务和账户；没有摘要不阻塞正文或工具执行。
- 系统执行过程与推理摘要分别展示。工具状态、耗时和任务阶段继续来自真实业务事件，不生成虚构推理。
- Responses 的 reasoning items 属于原生会话状态，必须按官方协议保留和回传；工具循环不能只提取回答文字而丢弃必要 items。不可将加密 reasoning 状态解读或展示为推理文本。
- 首版建议采用 `store:false` 的本地状态管理，按服务能力使用原生加密 reasoning items；不假定所有端点都支持同样的状态能力。连接测试需验证选定的会话状态策略与工具连续往返。
- 两套客户端可以复用 HTTP 传输、密钥管理和业务执行调度，但请求构造、响应解析、工具循环状态分别实现。若现有 LlmProvider 的消息模型只能表达 Chat Completions，应调整内部接口以保留 Responses 原生状态，不能强行压平。
- 服务配置增加协议类型；测试按所选协议验证正文、流式、工具往返，Responses 额外检查状态延续，摘要能力单独显示。
- 协议、地址、密钥或模型改变均使测试失效。任务固定协议和配置版本；切换协议后新任务从业务会话内容构造新输入，不把旧协议的不透明状态传给新协议。
- 本期 Responses 范围为文本、流式、原生函数工具调用、推理摘要、取消、超时、用量及会话状态；内置搜索、computer use、音视频等不自动纳入。
- 迁移验收覆盖双协议各自的工具连续往返、断流／失败／取消、摘要有无、原生状态保留、跨协议新任务、历史记录展示、部署配置迁移及多组织隔离。

依据：[OpenAI Reasoning models](https://developers.openai.com/api/docs/guides/reasoning)、[Responses streaming events](https://developers.openai.com/api/reference/resources/responses/streaming-events)、[Function calling](https://developers.openai.com/api/docs/guides/function-calling)。
