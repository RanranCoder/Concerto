## 业务与接口处理

- 管理按钮按真实权限码显示，不按角色等级判断；没有考勤管理查看权限时只调用 `/attendances/my`。无课表制作的批量导入要求 `schedule:manage`。
- 选择活动、进入签到现场只读取数据；用户明确开启或刷新签到才调用生成凭证接口，避免浏览页面就作废已有签到码。
- 发布全部草稿始终带当前 `activityId`，确认页显示具体班次和人次；不跨活动发布。
- 个人课表分析与批量导入无课表保持独立。分析接口只返回聚合人数，因此所选时段展示空闲人数和“参与分析成员”，不把全体参与者伪称为空闲人员。
- 日历使用真实日期，不硬编码开学日期。未设置日期的旧记录按指定教学周查看或通过全部列表访问；周末、无法定位到节次的班次保留可访问入口。
- 例行排班 Excel 导出继续按后端的类型与教学周范围导出，页面明确说明不包含人员关键词；考勤和只读无课表 CSV 导出当前筛选结果。
- 重新生成接口补传已有后端支持的 `semesterStartDate`，用于真实周次过滤。

## 后端必要修正

`ActivityScheduleService` 原实现忽略人工主副班，并在修改或重新生成已发布班次时整批删除考勤。本次修正：

1. 人工保存保留显式主副班；自动生成指定一名主班，其余为副班。
2. 人员变化只移除已不再排班的自动考勤。人工修正记录保留原 ID，使审计仍能关联；保留成员的既有签到结果不重置。
3. 新增人员建立待签到记录；重复发布按人员身份检查既有记录，避免新增重复考勤。同名不同用户按 `userId` 区分。

没有新增数据库迁移。当前 8080 服务由 IDEA 启动，后端修正需要在 IDEA 重新运行后端后生效。
