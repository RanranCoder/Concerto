# V6 灵思 Agent 落地记录

日期：2026-10-14。依据：[已确认原型与设计说明](PAMS-UI-v6-灵思Agent设计说明.md)。正式路由：`/agent`。

## 页面与交互

- 灵思进入全站 V6 外壳，工作区与顶栏直接衔接；系统导航在手机端可收起。
- 左侧提供任务搜索、全部/待确认/已完成筛选与今天/昨天/更早分组。名称、账号、组织与任务状态都来自真实数据。
- 新任务展示活动筹备、排班考勤、内容宣传、资料问答、党务成员和日常事务入口；按账号权限及组织领域包裁剪。点击入口只填入草稿，用户可以修改后发送。
- 输入区统一运行模式、活动关联、自动协作与模型状态；只有标准模式可以确认写入，资料问答沿用独立知识库流水线。
- 正文保留模型实际返回的回复、过程、思考记录、工具下钻与专家协作；没有固定示例响应进入生产代码。
- 工作成果统一通过一个面板打开，含内容、变更、来源三个页签。1250px 以下用右侧抽屉，960px 以下任务列表也用抽屉。来源继续使用服务端引用编号、路径、快照时间及撤回标记。
- 待补信息在对话中直接填写，必填错误就地标注，补齐后转换为确认清单；原有表单组件的弹窗调用方式仍兼容。
- 清单只在对话中确认；跳过与空缺事项在执行、取消及历史回放后保留。切换任务会清空待发送草稿与预览，避免上下文串入。
- 停止的迟到响应和事件不会覆盖后续任务；迟到历史请求也不会覆盖后来选中的会话。连接尚未建立时停止按钮暂不可用，首个过程事件到达后可停止。

## 后端配套

`ConversationStore.list` 批量读取本页会话的任务与最后一条消息，返回每个会话的待确认数量和状态。失败、部分完成、取消、待补充及没有答复的会话不会被当成“已完成”。任务归属及组织隔离继续沿用现有校验。

历史消息现在恢复执行回执、成果与跳过项。普通级别才恢复任务正文与明细，敏感和受限级别不通过新增字段泄露内容。任务 JSON 的读侧同时兼容 MySQL 对象与 H2 字符串包装，确认门禁也使用同一解析器。

排班预览复用 `ActivityScheduleService` 的均衡匹配计算。预览不创建活动、排班、人员或考勤；确认时重新计算并核对候选指纹，变化则拒绝写入并要求重新生成。未匹配或人数不足的时段保留明确空缺。确认后只生成草稿，发布流程仍在活动排班页面完成。
