## 2. 决策先行：品牌色红 → 蓝

### 2.1 为什么这个决策必须单独过

红色在党建系统里有语义（"党建红"），换蓝是**产品身份变更**，不是配色变更。v3 把决策抛回给用户是对的，但"对外一套识别色"不足以支撑结论。v4 把决策成本摆到桌面上，先决策、后执行。

### 2.2 决策矩阵（5 维评分，满分 10，评审判断值）

| 维度 | 保留红 `#DE2910` | 换院校蓝 `#0034A2` | 说明 |
|---|---|---|---|
| 党建语义契合 | 9 | 3 | 红色承载"党建红"天然联想；蓝色无此语义 |
| 官方锚点 | 1 | 9 | 与 gzccc.edu.cn 官网识别一致 |
| 可读性（白字） | 6.5 | 10 | 红 4.74:1 压线 AA；蓝 10.43:1 AAA |
| 改造可控性 | 10 | 5 | 红=零改动；蓝需改登录页 + lingsi 4 处 + theme |
| 对外识别统一 | 3 | 8 | 与院校品牌同源，一站一色 |

### 2.3 推荐：换蓝，但"红色让位不消失"

- **界面系统主色 = 院校蓝**：按钮、当前定位、focus、链接（承继 v3 §3.2 全表实测值）。
- **红色降级为 danger 语义色**：`danger #C0271A` 继承原品牌红的视觉血缘，作为"品牌红的延续"——不可逆操作警示、错误状态仍是红的。
- **仪式性场景保留红的唯一例外**：登录页品牌标题、党建主视觉横幅等**对外展示型区域**允许红色点缀（全站限定 2 处），在 §10 写死范围，防止扩散。

这样同时回答三个问题：语义损失被明示（红退到 danger 与仪式场景）、界面统一达成（一套蓝）、改造成本可控（改的是 token 不是页面）。

### 2.4 备选路径（决策为"保留红"时）

若最终决策保留红为主色，v4 的 P0/P1 只需把 brand 系列 token 换成红的可读版本——白字 4.74:1 不达 AA，需改用深红（约 `#B02318` 起，白字 6.5:1 以上），其余结构、批次、验收全部不变。**方案不白写。**

## 3. 设计原则（6 条，冲突时按序裁决）

1. **内容优先，容器退让** — 高对比元素只有「内容」和「一个主行动」。
2. **层级靠边框与间距，不靠阴影** — 阴影只留给真浮层（下拉、气泡、模态）。
3. **一色一义** — 每种颜色只有一个语义，不可互换。
4. **主色配额：每屏实底主蓝 ≤ 1 个**（新增，见 §3.1）。
5. **token 只有一个来源** — `tokens.css` 唯一出处，antd theme 从它读。
6. **克制的动效** — 只动 opacity/color/border-color，120–160ms。

### 3.1 主色配额与可操作元素清单

**硬规则：任何一屏（viewport）内，主蓝实底元素最多 1 个——通常是该页主行动按钮。** 需要第二个强调的操作一律降级为 outline（brand 描边 + brand-text 文字）。

✅ **允许用主蓝**（"可操作 / 当前定位"白名单）：
- 主行动按钮实底（每屏 1 个）
- Tab 下划线、侧边栏选中竖条（当前定位，小面积）
- focus 光环（`brand-soft` 底）
- 行内链接、面包屑末级文字（`brand-text`）

❌ **禁止用主蓝**：
- 卡片描边、表格行 hover、背景填充、图标默认色
- 按钮实底超过 1 个/屏（第二个降 outline）
- 状态标签底色（归语义色）

> 这条规则直接回应 v3 的隐患：v3 预览里主蓝已出现在 7+ 处，若不立配额，"一色一义"会重新变成"一色到处都是"。

## 4. 色彩系统

### 4.1 token 全表（承继 v3 实测值，仅列修订标注）

| 层级 | Light | Dark | 用途 |
|---|---|---|---|
| page | `#F5F6F8` | `#0E1320` | 整页背景，纯色，删渐变与氛围光 |
| canvas | `#FFFFFF` | `#161F38` | 卡片、表格、表单、弹窗 |
| soft | `#F2F4F8` | `#1D2742` | 表头、侧边栏、选中态 |

边框/阴影：`border #E2E7F0` / `border-strong #D3DAE6`；卡片无阴影；`shadow-1/2` 只给 hover 与浮层。

| token | Light | Dark | 修订说明 |
|---|---|---|---|
| brand | `#0034A2` | `#2563EB` | 承继；深色按钮底不用 `#0034A2`（3.16:1 不足） |
| brand-hover | `#0045D6` | `#3B7BF0` | 承继 |
| brand-active | `#002B85` | `#1D4FD8` | 承继 |
| brand-soft | `#E7EDFB` | `rgba(37,99,235,.18)` | 承继；**对比度按合成色核算（§8）** |
| brand-text | `#0034A2` | `#7FA6F0` | 承继 |
| accent 琥珀 | `#FFA811` | `#FFA811` | 承继，记号色边界见 §4.2 |
| accent-text | `#9A5B00` | `#E0A854` | 承继 |
| danger | `#C0271A` | `#F0735C` | **明示为"品牌红血缘色"（§2.3）** |

语义色（success/warning/danger/info）与文字色全表承继 v3 §3.3/§3.4 实测值，`info` 保持青色（避开同屏两种蓝）。

### 4.2 琥珀 vs warn 分工（解决 R3）

| | 琥珀 accent `#FFA811` | 语义 warn `#9A5B00` |
|---|---|---|
| 性质 | **系统级注意力记号** | **业务状态** |
| 出现位置 | 全局提醒、异常指标点、装饰线、图表高亮 | 状态标签、提示条、进度条 |
| 触发条件 | 需要用户"看一眼"的跨页面异常 | 业务数据的固定状态值（待审核、临期） |
| 同屏规则 | 与 warn 标签**不同时指向同一对象**；组件内二选一 | 同左 |

**判定口诀：值变了用 warn（状态标签），该看了用琥珀（记号）。**

## 5. token 与字号（修订 R6）

| token | 值 / 行高 | 用途 |
|---|---|---|
| `--fs-caption` | 12px / 1.5 | 辅助、时间、免责 |
| **`--fs-cell`** | **13px / 1.5（新增）** | **表格单元格、密集菜单** |
| **`--fs-body`** | **14px / 1.65（修订：原 13px）** | **正文、表单标签、长文** |
| `--fs-title` | 16px / 1.4 | 卡片标题 |
| `--fs-h2` | 20px / 1.3 | 页面标题 |
| `--fs-stat` | 24px / 1.2 | 统计数字 |

理由：中文 13px 正文在低分屏/浏览器缩放下可读性不足，14px 是中文界面的安全基线；表格密度靠 `--fs-cell` 13px 保持。字号刻度合计 6 个值（12/13/14/16/20/24），字重仍只用 400/500/600。

## 6. 壳层与页面模式

### 6.1 壳层（承继 v3 §5）

侧边栏贴边实心 200px（soft 底 + 1px 右边线）、header 52px 带底边、选中态 = soft 底 + 3px 主蓝竖条、内容区 `max-width 1440px` 居中。登录页保持暗色壁纸独立，仅同步主按钮 token。

### 6.2 页面模式（承继 v3 §6）

A 仪表盘 / B 列表 / C 详情 / D 表单 / E 工作台，5 个模板；表格规范（soft 表头、无斑马纹、行高 10px 12px、操作列右对齐）与状态标签规范（浅底同色文字、无边框、4px 圆角）承继 v3 §6.1/§6.2。

### 6.3 深色主题：随批验收（修订 R5）

- **切换策略**：跟随系统 + 手动覆盖开关（localStorage 记住选择）。
- **验收方式**：每批验收清单带 dark 列；巡检按 **5 个模板各抽 1–2 个页面**（A 仪表盘 / B 列表 / C 详情 / D 表单 / E 工作台），模板通过即视为全站覆盖——39 页共享同一套 token 与模板结构，无需逐页双跑。
- **深色专属问题清单**：`brand-soft` 合成色上的蓝字（§8 修正口径）、浮层 `shadow-2` + border 在深底的可辨度、Table header 与 body 的分界。

## 7. antd 高风险配置：P0 spike（修订 R4）

新增**第 0 批**，在最小页面（一个空路由 + 一个菜单 + 一个表格）上验证 5 项配置，**全部通过才允许进 P1**：

| # | 配置 | 风险点 | 验证方式 |
|---|---|---|---|
| 1 | Menu 选中态 = transparent + 左侧 3px 竖条 | antd Menu 默认是整块选中底色；竖条需 indicator 或自定义方案 | 截图确认无底色、竖条对齐 |
| 2 | `colorBgElevated` = canvas（浮层同白） | 弹窗/下拉与页面同色，仅靠 shadow-2 + border 区分 | 深色主题下弹窗可辨性 |
| 3 | Table `headerSplitColor: transparent` | 表头与卡片边界是否仍清晰 | 白底无分割线场景 |
| 4 | Input/Select focus = 3px `brand-soft` 光环 | antd 5 的 focus 阴影覆盖规则 | 焦点态光环可见且不溢出 |
| 5 | dark token 全套渲染 | `#2563EB` 按钮底、`#7FA6F0` 蓝字、青色 info 同屏 | 深色下三种蓝可区分 |

**判定**：5 项任一失败 → 先调整该配置的实现路径（如 Menu 竖条改 CSS 变量注入）再重跑 P0；P0 不通过不进入 P1。成本半天以内，避免在 39 个页面上返工。

## 8. 验收标准（修订 R7：合成色口径）

1. **构建与测试**：`npm run build` + `npm test` 通过（含 token 一致性断言）。
2. **视觉零残留**：`backdrop-filter` / `--glass-` 为 0；`box-shadow` 只剩 `shadow-1/2`。
3. **token 收敛**：`border-radius` 只出现 4/6/8/10/999；`font-size` 只出现 12/13/14/16/20/24。
4. **对比度按合成色核算**：凡"色文字 + 半透明底"组合（如 dark 的 `brand-soft: rgba(37,99,235,.18)`），先做 alpha 混合到 canvas 得合成色（约 `#192B58` 一类），再算对比度；验收表列出**合成色与比值**，禁止把 rgba 直接当 RGB。
5. **主色配额**：每屏实底主蓝 ≤ 1；按 5 个模板页 grep + 目检抽查。
6. **双主题随批验收**：按 §6.3 模板抽样，明暗各一遍。
7. **一致性**：对照 `design-preview.html`（修订版）逐项比对色块、字号、圆角、组件状态。

## 10. 明确不做的事（承继 v3 + 新增约束）

- ❌ 不改后端、数据库、路由、权限。
- ❌ 不引入 CSS-in-JS / Tailwind / 新 UI 库；继续 antd 5 + 原生 CSS 变量。
- ❌ 不动 `lingsi.css` 布局与结构；不可逆操作警示保留 danger 红。
- ❌ 不做第三套主题、不做主题色自定义。
- ❌ **红色仅限 2 处仪式场景（登录页品牌标题、党建主视觉横幅）+ danger 语义**，其余一律院校蓝体系——防止"红色让位"变成"红色蔓延"。
- ❌ 不为了好看加插画、渐变、玻璃、发光。
- ❌ **本方案执行前不改任何 UI**（本文仅为评审与决策使用）。

## 11. 决策项（3 个，比 v3 收敛）

1. **品牌色**（§2 矩阵）：推荐换蓝 + 红色降 danger 与 2 处仪式场景；备选保留红（P0/P1 只改 token 值，其余不变）。
2. **深色主题切换策略**：跟随系统 + 手动覆盖（默认推荐）；如只做浅色，删 §6.3 的 dark 列即可。
3. **P0 spike 是否先做**：推荐做——半天成本换 39 页不返工。
