# PAMS UI 设计方案 v6：明暗主题校园办公界面

日期：2026-10-14。范围：全系统，重点展示工作台、活动列表与活动详情。配套原型：`PAMS-UI-bright-v6.html`。保留 v5 供对比。正式前端落地情况见 [PAMS-UI-v6-落地记录.md](./PAMS-UI-v6-落地记录.md)，智能协作与党务台账按后续要求仅适配颜色。

## 这版的结论

采用院校蓝作为主品牌色，青绿与暖橙用于辅助分类，白色与中性灰承载表格和文档。色彩集中在今天日期、日程类型、待处理状态和文件入口。统计区使用连续摘要，容器圆角收为 6–10px，增加审批节点、材料清单与清楚的责任人信息。

v5 的浅蓝、薄荷绿、奶黄和淡紫被近似均等地分配到卡片上，容易产生通用模板感。v6 改变颜色分布及页面结构，让工作安排与活动准备成为主要视觉内容。这是针对 PAMS 的设计判断，并非行业规范规定“某种颜色有 AI 味”。

## 配色与层级

六个基础色：院校蓝 `rgb(22, 104, 220)`（`#1668DC`）、青绿 `#138375`、暖橙 `#C17B20`、纸白 `#FFFFFF`、浅灰背景 `#F4F6F9`、正文墨灰 `#263243`。

根据指定的新蓝色重新适配：青绿保持冷色方向，暖橙提供暖色平衡；浅蓝面使用 `#E6F4FF`，边界与日期分隔使用 `#BDE1FF`，今日列使用 `#F0F7FF`。主蓝、青绿、暖橙分清主次，文字和图标使用各自适合对比度的深浅阶。主色的衍生阶通过项目已有的 `@ant-design/colors` 生成，辅助配色根据亮度、用途与对比度调整。

主操作默认 `#1668DC`，悬停 `#094BB5`，按下 `#00328F`，均配白色文字。主色与活动类别为不同的语义变量，当前采用同一蓝色以保持一致。

| 角色 | 色值 / 背景 | 使用范围 |
| --- | --- | --- |
| 品牌与主操作 | `#1668DC` / `#E6F4FF` | Logo、选中导航、主按钮、今天日期 |
| 活动分类 | `#1668DC` / `#E6F4FF` | 活动日程边条和分类小标记 |
| 排班分类 | 图标与边条 `#138375`、文字 `#0E6D62` / `#EDF7F3` | 值班日程和排班入口 |
| 文书分类 | 图标与边条 `#C17B20` / `#FFF6E8` | 材料截止与文书图标，类别文字用 `#8C520F` |
| 待审核 | 文字 `#8C520F` / `#FFF3E0` | 审核状态、临近截止提醒 |
| 已完成 | 文字 `#267549` / `#ECF6EF` | 完成与归档结果 |
| 错误或逾期 | 文字 `#BB3344` / `#FDEEF0` | 失败、逾期、破坏性操作 |
| 灵思局部识别 | `#625A8F` / `#F1EFF7` | 仅用于助手图标与产物标记，不扩展到统计区 |
| 次级文字 / 控件边界 | `#5B6777` / `#7C899B` | 说明、日期、输入与复选框 |

避免预设机械的颜色面积比例。视觉检查三个条件：主操作能立即定位；多数文字由中性深色承载；分类色只覆盖和类别相关的区域。通过深浅、面积和位置建立主次。

分类色和状态色即使看起来接近也使用不同的 token。例如 `category.schedule` 与 `status.success` 分别管理；蓝色的活动安排不会因此被误读为正在处理，因为同时有“活动”类别文字和“待审核”等状态标签。

## 字体、密度与组件

- 字体沿用适合中文办公的系统无衬线：Microsoft YaHei / PingFang SC / HarmonyOS Sans SC，不强制下载字体。页面标题 26px/600、区块标题 16px/600、正文与表格 14px/400、辅助 12px；数字采用 tabular-nums。
- 内容边距 24px，区块间距 20px，内部间距 12–20px；基于 4px 节奏，不为制造留白拉大数据行。
- 控件圆角 6px，面板 10px，状态标签 4px，文件面板 6px；头像圆形。阴影主要用于浮层，正文面板以边框区分。
- 主按钮 36px；移动端触达区域 44px。空态有明确下一步，错误给重试或纠正路径；长标题允许双行，表格时间与状态不换行。
- 表格默认 64px 双行信息行，表头和工具栏同尺度；紧凑行、表头及工具栏统一 48px。字体维持 14px，密度调整主要来自内边距。原型提供标准/紧凑切换。
- 需要排序、批量处理或真正分页时接入现有业务接口。视觉原型中的 6 条活动构成完整演示数据集，顶部统计与列表一致，不伪造翻页控件。

## 工作台

```
工作台 / 组织名称                                新建活动
┌ 今日日期 ┬ 今日活动 / 值班 / 截止事项 ──────────────────┐
└─────────┴────────────────────────────────────────────┘
┌ 连续摘要：活动总数 / 进行中 / 本周排班 / 我的待办 ──────┐
└──────────────────────────────────────────────────────┘
┌ 本周安排：工作日 / 全周 ──────────────┬ 待处理 ─────────┐
│ 白色日历网格，蓝/青绿/橙边条日程     │ 对象 / 截止     │
│ 今日列轻微高亮，周末也能显示活动     │ 查看或处理入口  │
├ 临近活动：状态、准备情况、负责人 ────┼ 快捷入口 ───────┤
│ 按实际活动推进顺序呈现               │ 材料 / 灵思     │
└─────────────────────────────────────┴─────────────────┘
```

工作台名称与日期直接说明当前场景。周历与待处理约 2.3:1，今天日期采用小块实色院校蓝，成为品牌识别点。每个日程写“活动”“排班”或“文书”，配对应色边条，不把每天都装进独立圆角卡片。

全周模式补齐周六、周日；移动端为日期切换 + 当日安排。快捷入口用小图标、标题和说明组成连续行，避免新增大面积的紫色助手推广卡。

## 活动列表与详情

活动页顶部用白色连续摘要，待审核数字暖橙强调；下方状态筛选与搜索工具栏连成一个工作面。表格包含活动名称及部门、状态、任务进度、材料数量、负责人、日期和查看入口。标准与紧凑模式都保留完整文字。行悬停仅轻微变色。

详情进入独立的活动工作页，标题下方放状态、时间、场地和负责人。标签页沿用“概览、策划、任务、签到、材料、评分”。概览主区展示真实的活动阶段：策划→审核→执行→归档；只有这个有序流程使用步骤标记。下面是准备事项和材料清单，侧栏为负责人、截止和复核提示。

原型可从列表或周历进入详情，在策划、任务、签到、材料、评分页切换示例内容。它不实际提交审批、创建活动或保存材料。

## 原型与正式组件衔接

项目当前安装 Ant Design 5.29.3。本次使用官方 antd CLI 查询该版本的 Table token，设计原则参考官网规范。CLI 的 design.md 不支持 v5，因此不将 v6 的组件接口套入项目。实施时以项目 `tokens.ts` 为单一来源，`theme.ts` 负责主题映射；生成 CSS 文件不手改。

院校蓝映射至 `colorPrimary`；页面与容器背景映射至 `colorBgLayout`、`colorBgContainer`；输入边界与弱分割线分别管理；表格使用 `headerBg`、`rowHoverBg`、`cellPaddingBlockMD`、`cellPaddingInlineMD`、`cellFontSizeMD` 控制。活动类别另建 `category.*`，避免把品牌色或状态变量当作通用彩色变量。

静态原型旨在评审视觉与信息结构。上线前仍需对齐权限显隐、真实活动状态枚举、聚合接口与组织主题切换，新增材料完整度指标需确认业务定义。沿用现有 AI 操作确认与数据访问边界。

## 验收标准

主要颜色配对达到对比度目标；颜色均有文字或图形替代；键盘可操作筛选、详情标签与对话输入；390/1024/1440px 无整页横向溢出，宽表格可在自身容器滚动；日历覆盖周末；空结果给明确下一步；顶部统计与演示数据一致；减少动态效果设置有效。

“减少 AI 味”属于视觉评审目标，需要结合真实内容判断。本版通过品牌一致性、业务信息、明确操作和差异化容器结构提升辨识度，不用某个颜色或比例来宣称科学消除模板感。

## 核验与交付

在本机 Edge 无头渲染环境中，检查了 1440、1024、390px 的工作台、活动列表、详情、灵思和规范页，未发现整页横向溢出；宽表格在自己的容器内滚动。验证了状态与名称筛选、日期排序、标准/紧凑切换、详情标签的键盘切换、材料清单、全周视图、手机周末日期切换及导航开关。页面未出现脚本错误。

## 深色方案

新增一套以中性炭灰为主体的独立语义色阶，与亮色版共用信息结构、尺寸和组件。默认亮色；用户可通过顶栏的月亮/太阳按钮切换，选择保存在浏览器本地。链接 `/#dark` 和 `/#light` 可直接预览指定主题。入口加载前先应用主题，降低闪白。

### 覆盖范围与实现要求

原型已将硬编码的白色背景、浅色边框和次级面改为语义变量，覆盖工作台、全周日历、活动列表、紧凑表格、活动详情各标签、策划文档、签到名单、材料列表、灵思、规范页及两个弹窗。表单原生控件通过 `color-scheme: dark` 适配；输入占位文字单独定义。

正式接入时，深色 token 仍由 `tokens.ts` 单一管理，再交给 `theme.ts` 与 CSS。`colorPrimary` 保持 `#1668DC`，链接、选中项文字和焦点需要独立映射，避免直接复用暗背景上偏暗的主蓝；弹窗、表头、输入面、各类别前景/背景都应从对应语义 token 读取。
