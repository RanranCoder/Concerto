## 1. 文档概述

### 1.1 背景

PAMS 系统已完成三期建设（一期基础平台 31 项任务 + 二期活动详情页增强 + 三期签到应签名单），覆盖了活动全流程管理、材料归档、排班考勤、党员发展、素拓加分、模板资产库等核心业务。

本期（第四期）聚焦 **体验升级** 与 **协同能力补全**，围绕 9 项需求展开：座位表可视化编辑、签到名单精细化管理、文件预览/下载增强、素拓活动加分、群聊管理、权限体系重构、无课表智能化、以及全局消息通知。

### 1.2 用户角色

| 角色代号 | 角色名称 | 权限等级 | 核心职责 |
|---------|---------|---------|---------|
| TEACHER | 指导老师 | 5 | 最高权限，监督审核 |
| DIRECTOR | 办公室主任 | 4 | 统筹协调，跨部门审批 |
| DEPT_HEAD | 部门部长 | 3 | 部门内管理，策划审核 |
| STAFF | 干事 | 1 | 部门内执行 |

### 1.3 术语定义

| 术语 | 定义 |
|------|------|
| 活动（Activity） | 系统核心实体，贯穿策划→执行→签到→归档全流程 |
| 材料（Material） | 上传至材料库的各类文件（Word/Excel/PDF/图片等） |
| 模板（Template） | 预设的文件模板（策划书模板、签到表模板等） |
| 素拓（Quality Development） | 素质拓展加分，对学生参与活动的量化记录 |
| 应签名单（Sign-in Roster） | 活动签到时需要核验的人员名单 |

## 3. PRD-F01 座位表可视化编辑器

### 3.1 需求背景

**痛点**：现有座位表功能基于 revogrid 电子表格，操作门槛高，不直观。组织部在筹备活动时需要手动调整 Excel 表格来排座位，效率低下，且无法直观展示过道、不同区域。

**典型场景**：大学教室或报告厅座位排列，本质为矩阵格子布局，但需要支持过道设置和区域划分。

### 3.2 用户故事

> 作为 **组织部干事**，我希望在活动详情页的座位表模块中，通过可视化拖拽方式编辑座位布局，设置行列数、过道位置和区域颜色，以便快速完成活动场地座位安排。

### 3.3 功能需求

#### F01.1 网格编辑器

| 属性 | 说明 |
|------|------|
| 最大规格 | 100 行 × 100 列 |
| 编辑入口 | 活动详情 → 座位表 Tab → 点击"编辑座位表"按钮 |
| 视图模式 | 图标视图（默认）与编辑视图可切换 |
| 操作方式 | 点击格子切换状态（空白/已设座位），拖拽可批量选中 |

#### F01.2 行列配置

| 字段 | 类型 | 说明 |
|------|------|------|
| 行数 | 数字输入 | 范围 1-100，默认 10 |
| 列数 | 数字输入 | 范围 1-100，默认 10 |
| 操作方式 | 顶部工具栏，修改后实时渲染 |

#### F01.3 过道设置

| 属性 | 说明 |
|------|------|
| 设置方式 | 选中某列，在工具栏点击"设为过道"；或在列头右键菜单选择 |
| 视觉表现 | 过道列背景色变为浅灰，宽度变为普通列的 1.5-2 倍 |
| 允许多条 | 支持设置多条过道（如中间主过道 + 两侧次过道） |
| 取消过道 | 再次点击"取消过道"恢复为普通列 |
| 过道列不计入座位 | 过道列的格子不可设置座位状态 |

#### F01.4 颜色区域

| 属性 | 说明 |
|------|------|
| 预设色板 | 提供 8-12 种可区分的颜色（含无障碍友好色） |
| 自定义标签 | 每种颜色可绑定一个文本标签（如"嘉宾区""党员区""积极分子区"） |
| 上色方式 | 选中一个或多个格子，点击色板中的颜色应用 |
| 填充操作 | 支持按行填充、按列填充、矩形区域填充 |
| 颜色管理 | 工具栏"区域设置"弹窗，管理颜色-标签映射关系 |

#### F01.5 预设模板

| 属性 | 说明 |
|------|------|
| 保存模板 | 当前布局可保存为模板（名称+行列+过道+颜色布局） |
| 调用模板 | 新建座位表时可从模板列表中选择 |
| 预设模板 | 系统内置 3-5 个常见模板（大教室、报告厅、会议室、多功能厅） |
| 模板管理 | 增删改查，支持覆盖更新 |

#### F01.6 交互细节

- **缩放**：支持滚轮缩放（50%-200%），大规格时可拖拽平移
- **坐标显示**：行号（数字）+ 列号（字母 A-ZZ），悬浮格子显示坐标
- **选座状态**：每个非过道格子可标记为"空座""已选""锁定（VIP/预留）"
- **导出**：支持导出为 PNG 图片（用于打印或分享）

### 3.4 数据模型

```
seat_layout（座位表布局）
├── id: BIGINT PK
├── activity_id: BIGINT FK → activity
├── name: VARCHAR(100) — 布局名称
├── rows: INT — 行数
├── cols: INT — 列数
├── aisle_cols: JSON — 过道列索引数组，如 [5, 12]
├── aisle_width_ratio: DECIMAL — 过道宽度倍率，默认 1.5
├── seat_data: JSON — 完整格子状态 [{row, col, type, color, label, state}]
├── is_template: BOOLEAN — 是否为模板
├── template_category: VARCHAR(50) — 模板分类
├── created_by: BIGINT FK → user
├── created_at / updated_at: DATETIME
```

### 3.5 验收标准

- [ ] 可在图标视图直接点击进入编辑模式
- [ ] 行列数可自由调整，最大支持 100×100，无渲染卡顿（< 200ms）
- [ ] 可设置任意列为过道，过道视觉宽度增加，不可放置座位
- [ ] 可为格子设置不同颜色，颜色有文字标签
- [ ] 可保存当前布局为模板，可从模板新建
- [ ] 系统内置不少于 3 个预设模板
- [ ] 大规格（50×50 以上）支持缩放与平移

## 4. PRD-F02 签到名单多次上传与分类管理

### 4.1 需求背景

**痛点**：当前签到模块仅支持上传一份应签名单。实际业务中，活动参与者可能来自不同来源（如各部门名单、嘉宾名单、志愿者名单），需要多次上传并分类管理。上传后缺少批量删除能力，只能逐条操作。

**典型场景**：组织一次大型活动，需要分别上传"文秘部名单.xlsx""组织部名单.xlsx""嘉宾名单.xlsx"，签到时按分组查看。

### 4.2 用户故事

> 作为 **文秘部干事**，我希望多次上传签到名单并自动按文件名归类显示，以便清晰管理不同来源的签到人员；同时能批量删除过期名单。

### 4.3 功能需求

#### F02.1 多次上传与自动分组

| 属性 | 说明 |
|------|------|
| 上传方式 | 活动签到管理页面，"上传名单"按钮可多次使用 |
| 自动命名 | 每次上传的名单自动以文件名（去扩展名）作为分组名 |
| 名称可编辑 | 分组名称支持手动修改 |
| 文件格式 | 同三期，支持 .xlsx / .xls |
| 冲突处理 | 同一分组内重复上传时，提供"覆盖""追加""跳过重复"三种策略 |

#### F02.2 折叠列表展示

| 属性 | 说明 |
|------|------|
| 列表结构 | 分组折叠列表（Collapse），默认收起 |
| 分组标题 | 显示：分组名称 + 人数 + 上传时间 |
| 展开内容 | 该分组下所有人员列表，含核验字段信息 |
| 搜索 | 顶部全局搜索框，跨分组搜索姓名 |
| 排序 | 分组可拖拽排序 |

#### F02.3 批量删除

| 属性 | 说明 |
|------|------|
| 分组级删除 | 每个分组标题栏有删除按钮，删除整个分组及其人员 |
| 批量删除 | 列表顶部"批量管理"按钮进入多选模式，勾选多个分组后批量删除 |
| 人员级删除 | 展开分组后，可单选或多选删除单个人员 |
| 确认机制 | 删除前二次确认弹窗，显示将删除的条数 |

#### F02.4 签到统计增强

| 属性 | 说明 |
|------|------|
| 分组统计 | 每个分组显示已签/未签/总数 |
| 总计统计 | 顶部汇总所有分组的已签/未签/总数 |
| 筛选 | 支持按分组筛选签到状态 |

### 4.4 数据模型变更

```
sign_in_group（签到分组）— 新增表
├── id: BIGINT PK
├── activity_id: BIGINT FK → activity
├── group_name: VARCHAR(100) — 分组名（默认文件名）
├── source_filename: VARCHAR(255) — 原始文件名
├── sort_order: INT — 排序序号
├── created_by: BIGINT FK → user
├── created_at: DATETIME

sign_in_roster（已有表）— 新增字段
├── +group_id: BIGINT FK → sign_in_group
```

### 4.5 验收标准

- [ ] 可多次上传名单，每次上传自动创建分组，分组名默认为文件名
- [ ] 分组名可手动编辑
- [ ] 列表以折叠形式展示，分组标题显示人数和上传时间
- [ ] 点击分组可展开查看人员列表
- [ ] 支持批量选择分组并删除
- [ ] 支持在分组内选择多个人员并删除
- [ ] 删除前有二次确认
- [ ] 全局搜索可跨分组检索姓名

## 5. PRD-F03 材料库文件下载与预览

### 5.1 需求背景

**痛点**：材料库文件列表仅有删除操作，用户下载文件需要进入详情页或使用其他方式，缺少便捷的下载和在线预览能力。

### 5.2 功能需求

#### F03.1 文件下载

| 属性 | 说明 |
|------|------|
| 入口 | 材料库文件列表，每行操作列增加"下载"按钮（图标：↓） |
| 交互 | 点击直接触发浏览器下载，无需二次确认 |
| 权限 | 遵循现有材料库访问权限控制 |

#### F03.2 文件预览

| 属性 | 说明 |
|------|------|
| 入口 | 材料库文件列表，每行操作列增加"预览"按钮（图标：👁） |
| 预览容器 | 全屏遮罩层 + 居中预览框（Modal 或 Drawer） |
| 支持格式 | 见下表 |
| 预览框功能 | 关闭按钮、文件名标题、下载按钮、（图片）缩放控制 |

**格式支持矩阵**：

| 文件类型 | 预览方式 | 优先级 |
|---------|---------|--------|
| 图片（jpg/png/gif/webp） | 内联 `<img>` 标签渲染 | P1 |
| PDF | 内嵌 `<iframe>` 或 `<embed>` | P1 |
| Word（docx） | mammoth.js 转 HTML 渲染（复用策划书编辑器方案） | P1 |
| Excel（xlsx） | SheetJS 转 HTML 表格渲染 | P2 |
| PPT（pptx） | 显示"暂不支持在线预览，请下载查看"提示 | P3 |
| 其他格式 | 显示文件信息 + 下载按钮 | — |

### 5.3 验收标准

- [ ] 文件列表每行有"下载"和"预览"两个按钮
- [ ] 点击下载直接触发浏览器下载
- [ ] 点击预览弹出预览窗口，支持图片、PDF、Word 在线预览
- [ ] 不支持的格式显示友好提示和下载入口
- [ ] 预览窗口可关闭，不影响列表页状态

### 6.3 验收标准

- [ ] 模板名可点击，点击后弹出预览窗口

- [ ] 预览框中提供"使用此模板"快捷操作

## 7. PRD-F05 素拓活动加分

### 7.1 需求背景

**痛点**：当前素拓加分为手动逐条添加，无法关联活动签到名单批量加分。实际业务中，活动结束后需要对签到人员进行素拓加分，逐条录入效率极低。

**典型场景**：第四十期入党积极分子培训班结束后，文秘部需要为所有签到人员加 0.5 素拓分。

### 7.2 用户故事

> 作为 **文秘部干事**，我希望在素拓管理中选择某次活动的签到名单，一次性为所有签到人员批量加分，而不需要逐条手动录入。

### 7.3 功能需求

#### F05.1 活动加分入口

| 属性 | 说明 |
|------|------|
| 入口 | 素拓管理页面，"新增加分"按钮旁边增加"活动加分"按钮 |
| 交互 | 点击打开活动加分弹窗 |

#### F05.2 活动加分弹窗

| 步骤 | 说明 |
|------|------|
| ① 选择活动 | 下拉选择已完成/已归档的活动，支持搜索 |

## 9. PRD-F07 用户密码修改与权限管理

### 9.1 需求背景

**痛点一**：当前系统所有账号默认密码 123456，用户无法自行修改密码，存在安全隐患。
**痛点二**：权限仅通过角色硬编码（TEACHER/DIRECTOR/DEPT_HEAD/STAFF），无法灵活控制谁能访问哪些业务模块和功能。

### 9.2 功能需求

#### F07.1 密码修改

**自助修改**（所有用户）：

| 属性 | 说明 |
|------|------|
| 入口 | 页面右上角用户头像 → 下拉菜单 → "修改密码" |
| 字段 | 当前密码、新密码、确认新密码 |
| 密码规则 | 最少 6 位，建议包含字母和数字 |
| 安全验证 | 必须输入当前密码才能修改 |

**管理员重置**（DIRECTOR 及以上）：

| 属性 | 说明 |
|------|------|
| 入口 | 用户管理列表 → 操作列 → "重置密码" |
| 交互 | 确认后重置为默认密码 123456 |
| 强制修改 | 被重置用户下次登录时强制跳转修改密码页 |

#### F07.2 权限管理

**菜单位置**：用户管理 → 子菜单"权限管理"

**权限模型**：

采用 **RBAC（基于角色的访问控制）** 模型：

```
角色(Role) ←→ 权限(Permission)
用户(User) → 角色(Role) → 权限(Permission)
```

**权限定义**（详见附录B）：

| 权限层级 | 示例 |
|---------|------|
| 模块级 | 活动管理、材料库、签到管理、素拓管理... |

| 数据级 | 仅本部门、跨部门、全部 |

**权限管理页面**：

| 区域 | 说明 |
|------|------|
| 左侧 | 角色列表，点击选中角色 |
| 右侧 | 权限树（模块 → 功能），勾选框设置该角色的权限 |
| 顶部 | "恢复默认"按钮，一键恢复到系统预设权限 |

**预设权限方案**：

| 功能模块 | TEACHER | DIRECTOR | DEPT_HEAD | STAFF |

| 签到管理 | 全部 | 全部 | 本部门 | 本部门 |
| 材料库 | 全部 | 全部 | 本部门 | 本部门查看+上传 |
| 模板库 | 全部 | 全部 | 查看+使用 | 查看+使用 |
| 素拓管理 | 全部 | 全部 | 本部门 | 仅查看 |
| 群聊管理 | 全部 | 全部 | 本部门相关 | 仅查看 |
| 用户管理 | 全部 | 全部 | — | — |
| 权限管理 | 全部 | — | — | — |
| 通知公告 | 全部 | 全部 | 发布 | 查看 |

### 9.3 数据模型变更

## 14. 风险与依赖

| 风险项 | 影响 | 缓解措施 |
|--------|------|---------|
| 座位表 100×100 渲染性能 | 大规格可能卡顿 | 虚拟化渲染（仅渲染可视区域）；Canvas 方案备选 |
| Word/Excel 预览兼容性 | mammoth.js 对复杂排版支持有限 | 仅做预览用途，不要求 100% 还原；提供下载兜底 |
| 通知系统对现有功能侵入 | 需要在多个模块埋点 | 采用事件总线模式，业务代码仅发事件，通知逻辑解耦 |
| 权限管理灵活性 vs 复杂度 | 过于灵活导致配置困难 | 提供预设方案，大部分场景免配置；高级需求再自定义 |
| 无课表 AI 定义模糊 | "AI" 范围不明确 | 本期采用纯计算方案，不引入外部 AI 依赖 |
