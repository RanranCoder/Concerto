# Agent 上下文管理

实施日期：第一批 2026-10-29，第二批 2026-10-30。

## 组装与预算

`ContextAssembler` 统一组装普通对话和专家上下文：系统规则、数据库任务状态、待确认计划、早期用户要求节选、最近完整对话、本轮引用资料、当前任务。当前消息已落库时不重复添加。专家仅保留近期用户要求，其他专家回答由 DAG 的依赖结果提供。

`ConversationStore.context` 在数据库查询时排除工具及系统记录，再以 USER 消息为轮次边界选择历史，避免工具调用挤占窗口。最近轮数配置限制在 1–50。

`AgentLlmCaller` 在流式和隔离调用创建请求前统一执行 `ContextBudget`，因此知识库流水线及专家工具循环也受预算约束。计算包括消息、工具 schema、工具参数和推理回传，扣除输出预留及安全余量。使用 UTF-8 字节数作为保守估值，**不等同于模型 tokenizer 的精确计数**。

超预算时按完整历史轮次移除；当轮引用、用户任务、工具调用 ID、调用参数及推理回传不截断。工具正文允许带明确标记的节选。必须保留的内容仍超预算时返回可操作错误，不带残缺协议调用模型，也不通过 stub 绕开预算。debug 日志记录估算输入和保留消息数，不记录消息内容。

## 历史摘要与按需取证

第二批新增 `ConversationMemory` 和 `ContextSummaryGenerator`。超过近期窗口的 USER/ASSISTANT 消息按 ID 升序分批合入摘要，模型只接收上次有效事项及新增消息，不重新读取全部历史正文。每次组装最多生成一批；首次恢复超长会话时可能尚有积压，检查点明确标识覆盖范围，并保留原文节选和回查工具。

摘要结构包含 GOAL、CONSTRAINT、DECISION、OPEN_QUESTION、REPORT，每条关联真实来源消息 ID。助手自述只允许为 REPORT；非 REPORT 必须至少引用一条用户消息。模型输出必须是合法 JSON，引用 ID 必须出现在本次模型输入中，内容和整体渲染均有预算限制，已有目标不可静默丢弃。新增事项与旧事项的语义合并及纠正替换由模型完成，来源校验不能证明语义一定准确；执行成功仍只依据数据库和工具回执。

新增 V57 为 `agent_conversation` 添加 `context_summary_json`、`covered_through_message_id`、`context_summary_revision`。摘要文档记录已处理来源的 SHA-256 指纹，包括最终未被模型保留的来源，防止通过多次压缩丢失权限依赖。摘要只从已经按留存策略保存、并经出网策略处理的消息生成；写入前再次遮罩手机号等模式敏感数据，不保存推理和工具原始结果。

每次读取重新复核全部依赖来源，分批读取标量投影，避免 JPA 一级缓存掩盖模型调用期间发生的修改。引用 JSON 使用现有 `AgentJson` 兼容 MySQL/H2 的包装差异。撤权、来源删除或修改会使整个摘要失效：先清空摘要和检查点，再从当前可见记录重建。权限失效为读取时检查；当前没有后台即时撤权清理任务。

模型请求期间不持有数据库锁。压缩请求不带工具、不进入回答流，单次尝试默认限时 10 秒，输出最多 4096 token，受主调用上限进一步约束；不执行对话的重试和规则降级流程，避免可选压缩连续占用多次超时。文档与检查点通过 revision 比较一次性更新，携带 orgId、userId、deleted 条件；并发失败者只能读取复核后的胜出版本，不能返回自己未提交的生成内容。会话删除以单次数据库更新清空摘要并增加 revision，迟到生成结果无法复活会话。

生成失败、降级为规则模式、输出截断、格式错误、来源伪造及超出预算均不推进检查点，保留经复核的旧摘要。验证服务临时故障时不使用未验证摘要，也不删除此前有效的缓存，改走原文节选。单条来源本身超过本次输入预算时不截断并标记为已处理，而是延后压缩，仍可使用原文回查工具读取。

有效持久化摘要在后续预算裁剪中受到保护，避免刚生成的长期约束又被当作最旧对话移除；必须保留内容超限时仍显式失败。摘要作为 user 级历史资料传递，不提升为系统指令。

`recallConversation` 只能查询当前身份拥有的当前会话，不能指定其他会话：

- keyword 检索，或空关键词浏览；每次最多 3 条，按 beforeMessageId 继续回查。
- sourceMessageId 定位原文，以 offset / nextOffset 分段读取，每段 300 个 Unicode 码点。
- 每次重新验证会话归属、来源可见性；消息必须属于当前会话，不能读取工具或系统记录。

内置业务专家明确声明历史回查工具；协调者及审查者仍保持空工具作用域。启动时仅升级已知默认作用域，保留自定义配置、提示词和启停状态。

## 当前业务状态

任务状态从数据库读取，优先列出活跃任务，再补充最近任务；只包含 taskId、工具、状态、workItemId、revision、artifactId、artifactVersion 等定位信息。确认令牌、表单参数、敏感结果不进入状态摘要。参数以现有待确认计划为准，执行结果及恢复沿用 AgentRun、AgentWorkItem、TaskGate 和 DAG 回执，不新建第二套执行状态。

多 Agent 不再把历史消息角色压平成字符串，也不再按末尾 12000 字符截断会话历史。引用资料标记为证据，专家读取自己的子任务和已完成依赖节点结果；上下文组装不会扩大工具权限。

## 验证

新增预算和组装测试，覆盖完整轮次、当轮纠正、工具调用与推理完整性、schema 预算、超限拒绝、Unicode、历史撤权、越权回查、分段原文和专家上下文。回归确认流程、DAG 重试、提交后续跑、专家循环及敏感档留存。DAG 的假模型按消息角色寻找任务，避免依赖固定消息下标。

第一批验证：10 个测试类共 55 个用例通过，已单独发布。

第二批验证范围包括：100 轮历史分批追赶、仅处理新增消息、最新纠正与早期目标保留、失败后检查点不变、损坏摘要重建、来源撤权/删除/修改、模型调用期间撤权/删除/SQL 修改、一级缓存绕过、迟到并发结果被拒、租户/用户隔离、会话删除清理、来源读取故障保留缓存、敏感模式遮罩、预算保护、旧会话迁移默认值，以及既有 DAG/确认流程回归。语义场景使用可控模型替身验证协议与流程，未运行真实模型质量评测。

本轮运行 14 个相关测试类，共 89 项用例；包含普通会话 JSON 不得暴露未经复核的摘要缓存，以及并发删除后不得退回旧摘要的检查。

第二批已随提交 `06842df` 推送并部署，服务器单独应用了 V57 的三个新增字段，保留了迁移审计和数据库备份；未执行其他待处理迁移，Flyway 历史未推进。后续仍需沿用既定发布方式，不能为启用记忆而盲目执行所有待处理迁移。
