# 第三批：跨会话长期记忆

实施日期：2026-10-30。当前为代码实现，不包含生产部署。

## 可直接使用的聊天指令

指令必须是用户顶层消息的完整开头；模型回答、工具结果及引号中的句子不会触发写入。服务端直接处理后结束本轮，不让 LLM 决定记忆写入或继续执行其他业务任务。

```text
记住：风格=回答简洁，先给结论
记住：语言=中文
记住：【PROJECT:党建】格式=先列议程，再给分工
查看长期记忆
忘记：风格
忘记：【PROJECT:党建】格式
关闭长期记忆
开启长期记忆
```

项目标签也支持中文写法 `记住：【项目:党建】格式=先列议程`，使用时在问题中带 `【项目:党建】`。

同范围同名称再次明确“记住”表示替换，但必须通过版本检查；并发冲突时要求重试，不覆盖中间发生的修改。聊天写入默认有效期 90 天。关闭后停止读取和新增，保留记录供管理；删除后不会因重新开启而恢复。

## 范围与检索

所有记录都严格绑定认证身份的 orgId + userId。USER 是当前组织内的个人偏好，绝非跨组织共享；PROJECT:名称 是该用户的私有项目标签，也不会对其他用户发布团队规则。

语言、风格、格式、称呼四类 USER 偏好可用于任意任务；其他名称要求出现在当前任务文字中。项目偏好要求本轮用户消息明确带 `【PROJECT:项目名称】`，不会仅因历史消息或专家上游工具结果出现项目名而读取。项目标签是个人笔记分类，不代表拥有对应业务项目的访问权或操作权。

普通会话、知识库模式和专家使用同一检索服务，专家的项目选择依据最近用户消息。单次最多 6 条、1600 个 UTF-8 字节估值，作为 user 级资料放在本轮明确要求之前。当前要求优先，记忆不能代替业务数据、执行回执、审批或确认。知识库没有可用依据时仍直接拒答，不能拿偏好作为知识证据。

## 管理接口

所有接口要求登录；身份与组织来自服务端认证，客户端不能指定其他用户。

| 接口 | 用途 |
| --- | --- |
| GET `/api/agent/memories` | 返回 enabled 和最多 100 条个人记录 |
| POST `/api/agent/memories` | 保存、修改或确认候选 |
| PUT `/api/agent/memories/settings` | `{ "enabled": false }` 关闭读取和新增 |
| DELETE `/api/agent/memories/{id}?revision=1` | 按版本永久删除 |

POST 示例：

```json
{"scope":"USER","key":"风格","content":"回答简洁","consent":true,"days":90}
```

新记录省略 revision；修改或确认已有记录必须携带最新 revision。consent 缺省为 false，只创建 PENDING 候选，不进入模型上下文；候选不能覆盖有效记忆。确认使用相同 scope、key、content，携带 revision 和 consent=true。状态为 ACTIVE、PENDING、INVALID 或 EXPIRED。

本批没有启用自动抽取，也没有增加独立前端管理页面；用户可以直接通过聊天指令管理，前端后续可调用上述完整管理接口。避免在用户没有明确请求时自动保存聊天中的临时参数或业务资料。

## 留存、失效与并发

V58 创建 `agent_memory_setting` 和 `agent_long_term_memory`，不修改旧聊天内容。每个组织内的用户最多 100 条，内容上限 600 字，有效期 1–365 天。模式敏感信息和凭据、默认批准等授权声明拒绝持久化；业务工具确认门禁继续独立生效。

聊天指令保存来源会话、用户消息 ID 和原文指纹。读取时重新核对来源归属、会话是否删除、原文是否修改，以及引用是否仍可见；使用数据库标量快照避开 JPA 一级缓存。失效或到期时清空记忆正文并改变状态，不能继续进入模型。验证异常时上下文跳过长期记忆，不把未验证数据作为备用内容。接口直接保存的偏好由用户直接撰写，没有依附某个聊天来源。

写入、开关和删除用当前用户的设置行锁串行化。写入使用锁定读取获取当前版本，避免 MySQL REPEATABLE READ 旧快照造成关闭后仍写入或覆盖新版本；修改和删除同时校验 revision。模型没有记忆写入工具，不能把外部资料中的“记住”当作授权。

删除长期记忆不等同于删除旧聊天记录：历史仍可回看，当前聊天中已说过的话仍属于该会话上下文；新会话不会从已删除的长期记忆重新读取偏好。删除来源会话则使依附它的长期记忆在下次读取时失效。关闭对后续上下文组装生效，不能撤回已经发出的模型请求。
