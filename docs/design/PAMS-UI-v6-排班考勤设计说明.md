# V6 排班考勤原型

日期：2026-10-14。入口：`PAMS-UI-bright-v6.html?module=routine&page=schedules`。沿用原 V6 文件，工作台、活动管理、灵思与设计依据仍可切换。

## 设计方向

- 配色继承 V6：院校蓝 #1668DC、排班青绿 #138375、材料暖橙 #C17B20、纸白 #FFFFFF、底色 #F4F6F9、墨灰 #263243；深色使用 V6 的相同语义变量。
- 字体沿用系统中文字体；页面标题 24px、区块标题 16px、正文 13–14px、辅助信息 12px。数字使用等宽数字，人员与任务名称左对齐。
- 排班以“节次 × 星期”的工作表为主要视觉；今天列蓝色、值班事项青绿，状态必须有文字。考勤是可筛选表格，详细上下文与修正在右侧抽屉展开。
- 不为每个指标单独做卡片：连续摘要、工作表、流程条承载不同层级。生成时清楚显示数据来源与周次；发布前显示具体范围和人数。

布局：全站侧栏 → 模块页签 → 页面标题和主操作 → 连续摘要 → 筛选工具栏 → 主工作区（工作表/人员表）+ 辅助区（当天班次/数据来源）。移动端主工作区保留横向滚动，侧栏折叠，辅助区下移。

## 关键边界

1. 例行排班维持现有增改删逻辑；草稿/发布/结束/取消生命周期属于活动排班。
2. 活动生成按每个覆盖节次分别匹配无课人员；本次生成范围内按已排次数尽量均衡，不声称已支持全系统时段冲突拦截。
3. 无课表覆盖周一至周五；周末活动走人工排班。开学日期确定周次，缺失时后端跳过周次过滤，原型明确提示影响。
4. 自动生成来源可重新生成；仅已发布活动排班预建待签到考勤，取消排班同步取消自动考勤，人工修正不被覆盖。
5. 签到二维码按活动统一使用；示例展示“演示占位”，不伪造可扫描的真实签到码。打开/关闭/刷新只改变原型状态。
6. 无课表批量导入只保留部门+学期最新结果；重新导入覆盖该结果，不提供虚构历史管理。课表支持 `.xls/.xlsx`；原型不解析真实上传文件。
7. 个人课程表共同空闲分析与导入的周次无课表分开呈现，前者不声称读取批量导入结果；生成活动排班读取后者。
8. 考勤“已签到”沿用后端正常+迟到+补签；原型表格摘要随筛选计算。取消、早退仍可查看；统计口径问题在正式落地时另行核对，不擅自改后端。
9. 原型“管理者/成员”切换用于评审展示差异；真实落地仍由权限码、部门范围和组织隔离控制，不能仅由角色名称决定。

## 可演示流程

- 排班：切换周次与类型 → 点击班次 → 编辑人员/主副班 → 保存；空格可新增；列表筛选、导出当前结果 CSV。
- 活动：选活动 → 生成设置 → 生成示例草稿 → 查看结果 → 发布确认（具体班次和人数）→ 考勤出现待签到；人工创建、重新生成、取消均在页面内同步。
- 考勤：筛选状态或人员 → 记录抽屉 → 人工调整或补签 → 填写原因 → 保存 → 明细与审计同步。
- 无课表制作：编辑个人课表并保存；选择分析人员并查看热力图；选文件或使用示例文件 → 生成 → 失败结果/成功预览 → 查看无课表。
- 成员视角：我的排班、我的考勤、自己的课表；隐藏管理操作。

所有数据与修改仅发生在本地页面内存，不连接后端，不发送通知。重新加载恢复初始数据。HTML 通过相邻的 `PAMS-UI-v6-routine.css` 和 `PAMS-UI-v6-routine.js` 加载扩展，三个文件需一起保留。

正式前端已按审查通过的方案落地，接口与验证说明见 [排班考勤落地记录](PAMS-UI-v6-排班考勤落地记录.md)。本 HTML 仍保留为独立设计原型。
