# 活动甘特图重设计 · 待评审

2026-10-26。用户已完成原型审查并授权落地；实现与验证见[活动甘特图落地记录](PAMS-UI-v6-活动甘特图落地记录.md)。以下保留原型设计依据与审查约定。

## 业务判断

活动拥有独立生命周期；任务属于活动，维护任务名称、部门、负责人、日期、一个前置任务、里程碑、进度、说明。策划书、议程、座位、签到、材料和推文各自有独立业务状态。任务完成不能代替策划审批、推文发布或活动阶段推进。

现状依据：`ActivityOverview.tsx` 的摘要点击回调为空；`Gantt.tsx` 缺少活动身份、搜索筛选与尺度控制，并把执行成员进度更新重复放在图表下方；`GanttChart.tsx` 的任务名与时间轴同时滚动，缺失日期被映射为空字符串，今日线越界时被压到起点，里程碑同时画成时间条和菱形，部门灰阶与红色进度无法清楚表达风险。

## 设计计划与校准

沿用协奏既有工作台。纸白 `#FFFFFF`、页面灰 `#F4F6F9`、正文墨灰 `#263243`、协奏蓝 `#1668DC`、完成绿 `#267549`、风险红 `#BB3344`。所有界面通过已有语义变量支持明暗主题。中文沿用 Microsoft YaHei / PingFang SC 系统字，不引入网络字体；标题 25px、任务 13px、辅助 11–12px，数字等宽。

布局左对齐，部门是分组，颜色只表达任务状态。设计检索生成的作品集网格、粉金配色与此业务不符，明确舍弃；不再添加一排孤立统计卡，采用连续工作区、可点击风险计数和固定任务列。记忆点放在可读且能实际操作的时间轴。

```
返回活动详情                 演示身份 / 新建任务
活动名称 · 任务计划          日期、地点、负责人、当前阶段
任务计划 | 基本信息 | 策划书 | 议程 | 签到 | 材料 | 推文
完成数量与进度                全部 / 逾期 / 前置冲突 / 未排期
风险提示 → 查看风险
搜索 / 部门                 列表·甘特图 / 日·周·月 / 定位今日 / 全部
固定任务名、负责人、状态    | 日期尺、任务条、里程碑、依赖线
部门分组                    | 可横向滚动，纵向同步
图例                        | 日期范围与操作提示
```

## 用户路径

1. **从活动详情进入**：根据本轮审查意见，在“基本信息”之前增加“任务计划”标签，用主题蓝色圆角矩形衬底强调。点击后在活动详情内展示任务工作区，保留活动身份、生命周期与完整九个标签。基本信息中的同源任务摘要可直接进入该标签及对应任务详情。原独立甘特页保留为兼容入口。
2. **组织者排任务**：新增任务可先填名称，稍后补充部门、负责人和日期；没有日期进入“未排期”。选定里程碑时只选一个日期，以菱形展示。新增/编辑用右抽屉，固定标题和操作栏，未保存退出有保护。
3. **日常检查**：默认按部门分组，支持折叠、名称或负责人搜索、部门筛选、风险筛选、列表/甘特切换，筛选结果说明、清空条件和空态均可用。风险可叠加，计数不相加为总任务数。
4. **成员推进**：点击任务或时间条打开同一详情，展示责任、日期、进度、前后置关系和业务页面入口。在详情中修改并显式保存进度；执行成员只展示更新进度，管理员可编辑安排。权限在原型中可切换演示，正式权限必须来自现有授权服务。
5. **调整计划**：编辑日期或拖动时间条后，先预览改期和全部后续任务影响；选择仅保存当前任务并保留风险，或按原工期顺延后续任务。移动预览可取消，保存有撤销。菱形不拖拽，直接编辑日期。原型撤销只针对上次任务写入。
6. **业务衔接**：详情提供策划、签到、材料、推文等页面入口；示例导航按任务内容建议，正式落地需核对业务关联来源。明确标记任务完成不自动改变关联模块或活动阶段。
7. **手机查看**：默认任务列表，每项保留状态、负责人、日期、进度和依赖。仍可主动切换甘特图，时间轴在独立容器内横向滚动，页面本身不溢出。

## 时间与状态口径

- 原型示例基准日 = 活动日期前两天，界面明确标出“演示基准日”，避免历史活动样例使用真实今日后全部过期。活动日与基准日各有独立标线；基准日不在可视范围时隐藏，不吸附到边缘。
- 完成 = 进度 100%；逾期 = 已排期、截止日期早于示例基准日且未完成；待开始 = 进度为 0 且开始日晚于基准日；其余已排期任务为进行中。没有完整起止日期显示未排期，不在日期尺上伪造日期。
- 冲突 = 当前任务开始日早于或等于其前置任务结束日。原型提议采用“前置完成后次日开始”的按天规则，落地前需用户确认是否允许同日交接。冲突和逾期可同时存在。
- 依赖只支持现有 `dependsOn` 单前置字段。禁止自己依赖自己和循环依赖；删除有后续任务的任务时要求先解除关联。
- 里程碑使用单日菱形和日期，仍保留 0–100% 更新能力以兼容当前模型；100% 表示节点已达成。
- 完成比例按完成任务数 / 全部任务数，不使用没有业务定义的工时加权平均。

## 落地差异与需要确认的决策

现有后端仅验证日期先后、进度范围，没有循环依赖校验、批量改期事务、撤销协议，也未同步任务状态和进度。因此本原型的依赖保护、级联顺延、撤销与派生状态是**提案**；正式实施需要服务端一致性校验和事务，不能多次调用单条更新假装原子保存。未排期兼容现有可空日期；新设计允许先建任务，晚些排期。

重点审查：部门分组是否合适；任务摘要到完整工作区的入口；单前置与次日交接的口径；改期时保留风险/顺延后续的选择；执行成员操作范围；手机默认列表。未安排“通知负责人”按钮，避免原型暗示已有通知投递能力。

## 可用性依据

抽屉采用原生 dialog 管理模态焦点、Escape 关闭与返回触发位置，参考 [W3C 模态对话框模式](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)；列表使用原生表格提供非图形阅读路径，参考 [W3C 表格模式](https://www.w3.org/WAI/ARIA/apg/patterns/table/)。具体产品流程是本项目设计提案。

## 审查入口

`V6.html?view=detail&activity=1&tab=gantt#light` 进入活动详情的任务计划标签；`V6.html?view=detail&activity=1&tab=basic#light` 查看高亮入口和基本信息。`V6.html` 无参数默认打开任务计划标签，原 `view=gantt` 独立入口继续可用。工作区“设计说明”提供审查路线及加载、空、错误等示例状态。原型数据仅存内存，刷新恢复，不连接业务接口。
