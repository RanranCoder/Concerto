# 活动管理与详情 V6 设计审查

日期：2026-10-20。状态：已完成原型审查，用户已授权落地。正式代码与验证结果见 [活动管理落地记录](PAMS-UI-v6-活动管理落地记录.md)。下文保留原型阶段的设计与差异说明。

入口：[V6.html](V6.html)。在侧栏选择活动管理，进入任一活动，依次查看 8 个标签页。两个原有 HTML 入口加载同一份 `PAMS-UI-v6-activity.css/js`，其他模块与已有设计保留。

## 第二轮打磨：Word 文档与核心表单

根据本轮审查意见，策划书改为独立的文档工作区。以下内容更新了初稿对应设计：

- 纸张固定为 **210×297 mm 的 A4 纵向**，100% 时按 96 DPI 对应约 794×1123 CSS 像素；每页保持尺寸与比例，深色模式下也始终白底，正文不跟随系统反色。
- 提供适合宽度、75%、100%、125%、150% 的等比缩放；小屏缩放整页或在 100% 下横向滚动，不重新排版纸张。正文在独立 iframe 中渲染，避免全站表格、字体和深色样式污染 Word 原稿。
- 文档目录、版本与审核操作保留在纸张外；审核与版本记录改为右侧抽屉，给纸张留出完整阅读宽度。可展开阅读区，按 Escape 收起。
- “打开 Word”可本地选择 **.docx**，试阅标题、字色、表格、图片、页眉页脚和分页。读取仅发生在当前浏览器，不上传、不自动替换活动策划书。旧版 `.doc` 提示在 Word 中另存为 `.docx`。
- “下载 Word”会把当前原型策划数据生成真实的 A4 `.docx`，包含议程表、页眉页脚、活动内容、流程与保障措施；试阅本地文件时则下载原文件。已验证导出后重新打开的往返流程。
- 使用系统已有版本的 `docx-preview 0.4.0` 与 JSZip，本地依赖副本及许可证放在 `docs/design/vendor/word-preview/`，不依赖 CDN。显式分页与长正文流转到连续 A4 页面；样例的长内容不会通过裁切藏掉。
- Word HTML 试阅不承诺与桌面 Word 像素一致，复杂浮动对象、特殊字体、域代码、跨页合并表格仍需用实际策划模板验收。常见标题、正文、表格、图片与页眉页脚已有真实 DOCX 测试样例。该边界也符合 [docx-preview 官方说明](https://github.com/VolodymyrBaydalka/docxjs)。
- **新建/编辑活动、编辑策划书、创建/编辑推文，以及其他数据录入表单统一改为从右侧滑出的抽屉**。桌面宽 680px，手机全宽；标题和保存/取消按钮固定，内容独立滚动。简短操作确认仍保留居中对话框。
- 活动表单按基本信息、时间地点、组织人员、活动说明分组；策划编辑包含背景、目的、内容、流程、预算、注意事项、应急预案 7 类内容；推文表单按任务安排、稿件内容、审核发布分组。
- 关闭或按 Escape 时，若存在未保存修改，先在抽屉内给出“继续编辑 / 放弃修改”的选择，保留已输入内容。

新增的定向验证见 `docs/design/ui-v6-activity/refined-verification.json`，截图前缀为 `refined-`，包含真实 DOCX、A4 几何、明暗主题、窄屏缩放、固定抽屉操作栏、修改退出保护和导出往返测试。此前逐页表中的文本导出与旧文档布局以本节为准。

## 设计取向

延续协奏的院校蓝 `#1668DC`、纸白 `#FFFFFF`、浅灰背景 `#F4F6F9`、正文墨灰 `#263243`。状态沿用现有明暗主题语义变量：审核用暖橙、完成用绿色、归档用中性色。分类文字与状态标签始终同时出现。

字体沿用系统中文无衬线；页面标题 25px、模块标题 16px、正文与列表 13–14px、辅助信息 11–12px。页面边距 24px，面板间距 18–20px。文档标题使用宋体以贴近现有办公文档。

列表是连续的工作表面：统计摘要 → 状态筛选 → 检索工具栏 → 列表。详情先展示活动身份和状态，再展示业务内容。六阶段顺序与 `activityStatus.ts` 一致：已下达、排期中、策划审核、执行中、已完成、已归档。

```
活动管理       搜索 / 类型 / 部门 / 状态           新建活动

活动详情       活动名称 / 时间 / 地点 / 负责人    编辑 / 推进阶段

```

## 审查重点

1. 列表是否能快速找到活动并识别阶段、负责人和准备情况。
2. 固定的 8 页顺序是否符合日常工作习惯；任务甘特图保留在基本信息与独立页面，不额外占用第九个标签。
3. 策划书是否优先满足阅读和审核，议程是否适合现场查看，座位图是否容易定位人员。
4. 签到是否清楚区分应签范围与实际记录；评分规则与结果是否容易核对。
5. 明暗主题、手机信息卡、标签页横向滚动、键盘左右键/Home/End 导航是否适用。

## 与正式系统的衔接与差异

- 本轮只改 HTML 原型。正式页面依然使用现有 React / Ant Design 与接口。权限按钮必须按现有 `activity:*`、策划审核、签到等授权判定；原型中的示例按钮不代表最终权限。
- 本轮增加部门筛选、任务/材料摘要的展示提案。正式列表需要确认部门字段来源及聚合接口能力，不能从当前分页猜算全局统计。
- 活动日期的创建与编辑保留开始/结束日期；原型以单日活动为主要样例。正式列表应完整展示多日范围。
- “策划未通过时，推进执行提示先审核”是本轮建议的交互约束；正式落地需与后端状态转换规则核对，不能只靠前端限制。
- 策划书历史版本、近期动态与任务甘特摘要为演示内容。正式落地使用真实版本记录、任务与可用的操作记录；没有数据来源的模块提供真实空状态。Word 编辑器、模板导入与完整字段继续沿用现有能力。
- 座位图为 6×8 的布局评审样例；正式布局继续读取现有 SeatLayout，保留 Excel 与布局编辑器。区域颜色读取系统色板，不将本样例的蓝/橙色写死为所有活动的颜色。
- 评分维度支持任意数量；成绩累计与同分名次需与现有后端口径一致。原型维度超过三项时会换行显示，正式落地保留现有增删规则及记录能力。
- 材料上传只记录文件名与大小，不读取或上传文件内容。预览与下载是明确标注的文本示例，不伪造 Word/PDF/XLSX。正式落地复用真实文件预览、下载与材料库关联。
- 签到码区域明确标注不可扫码。真实二维码、有效期、定位与签到规则复用已有功能。设置弹窗是布局示意，不改变本原型的固定示例字段。
- 推文原型支持任务与正文评审。正式落地继续保留现有图片、长图预览、审核/发布与稿件流程，不以任意状态下拉替代实际业务流转。
- 数据仅保存在内存，刷新即恢复；原型不发出应用业务请求。

## 官方参考

- [Ant Design 数据展示](https://ant.design/docs/spec/data-display/)：按重要性与关联组织信息，表格结合筛选和分页，考虑空内容与长文字。本次据此保留活动名称、阶段、负责人和日期的清楚关联。
- [W3C 标签页模式](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/)：标签与面板语义、选中状态、焦点和方向键导航。本次提供左右键与 Home/End 导航。

以上为可用性依据。具体布局与视觉取舍是结合 PAMS 业务所做的设计提案，需要本轮审查后再实施。
