# 协奏 V6：知识库、用户管理与系统设置落地记录

日期：2026-10-19。依据已审查的 V6 原型改造现有业务页面。

## 页面入口与结果

| 页面 | 项目路由 | 本次落地 |
| --- | --- | --- |
| 知识库 | `/knowledge` | 来源侧栏、资料聚合列表、正文与完整分块、人工文档增改、事实快照、个人检索记录、维护确认 |
| 用户管理 | `/admin/users` | 账号摘要、服务端多条件筛选、真实有效权限、角色替换预览、批量启停逐项结果、账号新增与删除确认 |
| 系统设置 | `/admin/settings` | 运行概览、组织与领域包信息、统一管理入口、主题和列表密度偏好、只读存储与基础诊断 |

三个页面复用全站品牌令牌、表单工作面和主题机制。桌面采用表格与分类侧栏；手机切换为逐条账号或资料信息，保留状态与操作。原型示例数据和评审控件没有进入业务页面。

## 知识库

新增 `GET /api/kb/entries`，按知识源类型与记录 ID 聚合。先按当前组织与来源访问权过滤，再计算匹配资料、总数与分页；关键词可匹配任意分块，但列表分块数统计该资料全部可见分块。支持来源、全文或标题匹配方式、更新时间与标题排序。保留原分块接口，详情每次回源校验后获取完整正文。

资料来源链接由知识源适配器生成，避免把策划书 ID 当活动 ID。人工文档编辑保留原附加权限、生效日期与状态，避免表单没有展示的约束在保存时被清空。失败保留表单内容，提交期间防止重复操作。

统计新增 `entryCount` 和个人未答复数 `retrievalUnanswered`，保留人工文档数的原有含义。检索记录增加关键词与成功结果筛选，仍仅限本人；历史命中详情按当前权限重新过滤。事实快照增加标题搜索，保留模板说明、数据截至、生成时间和更新频率。

全量重建与快照刷新放在维护菜单，执行前确认。普通知识库读者不显示录入、编辑和维护入口。

## 用户管理

直接改造现有 `UserList.tsx`，路由保持 `/admin/users`；组织架构传入的 `?deptId=` 继续生效。

服务端用户查询增加学号、主角色、账号状态和管理身份筛选；统计与分页基于整个当前组织，不在前端只筛当前页。新增 `GET /api/users/summary` 提供完整口径的账号统计与角色筛选项。

账号列表单独展示业务主角色与管理身份，管理身份取自所有者与有效委派配置。未完成首次设密的账号与普通停用账号分开统计；列表不提供固定密码重置或明文凭证。

详情通过既有有效权限接口读取真实授权；只有有权账号才查询权限明细。角色替换沿用预览、版本校验与应用流程，预览返回前后真实授权差异。若角色应用成功而账号资料更新失败，界面明确提示，并允许仅重试资料保存，避免重复执行角色变更。

新增 `POST /api/users/status-changes`，每次最多 100 个账号：

- 每个目标独立事务，重新执行组织归属与管理权限校验。
- 只更新账号状态与更新时间，不用旧列表记录覆盖姓名、部门或角色。
- 返回更新成功、无需修改或失败原因，界面保留失败项供核对。
- 所有者、当前操作者及其他管理员遵循既有治理保护；停用管理员仍保留委派身份，普通账号管理员不能借重新启用恢复其管理能力。
- 待设密账号不能通过状态更新跳过首次密码设置。

账号删除放在详情低频入口，输入用户名后确认。花名册开户继续复用 `MemberAccountImport`，包括授权预览、交付、凭证下载与恢复批次。账号新增按 `user:manage` 与 `role:assign` 判断，不额外要求批量开户能力；角色替换仍遵循其独立权限要求。

## 系统设置

系统、组织和知识检索信息分别请求，部分失败不会被显示为正常。基础健康必须实际返回 `pong` 才标为正常；文件目录仅显示配置，不推断读写、可用空间或备份正常。

组织、用户、权限与知识库入口按当前账号可访问范围显示。组织资料和领域包在既有管理入口维护，设置页不另建一套配置写入流程。

主题复用 `useThemeStore`，立即与顶栏同步。用户列表密度通过独立浏览器偏好保存，应用于 `/admin/users`。未保存时离开页面或关闭浏览器会提示；支持保存、放弃和继续编辑。
