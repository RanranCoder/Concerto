# 协奏 V6：知识库、用户管理与系统设置

2026-10-19 · 设计评审稿。本轮仅修改 HTML 原型及其资源，业务前后端保持本轮开始时的状态，等待审查后再实施。

## 评审入口

- `docs/design/V6.html` 默认进入知识库，继续保留 V6 全站导航。
- `V6.html?view=knowledge`：知识库。
- `V6.html?view=users`：用户管理。
- `V6.html?view=settings`：系统设置。
- `docs/design/PAMS-UI-bright-v6.html` 同步加载本次原型模块，支持相同的 `view` 参数。
- 三页底部的“设计说明与能力边界”可查看本页建议；知识库评审说明提供正常、空状态、加载、失败和降级的演示切换。

所有名称、资料、数量、状态和时间均为本地演示数据。用户增改、角色替换、启停、文档录入、重建索引和快照刷新只更新内存，刷新页面恢复样例。主题和用户列表密度保存到当前浏览器的原型偏好，不读写应用数据。

## 设计依据与系统约束

对照现有 README、三页 React 源码、知识库与系统接口、组织架构 V6 原型、角色权限与租户管理落地记录，以及花名册开户入口设计。

给定部署地址访问时跳转到登录页，浏览器读取超时；本轮未完成登录态下的线上视觉核对。功能判断以当前工作区源码和既有设计记录为依据。

参考的行业规范：

- [Ant Design 列表页](https://ant.design/docs/spec/research-list/)：让筛选、定位、比较与进入详情构成连续任务。
- [Ant Design 数据展示](https://ant.design/docs/spec/data-display/)：按信息重要性组织表格，照顾长内容与空状态。
- [Ant Design 数据录入](https://ant.design/docs/spec/data-entry/)：字段标签、默认值、上下文提示及操作反馈保持清晰。

这些规范用于调整信息结构，原型继续使用当前 V6 原生 HTML/CSS/JS 结构。

关键约束：

1. 协奏是学生组织工作台，知识库服务灵思的有据问答，内容连接活动、党务、成员、宣传、通知和档案。
2. 用户账号与成员花名册分开。业务上一个账号只有一个主角色；所有者、组织管理员为独立管理身份。
3. 部门归属不自动产生管理能力。首版业务授权范围为本组织，不绘制尚未实现的部门级授权配置。
4. 知识库条目、统计、完整分块与检索历史都受当前来源权限约束；个人检索历史不扩大为全组织用户问答监控。
5. 事实快照必须显示数据截至时间；生成时间、索引时间不能代替数据时效。
6. 当前系统信息接口只有版本、上传目录和基础健康响应，不能据此推断数据库、磁盘或备份健康。

## 视觉与布局决策

沿用系统现有令牌，避免在管理页面另建视觉风格：

| 用途 | 浅色值 | 设计作用 |
| --- | --- | --- |
| 院校蓝 | `#1668DC` | 主操作、选中状态与链接 |
| 页面底色 | `#F4F6F9` | 区分全局背景与工作面 |
| 内容工作面 | `#FFFFFF` | 表格、详情与表单 |
| 主文字 | `#263243` | 标题和正文 |
| 次要文字 | `#5B6777` | 来源、日期和解释 |
| 暖橙 | `#C17B20` | 文档类别、待处理提示 |

字体延续 Microsoft YaHei、PingFang SC 与系统中文回退。页标题 24px，正文与表格主要信息 13–14px，次要信息 12px，数字 25px。左对齐，保留表格清晰的横向对照；统计采用同一连续条，避免各自浮起的 KPI 卡片。

桌面结构：

```text
全站导航 | 页标题 / 主操作
         | 状态提示 / 连续摘要
         | 来源或分类导航 | 内容工作面
         |                | 筛选 → 列表 → 详情抽屉
```

手机结构：

```text
顶栏 / 抽屉导航
标题 / 操作
两列摘要
横向来源或分类导航
筛选
逐条信息 / 状态 / 操作
```

设计自检：延续已有 V6 的外观，差异放在各页任务结构。知识库用来源和引用路径体现资料工作；用户页用角色与管理身份的并列关系体现治理；设置用分类和只读诊断体现维护边界。取消装饰性大图和独立推广模块。

## 知识库

默认进入内容台账，以资料聚合，减少一份制度被多行分块挤占视线的问题。左侧按业务来源浏览，上方保留全文检索状态、最近成功索引时间与范围说明。

主操作改为“录入文档”；全量重建与快照刷新放入“维护工具”。日常增量更新不需要用户频繁执行维护任务。

台账支持标题、正文和条款关键词搜索、来源筛选、检索方式筛选、排序与分页。详情抽屉展示来源、分类、可见范围、版本、更新时间、正文和引用定位。材料与模板显式标注仅标题匹配，避免误认为附件正文参与回答。

事实快照独立呈现“数据截至”、生成时间与更新频率，内容只显示汇总计数。检索记录仅展示当前用户，区分已引用、没有依据、相关度过低和未标注出处。详情解释“命中 → 权限复核 → 可用依据”，被排除资料不暴露标题或正文。

原型中的完整分块入口只演示一个分块，明确标注为样例。来源入口展示来源说明；正式落地需携带来源记录 ID 定位具体业务详情。

## 用户管理

摘要区回答账号总量、启用数量、待设密数量和管理身份数量。待设密提示引导经办人核对交付状态，不显示真实凭证，也不设计已关闭的固定密码重置入口。

用户列表将姓名与登录账号合并，部门、业务主角色、管理身份、账号状态分列。支持账号状态、关键词、部门、角色和管理身份筛选。选择普通账号后出现批量启停工具条，管理账号受保护。

编辑抽屉分为账号资料、部门与业务角色、登录与状态。角色变化先进入确认页，对比前后角色、示例权限增减和管理身份，再确认保存。示例权限仅用于绘制流程，落地必须由后端真实预览结果驱动。

账号详情展示角色与管理能力来源，并保留停用确认。停用作为日常管理动作；低频的删除入口放到账号详情底部，输入用户名后确认，受保护账号不提供删除。角色发布、管理员委派与治理日志继续由现有角色与权限工作区承担，此次只绘制说明入口，不重绘该页面。

花名册开户入口展示已有流程和交付状态说明，不另造第二套批量开户流程。

## 系统设置

采用四个分类：

| 分类 | 内容 |
| --- | --- |
| 运行概览 | 基础健康、知识检索状态、配置状态、系统信息、常用管理入口 |
| 组织与功能 | 组织资料、通用工作区、党建领域包状态、统一维护入口 |
| 使用偏好 | 即时切换主题、标准或紧凑列表密度、语言与时间口径 |
| 存储与诊断 | 只读上传目录、信息与健康连接检查、尚未检测的数据库 / 磁盘 / 备份 |

组织架构、账号管理与知识库通过已有全站工作区衔接。目录配置不做浏览器编辑，领域包不提供未经能力校验的开关。

主题即时生效；列表密度提供保存与取消。离开设置页前，未保存的密度修改会提示保存、放弃或继续编辑。

## 实施前需要确认的增强项

| 原型表达 | 当前情况 | 后续实施点 |
| --- | --- | --- |
| 资料聚合台账 | 现有台账主要以分块分页 | 明确资料级聚合查询、统计与分页口径 |
| 正文、类型筛选与排序 | 当前能力分散在来源与分块接口 | 核对大数据量下的服务端筛选与检索性能 |
| 可见数量与来源筛选 | 已有权限过滤 | 聚合不得统计或透露不可见来源 |
| 用户状态、角色、管理身份筛选 | 当前主筛选为关键词和部门 | 追加查询条件与精确总数 |
| 批量账号启停 | 单用户更新可用 | 逐账号授权校验、幂等执行与逐项结果 |
| 有效权限与角色变化 | 已有相关接口 | 真实权限差异、版本冲突、预览过期与保护对象反馈 |
| 用户列表密度 | 原型中本地保存 | 接入现有主题 / 偏好机制，定义作用页面 |
| 系统状态聚合 | 系统信息、知识统计分别可用 | 独立请求状态、部分失败与检查时间 |
| 删除账号入口 | 现有业务页面可删除 | 账号详情内低频入口、目标确认与关联影响提示 |

## 原型验证

使用 Playwright 在本地 HTML 上检查，未访问业务接口：

- 三页深链接、共享导航与两个 HTML 入口。
- 来源、关键词、结果筛选、分页及空状态。
- 文档录入、正文抽屉、快照时效、检索原因。
- 用户筛选、受保护账号、角色替换预览与应用、账号启停、新增用户。
- 偏好保存、取消和未保存离开确认。
- 1440px 桌面与 390px 手机、明暗主题、无页面水平溢出。

截图与结果位于 `docs/design/ui-v6-admin/`，`verification.json` 记录检查结果。该验证仅覆盖本地原型，不代表业务 API 或生产环境验收。
