# V6 策划书工作台

本轮为可交互设计原型，入口为`docs/design/V6.html`。正式 React 页面与后端审批接口尚未改造。

## 业务设计

策划书以活动为归属，包含七类正文、活动信息快照、审核意见和版本记录。

- **草稿**：负责人点击「编辑策划书」后，直接在文档正文内修改。文档顶部显示固定编辑栏，支持加粗、斜体、下划线和列表；点击保存后原地回显并持久化，取消则恢复保存前正文并隐藏编辑栏。普通保存不增加版本号，空白章节会阻止提交。
- **提交审核**：通过勾选选择一位或多位审核人，至少选择一位；名单按本次版本单独保存。
- **待审核**：固定提交内容，负责人只读；选定的审核人按章节添加意见、通过审核或填写原因退回。多人审核采用全部通过才完成、任一退回即进入修订的规则，并逐人显示进度。
- **版本可见范围**：负责人及本版本选定的审核人可以查看当前版本。未选中的用户自动展示历史版本，当前版本不会出现在其正文、版本列表、差异对比、A4 预览或下载中。新修订稿清空审核人名单，重新提交时再选择。
- **退回修改**：保留被审核正文与退回原因，另建修订版本；负责人修改后重新提交。
- **审核通过**：保留定稿，继续修改时创建修订稿；活动是否进入执行阶段由负责人另行确认。
- **版本追溯**：历史正文只读，展示实际章节差异；同时冻结当时的活动名称、时间、地点和负责人，避免旧定稿随活动编辑变化。

原型增加了“待审核时撤回并修订”的方案；正式落地需要补充对应撤回接口和权限校验。预览角色切换仅用于体验，正式产品应根据当前用户权限展示操作。

## 页面设计

桌面使用连续三栏工作面：左侧章节目录，中间阅读与原地编辑，右侧审核意见及版本记录。编辑正文不使用侧边栏或弹窗；编辑栏固定在文档显示区域顶部，滚动正文时仍可保存或取消。目录中的提示点区分已填写与待处理意见；点击意见可定位正文。顶部状态区说明当前由谁处理以及下一步操作。

正文阅读采用适合屏幕的行宽；A4 预览使用导出的同一份 DOCX 进行分页，保留缩放和展开阅读。深色主题下，A4 纸张仍为白色。Word 试阅明确为本地文件阅读，不覆盖正在编写的策划书。

手机改为单列，目录横向滚动，审核面板放在正文之后。继续沿用协奏的院校蓝、状态色和现有导航。

## 可体验的交互

1. 使用负责人视角，撤回待审核版本，点击「编辑策划书」直接修改正文；分别体验保存和取消。
2. 保存后刷新页面，确认固定活动示例的正文与格式保留。
3. 处理审核意见，提交时勾选审核人，再切换到已选和未选用户对比可见范围。
4. 添加章节意见、填写退回原因或通过审核。
5. 在版本记录中查阅历史正文和差异，并导出该历史版本的 Word。
6. 切换 A4 预览、缩放或打开本地 Word 试阅。

本地示例的修改按活动分别保存在浏览器；临时新建活动仅保留在本次预览，避免刷新后的活动编号复用导致数据混入。页面底部可重置单个活动示例。

版本可见范围在原型中使用示例用户模拟；正式落地时，后端应对正文、版本、对比、附件及导出接口统一校验当前用户与该版本审核名单，不能仅依赖前端隐藏。

## 验证

已验证章节编辑与刷新保留、待审核锁稿、审核意见处理、提交、通过、退回原因必填、修订留档和历史差异。历史 DOCX 下载后检查了有效 XML 与历史正文，确认不包含后续修订内容。检查了桌面和 390px 手机布局、深色主题与白色 A4 分页。

本轮补充验证：取消编辑恢复保存前内容；原地保存及刷新保留；固定编辑栏与正文滚动区域分离；空审核人选择拦截；两人分别通过后才定稿；未选用户的正文、历史列表、差异、A4 缓存与 Word 下载均不展示当前正文；新修订稿不继承上一轮审核授权。加粗格式已验证保存与 Word 导出。
