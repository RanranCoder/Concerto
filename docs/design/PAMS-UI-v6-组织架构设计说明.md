# V6 组织架构重设计（待审查）

日期：2026-10-18

## 预览入口与范围

- `docs/design/V6.html` 默认打开组织架构，并复用现有 V6 原型的导航、主题和其他业务模块。
- 原 V6 入口 `docs/design/PAMS-UI-bright-v6.html?view=org` 同样可用，左侧新增「系统管理 / 组织架构」。
- 新增的组织架构 CSS、JS 以 `org-` 前缀隔离，不更改正式前端、后端、数据库和现有注册流程。
- 演示修改只保存在页面内存；刷新恢复。「创建演示组织」替换当前预览的组织示例，不创建真实组织。

## 设计取向

沿用协奏已有视觉语言：协奏蓝 `#1668DC`、页面灰 `#F4F6F9`、内容白 `#FFFFFF`、正文 `#263243`、辅助文字 `#5B6777`、分隔线 `#DFE5ED`；深色引用 V6 的对应主题变量。字体沿用项目中文字体栈，标题 26px、节点标题 23px、正文 12–14px，主操作与详情层级清楚区分。

```text
标题与操作                              登录页预览 / 添加一级节点
组织资料摘要                            节点数 / 账号数 / 待设负责人
┌──────────────────┬────────────────────────────────────────────┐
│ 搜索与层级导航    │ 面包屑 / 节点名称 / 编辑与添加下级           │
│                  │ 负责人 / 直属账号 / 含下级账号               │
│ 部门 → 小组      ├────────────────────────────────────────────┤
│ 中心 → 分队      │ 下级节点 / 直属账号 / 节点信息               │
│                  │ 对应内容与关联入口                          │
│ 添加一级节点     │ 删除节点及其限制                            │
└──────────────────┴────────────────────────────────────────────┘
```

页面的主要识别点是可持续维护的架构树。右侧围绕所选节点组织工作，不再把树、编辑表单、邀请码并列为三个互不关联的卡片。编辑在弹窗中进行，避免将「修改当前节点」和「新建下级」混用一个表单。

手机默认显示所选节点，点击「切换节点」展开搜索与层级导航；选中后自动收起。账号表格在内容区横向滚动，页面本身不横向溢出。全部操作有键盘焦点，弹窗支持 Escape，尊重减少动态效果偏好。

## 与登录、创建组织的贯通

原型演示链路：

1. 点击「登录页预览」，由登录入口进入「创建组织」；页脚也提供直接演示入口。
2. 按现有四步流程填写组织信息、组织架构、管理员账号、确认并创建。节点类型仍为部门、中心、小组、分队，支持多层树。
3. 每步独立校验，返回时保留非密码信息；删除包含下级的草稿节点先确认；禁止空架构、空名称和组织内重名。
4. 确认页展示全部层级，可返回修改；扩展功能与创建流程一致，按需选择党建包、志愿包、社团包。
5. 创建成功后保留组织资料、完整架构与管理员用户名，返回登录时不带密码。原型不存储密码，离开密码步骤或关闭弹窗即清空。
6. 点击「登录原型工作台」进入组织架构，看到刚才建立的同一棵树，可继续添加、编辑、设置负责人。

组织显示名称、简称、主题色引用同一份原型状态；编辑组织资料后可在登录预览核对。登录页组织展示不决定账号租户归属，真实登录仍由账号所属组织决定。

管理员账号默认归属首个一级节点，与当前 `OrgService.register` 行为一致。管理员身份不等于节点负责人，创建后负责人仍待明确设置。原型不改变真实登录后的默认首页；正式首登引导可增加进入组织架构的明确入口。

## 系统关系与操作规则

| 内容 | 设计规则 |
| --- | --- |
| 组织根节点 | 表示当前租户，不是普通部门，不提供删除按钮 |
| 组织结构 | 创建时的 `units` 与后台 `/orgs/current/units` 延续同一组 Department 数据；正式落地不复制第二套树 |
| 节点类型 | 类型与父子关系分别表达；类型本身不自动授予权限 |
| 负责人 | 从当前组织正常账号中选择，展示姓名；不再要求手填用户 ID |
| 角色和管理员 | 与负责人分别维护，不因任命而隐式变更 |
| 计数 | 左侧是含下级的账号数；右侧分别标注直属和含下级；停用账号仍占归属关系并阻止删除 |
| 花名册 | 成员管理按届别维护成员记录，与账号列表分别展示，避免将名册人数当成账号数 |
| 批量开户 | 接续现有「花名册批量开户」流程；账号归属、主角色与管理员身份仍在对应管理模块维护 |
| 修改层级 | 当前更新接口不处理父节点迁移，原型不提供拖拽或更换上级；编辑保留原有关系 |
| 删除 | 有直属下级或直属账号时阻止；可删除的节点需再次确认。正式落地还须核对历史业务引用和关联约束 |
| 邀请码 | 当前后端只有生成接口，没有兑换入组流程；作为次级入口展示边界，生成的 `DEMO-` 码不可用于注册或登录 |

原 V6 的成员管理模块使用自己的独立示例数据；本次只提供明确标注的跳转入口，没有将新组织的数据伪装成已同步到旧模块。正式落地时需通过部门 ID 连接，并将当前组织与节点筛选传入对应页面。

## 审查后落地映射

| 原型能力 | 已有实现基础 / 需补足的工作 |
| --- | --- |
| 创建组织 | 复用 `OrgRegister.tsx`、`OrgUnitEditor.tsx`、`orgTree.ts` 的数据契约与校验；注册返回组织 ID、名称和管理员用户名 |
| 架构查询和维护 | 复用 `listUnits / createUnit / updateUnit / deleteUnit`，保留明确的新增和编辑模式 |
| 组织资料 | 复用 `getCurrentOrg / updateOrg / listPublicOrgs`；组织类型目前只展示创建值 |
| 负责人选择与账号计数 | 接入当前组织可见账号查询；不能仅从前端分页中的账号计算总数，正式落地需完整查询或后端聚合 |
| 账号归属 | 复用用户管理与花名册开户流程；梳理节点改名对成员、活动、排班、宣传和档案的关联展示与缓存刷新 |
| 访问控制 | 保持现有组织管理授权，不仅依赖前端菜单；后端继续约束当前租户和可分配角色范围 |
| 资料更新后的主题 | 刷新组织 store 和登录页公开资料，使用项目的主题色规范化逻辑 |
| 删除 | 服务端重新校验子节点、全部关联账号和历史业务引用；原型的前端拦截不能替代服务端规则 |

这些是后续实现边界，本轮只交付可审查原型。
