# 权限一期：迁移确认与回退操作手册

更新：2026-10-26。适用于已运行 V46、完成租户授权初始化的系统。此次实现与演练不代表已批准对现有业务库执行切换。

## 切换前准备

在目标数据库版本的隔离副本中先完成本流程及业务抽查。停写维护窗口内停止旧应用的全部实例、后台任务和其他数据库写入方；预检工具不能代替维护窗口。备份完整数据库及当前应用、前端构建和配置，并演练恢复备份。报告和批准记录包含内部账号编号及授权配置，应按内部敏感配置保存。

升级包提供独立工具 `com.pams.module.permission.service.PermissionMigrationCli`。它直接读取 JDBC，不启动 Spring、不自动运行 Flyway。数据库地址、用户和密码分别通过环境变量 `PAMS_MIGRATION_URL`、`PAMS_MIGRATION_USER`、`PAMS_MIGRATION_PASSWORD` 提供。不要把密码写入命令参数或提交到代码仓库。

以下命令在 Git Bash 中执行；`release.jar` 代表本次打包的后端可执行包。输出文件必须使用未存在的新路径。

```bash
java -Dloader.main=com.pams.module.permission.service.PermissionMigrationCli \
  -cp release.jar org.springframework.boot.loader.launch.PropertiesLauncher \
  report permission-preflight.json
```

报告会读取授权快照、当前投影、角色、账号与部门关联、所有者、管理员委派、领域包、岗位和邀请引用，以及推文／策划的作者关系编号，不读取密码、邀请令牌或正文。

逐组织核对：

- 角色的旧配置、新候选配置、增加／撤销、高影响操作、使用账号、领域包生效情况与旧工作稿候选配置。
- `sourceIssues` 必须为空。发布快照与当前投影不一致时先核实原因并修复，再重新生成报告，不能直接选一个来源覆盖。
- `implicitAuthorReview` 中列出的作者已有对象：确认其新职责是否包含编辑、提交、发布等操作。需要保留时先在旧系统明确调整职责，并重做预检；接受限制时须在所有者确认依据中写清。
- `delegations` 中管理员原可授权清单与细分后的候选职责、管理能力、有效期和版本，以及所有者身份和账号状态。
- 每个存量考勤角色是否保留组织考勤查看和人工修正，不能按“干事／部长”等名称自动判定。
- 姓名记录与账号 ID 的绑定。新版本人排班和考勤不按姓名自动认领，未关联记录需先核对修复。

这是目录授权的影子对比与关系核对报告；具体作者、指定审核人、业务状态、来源附件的行为还需按验收用例抽查。报告不把 ORG 解释成解除业务对象约束。

## 记录所有者确认

由运维人员依据各组织所有者的实际确认记录填写决策文件。工具核验组织所有者编号和账号状态，保存确认依据；它不会代替所有者做决定，也不提供电子签名或代登录。

示例中的编号须替换为报告中的真实组织、账号、角色编号；每个存在存量角色的组织都须提供 `owners` 条目，每个要求考勤决策的角色都须提供 `KEEP` 或 `REVOKE`。

```json
{
  "acknowledgeBusinessChanges": true,
  "owners": {
    "1": {"userId": 1, "evidence": "所有者确认记录的内部编号或受控文件位置"}
  },
  "attendance": {
    "12": "KEEP",
    "13": "REVOKE"
  }
}
```

`acknowledgeBusinessChanges` 表示已确认全部职责映射、作者操作、范围、导出、敏感能力及治理上限。`KEEP` 保留该角色候选中的组织考勤权限；`REVOKE` 明确撤销，均不影响独立的本人考勤权限。工具不会自动把考勤决定反向覆盖已保存的独立工作稿；工作稿仍须正常预览发布。

```bash
java -Dloader.main=com.pams.module.permission.service.PermissionMigrationCli \
  -cp release.jar org.springframework.boot.loader.launch.PropertiesLauncher \
  approve permission-preflight.json permission-decisions.json
```

成功后输出 release ID，并在 `authorization_v2_release` 保存报告对应的旧快照和决策。此步骤只写批准元数据，不切换实时权限。报告被改写、源授权或人员发生变化、目录版本不匹配、遗漏所有者或考勤决策都会被拒绝。

## 执行切换与验收

保持停写状态，启动新版，Flyway V47 在任何目录／投影改写之前检查批准记录及数据指纹。V48 增加治理元数据和常规排班状态补齐。没有存量发布或工作稿的新安装使用新默认模板，不要求历史迁移批准。

切换保留旧发布快照，生成新的发布配置，转换未发布工作稿及管理员可授权清单，退出旧聚合码，增加组织授权版本并使旧预览失效。考勤按批准决定立即保留或撤销，不再先撤权再让所有者补审。

先由验收人员检查登录、职责配置、普通账号业务访问、拒绝路径、本人排班／考勤、指定策划审核、宣传编审、知识检索和来源附件，再开放用户访问。确认前避免新增账号、编辑授权或开始正常业务写入，以保留受保护回退的条件。

## 回退

**数据库迁移中途失败：** MySQL DDL 不保证整体事务回滚。停止新版，使用已演练的完整备份及对应旧应用恢复，不手工删除列、不跳过 Flyway 错误，也不强行重复已经部分执行的迁移。

**迁移已完成、尚无后续授权／相关关系变更：** 停止全部新版实例后，可执行授权投影回退：

```bash
java -Dloader.main=com.pams.module.permission.service.PermissionMigrationCli \
  -cp release.jar org.springframework.boot.loader.launch.PropertiesLauncher \
  rollback APPROVED_RELEASE_ID
```

工具锁定组织并核对切换后指纹，恢复旧角色指针、状态、授权投影、模板及管理员委派；旧发布快照从未被改写，新发布历史也保留。组织授权版本继续增加，旧预览保持失效。它不会回退业务数据、删除新版列或改写 Flyway 历史。完成后必须使用已演练的对应旧应用和前端；新版启动保护会拒绝运行已经回退的授权投影。

切换后只要人员、角色、领域包、委派、相关作者关系或受监控配置发生变化，工具就拒绝覆盖回退。此时依据完整备份和变更记录制定人工恢复方案，不能为了回退而删除新授权或恢复已撤销的能力。完整库恢复也可能覆盖新业务数据，须单独评估。

## 验收边界

仓库测试覆盖未批准阻断、报告只读、批准后变化阻断、考勤保留／撤销、旧工作稿转换、历史不改写、后续变化阻止回退和授权回退。隔离 MySQL 演练只能证明所用版本与构造数据下的结果；目标生产版本和真实数据副本仍须验收。正式所有者确认、完整备份与现有业务库切换属于部署操作，不能以测试中的示例确认记录替代。
