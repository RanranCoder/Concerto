# 消息通知管线 v1：剩余通知接入收尾记录

日期：2026-10-29

本批对应剩余三批计划中的第一批：成员账号导入结果、维护订阅和知识库主动聚合告警。站内收件箱、MySQL Outbox、SSE 技术路线保持一致；尚未部署生产。

## 成员账号导入结果

`MemberAccountImportService.apply` 首次成功应用批次时，在同一事务向操作人记录 `IMPORT_RESULT`。正文仅包含批次标识、待激活账号数量和核对提示，不包含姓名、用户名、密码、激活链接或原始凭据。

预览、重发激活凭据不产生这条结果通知；重复应用已成功的批次直接返回原结果，不再次通知。业务事务失败时通知与 Outbox 一起回滚。不同批次使用不同标识，避免同事务中相同数量批次被合并。

此类个人结果按当前 `member:import_account`、`user:manage`、`role:assign` 治理资格和冻结受众校验，支持有开户资格的治理身份阅读摘要。具备成员查看权限的账号可从通知进入成员页面，其余账号保留无业务链接的结果记录。

## 本人维护订阅

新增 V55：

| 表/调整 | 用途 |
| --- | --- |
| `notification_maintenance_subscription` | 按组织和账号保存本人订阅开关、启用边界与更新时间，默认关闭 |
| `notification_incident_delivery` | 按组织、故障日记录、接收人唯一，保存通知事实 ID |
| 故障台账时间精度 | 首次/最近发生时间扩展为微秒，与订阅边界一致 |

通知中心“管线运维”新增“订阅本人维护告警”。通过 `GET/PUT /api/notifications/operations/subscription` 查询或修改当前账号的设置；请求中不接受目标账号 ID。服务端再次校验有效身份、组织归属和当前 `org:audit:view` 资格。

重复开启保持原启用时间；关闭后停止生成新的告警意图，再次开启使用新的时间边界。已经生成的通知保留历史。旧故障在订阅前停止发生时不补发；订阅后再次发生且仍在最近两天窗口内的故障可纳入摘要。

切换账号会隐藏旧身份的配置，旧请求响应不能覆盖新账号的订阅状态。即时提示仍尊重个人的维护告警通知偏好，订阅与已读不充当故障恢复确认。

## 知识库主动聚合告警

`MaintenanceNoticeScheduler` 默认每 60 秒扫描启用的订阅，按组织/账号分页读取元数据，并在明确组织上下文中调用事务服务。缺少有效治理资格、账号停用或组织失效时不生成新告警；任务结束后恢复原上下文。

当前接入三类故障：知识库增量索引失败、索引队列拒绝、每日重建失败。同一组织、类别、上海自然日形成一条故障记录；每位订阅者每天每类最多收到一条 `MAINTENANCE_ALERT`。后续次数在独立故障台账中累计，通知保留生成时的计数快照。

处理时先锁定订阅行，重新校验权限，再将通知事实、Outbox 和个人告警去重凭据一起提交。并发扫描或重启补跑不会产生重复的个人告警；事务回滚后仍可重新扫描。下一自然日使用新的故障记录，允许产生下一天的摘要。

正文只包含固定类别名称、日期与次数，链接定位已有管线运维视图。通知读取时重新校验组织审计权限及冻结受众。故障台账与原日志保持独立，Outbox 故障不会让故障事实消失；本批不把固定角色或全部用户设为默认告警受众。
