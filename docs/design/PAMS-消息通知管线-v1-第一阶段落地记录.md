# 消息通知管线 v1：第一阶段首批落地记录

日期：2026-10-28  
依据：[已评审的消息通知管线重设计 v1](PAMS-消息通知管线重设计-v1.md)  
状态：第一阶段核心代码与定向验证已落地，未部署生产；本记录不代表 v1 所有阶段完成。

## 已实现范围

### 可靠事件与个人状态

- 现有 `notification` 表保留为消息事实表，避免破坏已有消息 ID；新增 `notification_inbox`、`notification_outbox`、固定受众表、`notification_delivery`、`notification_preference`。
- 现有业务事件在 `BEFORE_COMMIT` 阶段解析为不可变通知命令，在原业务事务内写消息事实、outbox 和受众快照；后台独立事务生成个人收件箱，网络写流在数据库事务外执行。这是设计中事件记录阶段的具体接入方式，不依赖提交后的内存事件可靠性。
- 同一事务中相同消息事实合并，接收人去重；消费者按消息与用户唯一键幂等生成收件箱，重复消费不重置已读。
- worker 使用数据库租约、带领取令牌的条件更新和 5 档退避；失败保留记录，超过重试上限进入 FAILED。首批尚未提供可视化运维与人工重放界面。
- 角色、部门在记录时展开为同组织有效账号，之后加入角色的人不继承旧收件箱。消费时复核账号及资源可见性，读取时再次校验并脱敏。
- 单条和全部已读只操作当前组织、当前用户的收件箱；已读变化进入持久唤醒队列，其他标签页可对账。
- 偏好存入数据库，控制新消息是否弹提醒，不删除业务记录；系统类型始终启用。免打扰、摘要等高级偏好尚未实现。

### SSE 通道

- 新增 `GET /api/notifications/stream`，通过现有 Bearer JWT 过滤链认证，只接收当前身份的信号，不支持按请求参数选择其他用户。
- 后端 `SseEmitter`，前端 `@microsoft/fetch-event-source`，仅传 `ready`、`inbox.changed`、`heartbeat` 薄信号，不传业务正文、不提供历史事件重放。
- 连接寿命上限 15 分钟且不超过 Token 剩余有效期，15 秒心跳；发送时复核账号、组织、Token 吊销水位。按连接串行写入，有界写线程池与等待队列，断开/超时/失效回收。
- delivery 的 `SIGNAL_QUEUED` 仅表示唤醒提交至本机有界执行器，不表示浏览器收到或用户阅读。写失败移除连接，由重连 REST 对账恢复；离线记录为 OFFLINE_SKIPPED，不无限重试。
- 前端统一管理断流、退避、页面隐藏/恢复、网络离线/恢复、Token 改变和退出。连接恢复主动对账；流不可用时前台约 60 秒 REST 降级，历史补拉不集中弹窗。
- SSE 客户端关闭库内置页面可见性管理，由应用统一控制生命周期，避免两套重连竞争；只有当前聚焦页面展示 Toast。
- 通知专用 WebSocket 发送与订阅已删除，灵思和权限 WebSocket 保留。
- Nginx 新增 stream 精确路径的禁缓冲、禁缓存、禁 gzip 与读超时配置。配置已入库，完整生产代理链尚未上线验证。

### 核心业务与前端

- 策划书仍只通知选定审核人；审核待办状态直接读取该版本审核事实。已读不改变办理状态；审核完成、退回或撤回后更新相关用户。
- 活动排班发布、再次无变化发布、换人/改时/改地点、重新生成、取消和删除按发布前后差异生成通知。草稿不通知，已发布人员变更合并新旧人员，重复发布无变化不重发。
- 任务映射已有 `assignee_user_id`，前端提交稳定账号 ID，并显示姓名和 ID 区分同名成员；后端核对账号所属组织、部门及有效状态。
- 历史姓名不自动猜测账号；没有个人账号关系时，向负责部门具有 `task:manage` 的成员提供分配提醒。后续仍可配置明确的部门任务协调人。
- 接入任务指派、改派、关键安排变化、完成、删除与撤销变化；进度微调不逐次通知。任务和策划书的办理状态独立于阅读状态。
- 通知中心与铃铛共用刷新、未读数和身份失效控制；新增“查看/去审核/去处理”，活动相关消息可定位对应 Tab。
- 灵思定向通知归为 COLLABORATION，回执明确为已受理异步投递，不再声称用户已收到。
- 现有推文截止扫描改为逐组织、独立事务运行，显式使用 Asia/Shanghai，不再对已提交审核或待发布的稿件催作者撰写；扫描失败写独立日志，不递归发送给固定 TEACHER 角色。

## 数据迁移与兼容

- V50：消息事实扩展、收件箱、outbox、受众、delivery、偏好及存量数据迁移。
- 旧个人通知保留原已读状态；旧共享通知按迁移时受众展开为已归档历史，不计入新未读角标，不重新在线推送。旧共享行不能恢复每人真实历史阅读情况。
- V51：为 `task(org_id,assignee_user_id,end_date)` 建索引。账号列已由 V37 创建，本次只映射使用并建索引，不重复加列、不按姓名回填。
- REST 通知 ID 继续使用消息 ID；操作时附加 orgId+userId 归属条件，与个人收件箱内部主键分开。
- 通知只保存有长度限制的摘要，完整审核意见等内容回业务页查看；合法长意见不会因通知字段长度导致业务事务回滚。
