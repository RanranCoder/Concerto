# 消息通知管线 v1：第三阶段第二批落地记录

日期：2026-10-29

进入本批前已将前五个提交推送到 `origin/Concerto`，远程由 `b782f77` 更新至 `4e13fd3`。本批继续补充授权经办摘要、导入结果和运维可追溯性，沿用站内收件箱、MySQL Outbox、SSE。

## 授权经办摘要

新增 `BusinessNoticeService`，按组织、领域、操作人，在同一个业务事务内累加操作类型与数量，提交前生成摘要及冻结受众。回滚不生成通知；独立事务使用独立聚合容器，不与外层事务混合。通知正文只接受操作枚举和数量，不接受姓名、学号、分数、家庭关系、备注或文件内容。

| 已接入操作 | 摘要受众 |
| --- | --- |
| 素拓新增、调整、活动批量加分 | 同组织具有 `quality:view` 与 `quality:add` 的有效经办账号 |
| 素拓删除、批次回滚 | 同组织具有 `quality:view` 与 `quality:delete` 的有效经办账号 |
| 党务阶段流转 | 同组织具有 `party:view` 与 `party:manage` 的有效经办账号 |
| 名单、登记、转移记录增删改 | 同组织具有 `party:view` 与 `party:entry` 的有效经办账号 |
| 函调记录增删改 | 同组织具有 `party:view` 与 `party:letter` 的有效经办账号 |

当前党务领域与权限配置仍决定实际可用权限，未启用领域不会因通知扩大受众。素拓与党务的个人成员提醒继续等待本人账号关系、本人可读接口，不按姓名匹配或向全员广播。通知展示时再次校验当前领域权限，撤权后隐藏摘要正文。

批量操作按领域生成一份消息事实并展开个人收件箱，不按人员逐条通知。例如一次事务新增 300 项、调整 7 项，摘要只包含这两项计数。普通成员资料保存不在本批广播范围。

## 导入结果

成员名单、党务名单、无课表导入完成时，提交一份仅面向操作人的结果摘要，包含成功、跳过或未导入数量。当前登录账号优先于业务参数中的操作账号；发送和展示均需要其当前领域查看资格，党务导入还需经办资格。

整次解析失败或事务回滚仍通过原 HTTP 错误返回，不把失败事务中的临时数据当作已完成结果通知。未配置操作账号的后台调用不猜测收件人。无课表结果按 `schedule:free_table` 资格回到已有页面，成员及党务结果回到各自业务入口。

## 知识库维护故障

新增 V54 的 `notification_incident`：按组织、固定故障类别、上海自然日唯一，重复故障递增次数，保留首次与最近发生时间。不存源正文、异常堆栈或人员资料。

增量索引失败、执行队列拒绝、每日重建失败写入独立事务台账，不依赖通知 Outbox 能否工作；原日志仍保留。台账写入本身失败时继续记录日志，不反向影响已提交业务。

索引提交任务时捕获组织，工作线程执行前设置组织并在结束后恢复原上下文；缺少组织时拒绝排队，避免默认组织回退。每日重建显式遍历有效组织，各组织分别调用事务索引入口，单个组织失败后继续其余组织。

当前先向有组织审计权限的维护视图提供故障信息，没有将固定 TEACHER 或全部用户作为告警收件人。维护责任人订阅配置和主动聚合告警尚待补齐；本批不宣称已接通维护告警发送渠道。

## 失败恢复审计

V54 同时新增 `notification_operation_audit`。FAILED 记录重新入队前加行锁，在同一事务保存操作账号、组织、管线、记录 ID、原尝试次数和时间；并发或重复请求只有成功改变状态者留下一条操作记录，重试失败则一起回滚。

新增 `GET /api/notifications/operations/audit` 与 `/incidents`，只查询当前组织最近 100 条元数据，复用实时组织审计资格校验。通知中心运维视图显示这两类记录，切换账号时隐藏旧身份数据。
