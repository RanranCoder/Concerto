## 1. 通用提醒引擎

新增 V52 迁移，包含：

| 表 | 用途 |
| --- | --- |
| `notification_reminder_source` | 保存组织内业务资源的配置指纹、有效状态和提醒代次 |
| `notification_reminder` | 保存接收人、规则、时间窗口、触发时间、到期时间、发送状态及消息 ID |

提醒按“组织 + 资源 + 用户 + 规则 + 时间窗口”唯一；普通规则的窗口绑定业务代次，逾期摘要窗口绑定自然日。业务配置改变、完成后重新打开时使用新代次，不复用旧的已发送或取消记录。

调度默认每 60 秒执行，使用 Asia/Shanghai 时间。组织扫描显式设置 OrgContext，业务资源按 ID 每页 200 条核对，各资源在独立事务内处理；启动后恢复扫描即可补跑，不依赖进程内长期定时器。

发送时先锁资源代次，再锁提醒记录，并重新检查资源状态、当前负责人、截止时间、组织和权限。消息/outbox 与提醒 SENT 状态在同一事务提交；回滚一起恢复。重复执行和并发消费者只产生一份消息意图。

错误保留待补跑，5 分钟后重试，累计 6 次失败转 FAILED，并记录脱敏错误类别。后续实际通知消费、个人收件箱和在线唤醒仍使用第一阶段 Outbox 机制；提醒 SENT 不表示用户已阅读。

## 2. 已接入的时间规则

| 场景 | 当前默认策略 | 取消与补跑 |
| --- | --- | --- |
| 本人任务临期 | 截止日期前 1 天 09:00 一次；任务日期的截止语义是当日结束 | 已过截止日期的旧临期提醒跳过，不补发过期催办 |
| 本人任务首次逾期 | 截止日期后 1 天 09:00 一次 | 停机恢复后仍未完成则补发一次 |
| 本人任务逾期摘要 | 工作日 09:00，按接收人合并为每天一条 | 只纳入较早已发首次逾期提醒的未结任务；不与当天首次提醒重复轰炸 |
| 推文临期 | 截止前 3 天所在日期 08:30 一次 | 草稿/退回状态且作者具有编辑或提交资格才提醒；错过窗口不补发临期 |
| 推文逾期 | 截止时刻后一次 | 已提交待审、已通过待发布、已发布均停止催作者撰写 |
| 活动排班班前 | 精确开始时间前 30 分钟一次 | 已取消、改派、改时、活动归档或已到开始时间均使旧提醒失效 |

任务改派、改期、完成、撤销、重新打开，以及排班重要变化通过业务挂点同步核对提醒。推文指派、提交、审核、发布通过事务事件核对；普通稿件编辑中的负责人/截止时间变化和删除也同步核对。定时扫描另作为恢复和漏挂点补偿。

原 `ArticleDeadlineTask` 的自动调度已停用，保留兼容调用与旧单测入口，避免同一稿件由两套定时任务重复提醒。新版采用明确的临期/首次逾期窗口替代旧版每日反复催作者的扫描策略。

已过时的任务/审核提醒不再触发新 Toast；已发送记录仍可作为历史查看。业务状态和提醒代次决定当前可办理性，通知已读状态不参与提醒是否完成的判断。

## 3. 常规排班的生效规则

核对当前代码后，常规排班已具备明确的保存草稿、发布和取消接口，因此接入其发布/调整/删除通知。未发布草稿保持安静；已发布内容或人员变化才通知原、新受影响账号。

常规排班常用“上午”“某节次”等文本时段，当前请求模型没有精确的开始/结束时间，因此：

- 不从文字时段、周次或星期猜测开始时刻，不生成班前定时提醒。
- 已发布、绑定个人账号且有具体日期的安排可进入本人待办；缺少时刻时不虚构办理截止时间。
- 只有周规则、尚无具体日期的记录继续在排班页面管理，不推导未来每周实例。
- 精确班前提醒仍限于具有准确日期和开始时刻的活动排班。

## 4. 统一“待我处理”

新增 `PendingWorkService` 与 `GET /api/notifications/pending`。该查询直接读取业务状态，工作台、通知中心和灵思 `queryMyPendingWork` 共用。

| 待办来源 | 当前资格 |
| --- | --- |
| 活动任务 | assignee_user_id 明确绑定本人，任务未完成、活动未归档，且有任务查看权限 |
| 策划书审核 | 当前提交版本明确选择本人、本人尚未审核，且具备活动查看、策划书查看及审核权限 |
| 推文撰写/提交 | 本人作者，草稿或退回，具有相应编辑/提交资格 |
| 推文审核 | 当前待审稿件，有审核资格的候选人；任何人审核后该轮待办收敛 |
| 推文发布 | 当前已通过稿件，本人作者且有发布资格，或有稿件管理与发布资格的经办人 |
| 本人排班 | 绑定本人账号、已发布、有具体日期，尚未签到且未结束/取消；只读本人或已有组织查看权限 |

查询同时校验组织归属、账号有效性、当前生效权限和调用上下文的权限上限。角色变化后旧 Agent 上下文不能恢复已撤销权限。

首页任务日历也改为稳定账号查询。历史未绑定姓名和同名他人的任务不会自动进入“我的待办”；组织级任务查询和治理工具的职责保持独立，不再把全组织逾期任务混进个人待办。

前端复用原有工作台卡片样式，通知中心增加“消息记录 / 待我处理”切换。SSE 状态变化刷新待办；前台定期对账，隐藏页面停止轮询，回到前台刷新。切换账号立即隐藏旧账号待办，并丢弃旧请求响应。

逾期摘要可直达通知中心的待办视图；排班链接依据当前用户权限进入个人或组织排班页。未配置策划书审核期限，不生成虚构的审核逾期提醒。
