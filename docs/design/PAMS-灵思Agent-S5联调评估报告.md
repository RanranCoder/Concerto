# 灵思 Agent S5 联调与评估报告

日期：2026-10-25。对应《PAMS-灵思Agent升级优化方案》S5。本文区分代码落地、隔离验收与生产发布，不把运行状态直接当作业务质量。

## 交付范围

本批实现了可重复执行的 21 工具验收、单／多 Agent 公平对照、真实模型计量、真实浏览器业务闭环、进程故障恢复测试，以及按组织灰度和回退配置。测试使用服务器上的独立 MySQL 8.0.46 库 `pams_s5_20261025_20ae2b15`，仅写合成数据；连接用户只有该库权限。验收后已删除临时库和账号，停止本机隧道并移除私有凭据，保留脱敏证据。没有将当前业务库或本地备份发送给模型。

线上应用仍为此前部署的 S4（`f779a2e`），业务库仍为 `pams_db_local_20261025`、V45。本批 V46 仅在验收库等测试环境执行。S5 代码、迁移与验收材料随本次提交归档，尚未部署到服务器。

## 本批修复与行为

| 发现 | 落地结果 |
|---|---|
| 旧对照使用不同执行内核，统计口径混杂 | SINGLE 与 MULTI 使用同一持久化 DAG；P1 顺序执行，P2 按依赖并行；任务、身份、可见工具、模型与预算相同，按任务交替分组先后顺序 |
| 多步执行只传模型摘要，缺少数据库事实 | 普通读取工具提供有界、有效 JSON；上游实际工具事实单独持久化、传递，审查不把模型建议当作新增要求；敏感结果仍沿用权限与出站策略 |
| 调用统计为零或错误地等同于业务成功 | 持久化每次实际工具调用的名称、状态、耗时；成果数量改从持久化台账读取；Run SUCCESS、等待确认、外部质量验收分别统计；未评估的完成率保持 NULL |
| 用量和价格缺失可能误导成本评估 | 支持非流式及 SSE 最终用量帧，记录实际 provider/model、finish reason、失败、降级和重试；重试计入预算，未知成本为 NULL，不显示零费用 |
| 明确要求草稿预览时模型可能只返回文字 | 有界纠正后仍未生成实际清单则记 PARTIAL；模型因长度结束也不直接当作成功 |
| 草稿把未来活动写成已经成功举行 | 改为中性活动文稿草稿，只写实际名称、日期、地点等信息；去除正文内的系统工作流说明 |
| 审查将文风或模型建议升级为业务阻断 | 只核对用户原要求、实际工具事实与正文；阻断需有连续原文及有效来源；保留对植入日期、地点错误的真实模型阻断验收 |
| 执行器包装后丢失底层线程池生命周期 | 显式销毁底层线程池，独立验证上下文关闭和 JVM 正常退出 |
| 同毫秒创建流时缓存淘汰不确定 | 增加创建顺序作为次级排序，淘汰时同步清理状态 |
| 不存在／跨组织人员被共同空闲计算当作有空 | 计算前校验人员存在性和组织归属，并去重；真实课表验证占用时段与空闲时段不同 |
| 评估请求超过普通接口超时 | 前端与 Nginx 为隔离评估接口单独设置 30 分钟等待；Nginx 语法检查通过且未重新加载线上配置，页面说明离开后采样仍会继续 |
| 重启测试可能读取尚未写完的检查点 | 检查点写入后原子改名；准备、恢复与父进程均强制校验两个案例，防止空证据误报通过 |

工具结构化事实最多 12000 字符，限制嵌套、键数、列表和字符串长度，标明截断并过滤口令类字段。步骤累计事实最多 10000 字符，仅保留整体敏感级别为 NORMAL 的实际读取结果；模型推断不作为权威事实补写。

## 对照结果与解释

实际模型为 `deepseek-flash`；验收设置 `thinking=false`、最多 8 次尝试、单次最多 2048 输出 token、最多 4 轮工具循环。这些是显式验收配置，不改变普通线上请求默认值。输入用量由供应商报告，不承诺总输入 token 上限。SSE 最终用量帧处理参照 [DeepSeek 官方接口说明](https://api-docs.deepseek.com/api/create-chat-completion/)。

| 任务 | SINGLE 耗时 | P1 耗时 | P2 耗时 | 质量断言 |
|---|---:|---:|---:|---|
| 查询指定活动与任务 | 18.294 秒 | 20.085 秒 | 19.178 秒 | 三组实际工具事实均包含正确活动 ID、名称、日期、地点 |
| 查询后生成推文预览 | 19.906 秒 | 42.875 秒 | 40.448 秒 | 三组均有实际草稿清单，内容匹配，通过独立审查并等待确认 |

本轮简单任务的单 Agent 更快。不能据此认定多 Agent 在复杂任务上无价值，也不能宣称 P2 已带来普遍提速；写作任务有查询依赖，本身不提供足够的独立并行工作。每组仅 2 个样本，p50/p95 只是这两个观测值的分位数，不代表稳定 SLA。

对照不自动确认业务写入，采样后取消未提交清单。查询的 SUCCESS 和草稿的 WAITING_CONFIRM 都符合各自预期，因此“Run 成功率 50%”不是“业务完成率 50%”。产品评估页的完成率和审查通过率仍标为未评估；6 个质量断言仅覆盖此次预定义的读取／预览检查。真正业务提交的证据见独立闭环测试。

各样本有供应商 token 与缓存命中报告，但没有固定版本的价目表和最终账单校验，因此费用保持未知。本轮原始对照记录的成果计数采于最终台账计数修正前，未用于质量或性能结论；后续新样本从实际成果台账计数。缓存预热、网络与数据库往返影响耗时；交替组次序只缓解固定顺序偏差，没有消除缓存影响。

## 发布与复跑

新增 `V46__agent_evaluation_metrics.sql`，仅为 `agent_benchmark` 增加可空 JSON 字段，不回填历史指标。后端、前端评估页和迁移应同批发布。

- `pams.agent.benchmark-enabled=false` 为默认值；开启评估还必须列出 `benchmark-org-ids`。
- `pams.agent.collaboration-enabled=false` 将新请求切到单 Agent；`collaboration-org-ids` 非空时只开放列出的组织。空组织集合保持既有范围，关闭必须使用主开关。
- 回退仅影响新请求，不删除历史 Run、清单与成果版本，不重放已确认或待核对的业务写入。按当前部署方式修改配置后重启生效。
- 执行方式见 `scripts/agent-s5/README.md` 与 `run-acceptance.ps1`。
- 新增手动 GitHub Actions 验收流程，默认不调用付费模型；此流程尚未在 GitHub 执行，不计入本次已通过结果。

S0–S5 的代码实施与首轮隔离验收至此收尾。生产灰度、大样本质量标注、固定价目账单核验和多实例运行／故障切换尚未执行；这些属于发布及持续评估范围。本轮不将其写为已经完成，也不以 6 个样本作为自动扩大协作流量的依据。
