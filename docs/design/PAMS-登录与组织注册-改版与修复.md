# 登录与组织注册流程改版

日期：2026-10-16

## 页面与交互

- 沿用协奏品牌与现有明暗主题令牌：主蓝 `#1668DC`，浅色底 `#F4F6F9`，正文 `#263243`，辅助文字 `#5B6777`，分隔线 `#DFE5ED`；字体沿用项目中文字体栈，字号与圆角均引用统一令牌。
- 登录页用组织协作示意连接产品定位与表单；公开组织选择只用于品牌展示，明确说明实际归属由账号决定。
- 登录请求期间禁用重复操作；凭据错误保留输入并展示可重试提示。`/auth/login` 的 401 不再触发整页跳转，其余接口的会话失效处理保持原逻辑。
- 创建组织分为组织信息、组织架构、管理员账号、确认并创建四步。当前步骤单独校验，返回时保留输入。
- 组织类型直接选择，主题色可预览；架构树支持多层增删改、删除整支前确认、空白及重名检查。
- 管理员增加确认密码；确认页可返回修改各部分，扩展功能按需选择。
- 创建成功后使用管理员用户名返回登录，不传递或存储密码。
- 桌面显示侧边步骤，手机显示顶部步骤；键盘操作、焦点、深色主题均沿用同一套交互。

## 两处崩溃原因与修复

1. `/register` 使用 React.lazy，而原 Suspense 只在登录后的 MainLayout 内。点击公开入口时没有加载边界。根布局增加 Suspense，RouterProvider 启用 v7_startTransition，并提供中文路由错误页面。
2. 原递归编辑器展示的是子数组，更新时却使用相对于根的完整路径，并把子数组写回整个架构状态。现在视图只传递节点路径，所有更新均在根状态上执行不可变更新，提交时递归保留并整理全部节点。

步骤按钮始终使用普通按钮，主动校验后推进；仅在最终明确点击创建时发送注册请求，避免切换步骤时按钮变成 submit 触发表单默认提交。

## 注册限流跟进修复

原规则将同一来源的所有尝试都计入每小时 5 次，业务校验失败也占额度。前轮测试虽清除了数据库测试数据，运行中后端的内存计数仍然存在，导致正常注册被拦截。

- 小时额度改为每来源最多成功创建 5 个组织；事务失败不消耗成功额度。
- 失败请求仍受每分钟 20 次的短时限流保护；被拦截的请求不延长窗口。
- 超限消息给出剩余等待分钟数或秒数；同来源并发创建不会超过成功额度。
- 通过 4 项限流单元测试及 5 项组织注册服务集成测试。
- 本地后端已重启以清除旧计数、加载修复；通过前端代理发送空请求返回正常必填校验码 2001，确认不再被旧限流拦截，没有创建组织数据。现有浏览器表单可以直接再次提交。
