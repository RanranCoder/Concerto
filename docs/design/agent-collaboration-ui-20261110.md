# Agent 输出与协作过程优化

本轮沿用 concerto 现有字体、主题令牌与 React 组件体系，只调整消息内的信息层级，不引入新的组件库。

## 设计依据

- Anthropic 的主 Agent / 专家分工实践：https://www.anthropic.com/engineering/multi-agent-research-system 。转化为可见的专家身份、任务职责和前置依赖，不凭 UI 推断并行关系。
- Cursor 的执行工具、历史与结果审阅实践：https://docs.cursor.com/chat/overview 。转化为协作概览、可展开过程记录、回复正文和任务操作四层信息。

这些布局是针对本项目的设计取舍，并非声称上述产品采用完全相同的界面。

## 已实现

1. 持久化 run 在回复正文前展示协作概览：专家数、成功任务数、执行中数量和需关注数量全部从快照计算。
2. 每行展示真实任务标题、负责人、状态；依赖通过节点 ID 解析为任务名称，缺失节点保留步骤编号。
3. 等待确认、部分完成、失败均不计入成功；完成与停止默认折叠，异常及等待默认展开；手动折叠在增量更新中保持。
4. “查看待处理事项”打开已有任务详情，滚动并转移键盘焦点；原有确认、修订、重试、停止与产物预览继续复用。
5. 历史流式协作面板采用原生按钮和明确状态标签，失败记录默认展开。过程区从概览去重，不再将协作过程记录结束表述为整个任务完成。
6. 回复正文增加阅读分区，过程明细在上，成果与业务操作继续保留在正文后。

## 验证与范围

- 15 项相关组件测试，覆盖等待状态、重复专家执行记录、依赖、完成计数、手动折叠、过程流式呈现。
- 5 项 Playwright 场景：1440/768/390 宽度的协作概览；桌面浅色和手机深色的独立确认、续跑与刷新恢复。
- 截图位于 `docs/ui-v6-lingsi-implementation/collaboration-overview-*.png`。逐张检查了层级、依赖换行、状态对齐与横向溢出。
- 新概览组件通过设计规则源码扫描。此为已有组件局部改造，未重新抽取整站视觉方向。
- 浏览器场景使用模拟接口和真实应用组件，不代表本轮验证了真实模型、多 Agent 后端调度或生产环境端到端执行。生产构建另外校验。

## 视觉复核

### 2026-11-11 实时与历史界面一致性修复

实时阶段尚无 `run` 时原本进入 `LingsiTeamPanel`，而历史加载后进入 `LingsiRunOverview`，导致用户先看到旧版再切新版。现在消息始终挂载同一个概览组件，以事件显示已知专家记录，快照到达后原位补齐完整任务及依赖，不虚构实时阶段的任务总数，也不重置手动折叠状态。

首次 `AGENT_RUN_UPDATED` 通知在 run 未绑定时，按当前 request / stream 身份恢复快照；异会话通知不会绑定到当前消息。迟到的 chat 响应保留更新版本的 run，防止界面退回。新增组件、store 和浏览器回归覆盖实时事件、首次快照、迟到响应及刷新后的同一渲染路径。

主要问题“谁在做什么、为什么在等待”已由正文之前的分工列表直接回答。三种宽度下列表完整、状态文字与色彩共同表达含义，长依赖可以换行；没有虚构百分比或预估时间。颜色与字体沿用现有主题，避免让协作区成为第二套视觉系统。

已知边界：大量任务仍纵向列出，可手动折叠；本轮未改全局导航或消息的自动滚动策略。没有运行需要登录状态的整页设计 inspector，视觉证据来自上述 Playwright 场景与人工截图复核。
