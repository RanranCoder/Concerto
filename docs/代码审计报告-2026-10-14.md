## 二、鉴权、授权与会话

### 10. 账号写接口跨组织无隔离：改 / 禁 / 删 / 重置他组织账号，可完整接管任意用户（含降权链）

- **位置**：`UserService.java:162-166`（update）、`:225-231`（delete）、`:243-252`（reset）、`:178-193`（apply）；入口 `UserController.java:63-87`；`User.java:33-34`（**显式注明不参与 `@TenantId`**，人工复核确认）
- **严重度**：**高**　**验证**：CONFIRMED
- **证据**：
  ```java
  // UserService.java:162 —— 只有 findById，无 org 归属比对；User 无 @TenantId 无 @SQLRestriction 组织过滤
  public void updateUser(Long id, UserSaveRequest req, Integer currentLevel) {
      User u = userRepository.findById(id).orElseThrow(() -> new BizException(1004, "用户不存在"));
      apply(u, req, currentLevel);   // apply 内可改 status/dept/role，deptId 亦不校验归属
  // :243 resetPassword —— 只校验"目标角色 level ≥ 自己 level 则拒绝"，不校验组织
  ```
  对照：同文件 `page():88-99`、`options():49-61` 读路径已显式加 `OrgContext.getOrDefault()` 过滤——说明作者知道该表不过滤，但只补了读列表。
- **风险场景**：B 组织 DIRECTOR（含第 12 条的匿名注册所得）持有 `user:manage`：
  ① `PUT /api/users/{A组任意用户id}` 可把 A 组 **TEACHER 降为低级别角色**（updateUser 对目标级别零校验，只看新角色 level）；
  ② 降权后 `POST /api/users/{id}/reset-password`（目标 level < 4 时放行）→ 密码变 `123456` → **以 A 组织账号登录**；
  ③ 或直接 `status:0` 停用任意组织任意账号（跨租户 DoS）。
- **建议**：三条写路径统一 `if (!Objects.equals(u.getOrgId(), OrgContext.getOrDefault())) throw 403;`；updateUser 补"目标既有角色 level"防降权校验；根治方案是给 `sys_user` 加 `@TenantId` 并为注册/登录显式旁路。

### 11. 软删账号"复活"路径跨组织：native 查同名已删账号 + `apply()` 不写 orgId

- **位置**：`UserRepository.java:23`（native，无 org 谓词）→ `UserService.java:130-141`
- **严重度**：**高**　**验证**：CONFIRMED
- **证据**：`findDeletedByUsername` 全库唯一按用户名找已删行的入口；复活分支 `deleted.setPassword(...); apply(deleted, req, currentLevel); setDeleted(0L)`——`apply` 不改 orgId，行仍属原组织，但密码由攻击者指定
- **风险场景**：A 组织有已软删账号 `zhangsan`；B 组织 DIRECTOR `POST /api/users` 用同名 → 命中复活分支 → 以攻击者设定的密码 + A 组织身份登录
- **建议**：`findDeletedByUsername` 改派生方法并附 `orgId`；service 内比对组织，不一致则退回新建或 409

### 12. 匿名自助注册即发放全局 DIRECTOR 账号；注册限流键信任客户端 `X-Forwarded-For` 可无限绕过

- **位置**：`SecurityConfig.java:53-54`（permitAll）；`OrgService.java:122-135`（取全局 DIRECTOR、`status=1` 直接可登录）；`OrgController.java:46-53`（`clientKey` 取 XFF 首段）；`OrgRegisterRateLimiter.java:16-35`（每 IP 每小时 5 次）
- **严重度**：**高**　**验证**：CONFIRMED（人工复核）
- **风险场景**：任何人一次 `POST /api/orgs/register` 即获 DIRECTOR（除 `user:permission` 外全部权限码）；限流只需每次换 `X-Forwarded-For: 1.2.3.<n>` 即可无限注册。与本报告第 10/11 条组合 = **从公网到任意租户账号接管的完整链路**
- **建议**：注册改 `status=0` 待审核（或邀请码/管理员开通）；限流键改用容器解析后的 `getRemoteAddr()`（或 `forward-headers-strategy` 开启时才信 XFF）

### 13. 知识库台账接口不套用 `visibility`/`required_permission`：STAFF 可读被检索侧拦住的全文

- **位置**：`KnowledgeController.java:75-91`（仅 `kb:read`）；`KnowledgeAdminService.java:216-241`（`pageChunks` Specification 只有 sourceType/keyword）、`:244-260`（snippet）、`:269-277`（`chunksOf` 返回**完整正文**）——人工复核确认无任何权限/可见性谓词
- **严重度**：**高**　**验证**：CONFIRMED
- **证据**：对照检索侧 `ChunkSearchRepository.java:150-172` 有 `visibility`/`required_permission`/租户谓词；`SnapshotSource.java:110`（LEADER 级快照）、`MemberSource.java:166-168`（要求 `member:view`）——两套门禁都存在，只是台账接口没用
- **风险场景**：STAFF（`kb:read` 全员持有、`member:view` 无）调 `GET /api/kb/chunks?sourceType=member` 即可看到成员分块标题，再 `GET /api/kb/chunks/member/{sourceId}` 取全文；PARTY/LEADER 级快照与设了权限码的人工文档同理——即 09-14 权限审计 A9 事故（"干事看不到党务页却能问出党员姓名"）**换了一扇门重现**
- **建议**：`pageChunks`/`chunksOf` 复用检索侧的 `visibility`/`required_permission` 谓词（同源实现，避免再分叉）

### 14. WebSocket 链路不校验 token 吊销水位，`/ws` 完全绕过 Spring Security 过滤链

- **位置**：`WebSocketAuthInterceptor.java:44-50`；`SecurityConfig.java:36-44`（`/ws/**` permitAll）；`WebSocketConfig.java:31`（`setAllowedOriginPatterns("*")`）
- **严重度**：中　**验证**：CONFIRMED
- **风险场景**：受害者改密/重置后 HTTP 侧旧 token 立即 401，**但同一旧 token 仍可 STOMP CONNECT `/ws`**，继续收取该用户的 `/user/queue/agent/stream`（灵思过程事件含工具参数与结果摘要）；登出后连接也不会被断开
- **建议**：拦截器补 `isRevoked` 同等判定并主动断开被吊销会话；`setAllowedOriginPatterns` 收敛为站点白名单

### 15. 服务端 HTML 净化只覆盖 Agent 写路径，5 条人工写路径原样落库（与 `HtmlSanitizer` 注释矛盾）

- **建议**：Service 写入入口统一挂 `HtmlSanitizer`（与 Agent 路径共用白名单）

### 16. 登录失败限流只按用户名：可锁死任意账号，且不防跨用户名撞库

### 17. 无课表下载口仅需登录，绕过 `FileService` 对象级 ACL；`/analyze` 可读他人课表

### 18. 文件上传无权限注解、无体积/配额限制；`bizType` 由客户端指定可关闭敏感判定

### 30. 排班被置 ENDED 后扫码不再回写考勤 →「已签到却缺勤」永久矛盾
