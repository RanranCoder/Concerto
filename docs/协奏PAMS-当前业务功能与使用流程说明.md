## 1. 系统是什么，以及解决哪些问题

### 1.1 产品定位

系统对外名称为 **协奏 Concerto**，工程名称仍为 **PAMS**，智能助手名称为 **灵思**。它是一套面向学生组织的协同工作台，起源于党建办公室党务管理场景，现已具有多组织注册、组织数据隔离和通用活动协作能力。

系统将以下工作放入同一个业务空间：

1. 建立组织、部门、小组和登录账号，明确成员归属及业务权限。
2. 创建活动，组织策划、任务分工、议程、座位安排、现场签到和活动收尾。
3. 维护课表与无课信息，形成常规值班或活动岗位排班，并跟进考勤。
4. 维护成员和党务专项台账，保存届别、任职和发展历程。
5. 跟进宣传稿的撰写、审阅、发布登记和传播数据。
6. 归集文件、模板、公告、群聊资料和素拓加分记录。
7. 通过灵思检索资料、查询业务、生成草稿，并在人工确认后执行支持的操作。

### 1.2 核心业务关系

| 对象 | 表达什么 | 与其他对象的关系 |
| --- | --- | --- |
| 组织 | 独立的业务与授权空间 | 拥有架构、账号、角色、活动及各类业务数据 |
| 架构节点 | 部门、中心、小组、分队 | 承载账号归属、负责人及部分工作资料关联 |
| 用户账号 | 谁可以登录，以及可以做什么 | 一个业务主角色，治理身份另行授予 |
| 成员档案 | 谁属于某一届组织，担任何种职务 | 可以关联账号；建档与开户是两个步骤 |
| 党务成员 | 党务业务中的人员及发展材料 | 有阶段、函调、登记、组织关系转移记录 |
| 活动 | 一项组织工作的主业务对象 | 关联策划、任务、议程、座位、评分、签到、排班、宣传、材料和加分 |
| 排班 | 某日期或周期、某时段由谁值班 | 发布后进入个人安排，并建立相应考勤记录 |
| 活动签到 | 活动现场的签到事实 | 可关联应签名单；符合条件时联动已发布活动班次的考勤 |
| 考勤 | 某人对某班次的到岗结果 | 区分自动结果与人工修正，人工处理保留审计 |
| 知识资料 | 灵思可以检索和引用的内容 | 是来源数据的受控投影，访问仍受来源规则约束 |

### 1.3 谁使用系统

| 使用者 | 典型工作 |
| --- | --- |
| 组织所有者 | 创建组织、配置管理身份和授权上限、核对治理变更 |
| 组织管理员 | 在委派范围内维护用户、角色、开户和治理资料 |
| 活动负责人 | 建活动、组织策划审核、分配任务、安排现场工作、归集成果 |
| 排班与考勤经办人 | 制作无课表、生成排班、发布班次、核对异常考勤 |
| 宣传人员 | 撰写稿件、提交审稿、登记发布链接和传播数据 |
| 党务经办人 | 维护发展阶段、专项登记、函调、名单与转移记录 |
| 普通成员 | 查看获准业务、本人安排与考勤、维护个人课表、阅读通知、使用灵思 |

上述是职责示例。系统当前采用细分权限，**“老师、主任、部长、干事”等名称本身不能完整代表实际权限**；应以当前组织发布的授权与业务对象规则为准。

## 3. 账号登录、首次设密与个人使用

### 3.1 账号密码登录

**是什么：** 使用组织内已经创建且启用的用户账号进入工作台。

**使用流程：**

1. 打开登录页，核对页面展示的组织信息。
2. 输入用户名和密码，点击登录。
3. 系统检查凭据、账号状态、组织状态和当前授权。
4. 登录后进入工作台，侧栏按权限和领域包显示入口。

**实现结果：** 建立带组织身份的登录会话，下发当前用户信息及有效权限，供业务访问和界面展示使用。

**规则与限制：**

- 组织展示选择不改变账号真实归属；真实组织由账号决定。
- 同一用户名连续登录失败 5 次会暂时锁定 5 分钟。
- 停用账号、不可用组织不能正常登录。
- 页面刷新会重新获取当前授权；授权变更还会通过实时信号和兜底刷新同步。
- 当前不是“一个账号自由切换多个组织身份”的成员体系。

### 3.2 批量开户后的首次设置密码

**是什么：** 花名册批量创建的账号先处于待设密状态，由成员本人设置密码后激活。

**使用流程：**

1. 开户经办人从开户批次下载每个人的一次性设密链接。
2. 成员打开自己的 `/activate-account#token=…` 链接。
3. 设置至少 8 位密码并确认。
4. 设置成功后使用对应用户名登录。

**实现结果：** 完成待激活账号的本人设密，避免全员共用固定初始密码。

**规则与限制：** 凭证有效期为 48 小时；重新签发会使此前尚未使用的链接失效。系统只生成和下载凭证，不会自动逐人发送。

### 3.3 修改密码与退出登录

**流程：** 点击顶栏头像 → 修改密码 → 输入当前密码、新密码和确认密码 → 提交 → 重新登录。

当前自行修改密码要求新密码至少 6 位；新增用户和首次激活采用至少 8 位的规则，两者在当前实现中不同。

退出登录会清理本地会话，并推进账号令牌失效水位，因此可能同时影响该账号此前签发的其他登录会话。固定密码重置入口已被服务端关闭，不能将旧接口理解为可用的“重置为统一密码”功能。

### 3.4 界面主题与移动使用

系统提供浅色、深色主题，桌面侧栏与手机抽屉导航，组织主题色参与界面品牌展示。主题及部分列表密度偏好保存在当前浏览器。它们不会同步更改其他成员的界面偏好。

## 4. 组织注册、品牌与组织架构

### 4.1 自助注册组织

**入口：** 登录页“注册组织”，或 `/register`，无需提前登录。

**流程：**

1. **组织信息：** 填写名称、简称、类型、主题色。
2. **组织架构：** 至少建立一个部门或小组，可继续添加下级节点。
3. **管理员账号：** 填写首个管理账号的用户名、密码、姓名等资料。
4. **确认并创建：** 核对组织与架构，选择领域包，提交创建。
5. 创建成功后返回登录页，使用新组织的管理账号登录。

**实现结果：** 一次建立独立组织空间、初始架构、岗位与组织角色配置，以及首个管理账号／所有者身份。

**可选组织类型：** 党建办公室、学生会、社团、青年志愿者协会、科技协会、其他组织。

**规则：** 组织名和管理员用户名需要通过唯一性校验；节点名称与颜色格式也有校验；公开注册受来源限流。注册不能创建空架构。

### 4.2 组织品牌与领域包

**入口：** 组织架构 → 组织总览 → 编辑组织资料。

可以维护组织名称、简称、Logo 地址、主题色，以及启用的领域包。登录页和工作台读取同一组织资料，可通过登录页预览核对展示。

当前领域包包括 `party`、`volunteer`、`club`：

- 党建包对接当前党务台账与党务能力开关。
- 志愿包和社团包有配置及展示选项。
- 当前源码没有独立的完整志愿服务时长、社团会费、社员审批等专用业务模块；不能仅凭领域包名称认定这些功能已完成。

### 4.3 组织树与节点维护

**是什么：** 以树形方式管理部门、中心、小组、分队及其上下级关系。

**流程：**

1. 进入组织架构，搜索或选中组织／节点。
2. 查看直属下级、直属账号及节点资料。
3. 有权人员新增下级，填写名称、类型、负责人和显示排序。
4. 保存后树形导航与关联资料使用同一节点身份。
5. 需要删除时，先处理下级及关联账号、花名册和历史工作资料。

**实现结果：** 为组织分工建立稳定归属；支持节点负责人展示、直属账号查询、层级导航与排序。

**规则与限制：**

- 当前编辑节点时不能直接更换上级，不能据此认定支持拖动迁移整棵子树。
- 有下级、账号或工作资料引用的节点不能直接删除。
- 任命负责人不会自动修改其业务主角色或授予管理员身份。
- 岗位和角色映射参与注册及治理引用，但当前没有独立、完整的岗位任免审批工作区。

### 4.4 邀请凭证

有邀请权限的人员可在“成员与账号”入口选择可分配角色、预设部门和有效期，生成邀请码。页面提供 24 小时、72 小时、7 天等选项。

**当前边界：只实现生成，未开放兑换入组页面与完整消费流程。** 现阶段成员入组和开户应使用用户管理或花名册批量开户，邀请码不能直接用于登录或注册。

## 5. 工作台与工作安排总览

**是什么：** 登录后的日常工作起点，聚合活动、排班和任务截止信息。

**流程：**

1. 查看活动总数、执行中活动、本周排班、我的待办。
2. 在“本周安排”切换工作日或全周，选择某一天查看安排。
3. 通过待处理任务进入对应活动的甘特图。
4. 有创建权限时，可直接进入新增活动。

**实现结果：** 将多个模块的当周工作放到同一视图，减少逐页查找；任务显示负责人、截止时间和状态，便于跟进。

**边界：** 工作台是授权范围内的聚合视图。缺少某模块权限时，相应数据会被裁剪；某项显示为空或零，不能直接解释为整个组织没有业务数据。“我的待办”来自当前任务匹配逻辑，不是可自由配置的全业务审批引擎。

## 6. 活动全流程管理

### 6.1 活动档案与查询

**入口：** 活动管理。

**管理内容：** 名称、主题、类型、起止日期、地点、主办方、对象、主持人、负责人和说明等。

**流程：**

1. 按关键词、活动状态、类型、主办方等条件查询，调整日期排序。
2. 新增活动，填写基本资料后保存。
3. 打开详情，在各业务页签继续准备材料、策划和现场工作。
4. 需要时编辑资料、推进阶段或删除记录。

**实现结果：** 形成统一活动档案，并为任务、宣传、排班和归档提供关联主键。

支持的活动类型包括党课、主题团日、主题党日、竞赛、志愿服务、讲座、会议、其他。

### 6.2 活动阶段推进

当前活动阶段如下：

```text
已下达 → 排期中 → 策划审核 → 执行中 → 已完成 → 已归档
```

| 阶段 | 业务含义 | 典型操作 |
| --- | --- | --- |
| 已下达 | 活动已登记，等待组织筹备 | 明确负责人、日期、基本目标 |
| 排期中 | 安排筹备工作 | 编写策划、拆分任务、协调时间与人员 |
| 策划审核 | 活动处于策划核对阶段 | 提交策划并处理审核意见 |
| 执行中 | 开展现场及执行工作 | 议程、座位、签到、岗位排班、评分 |
| 已完成 | 活动结束，进入总结与成果整理 | 核对材料、宣传、加分与考勤 |
| 已归档 | 活动进入查阅与留存阶段 | 查阅历史成果 |

**规则：** 阶段一般只能相邻前进或回退。已完成、已归档活动不能回退到筹备阶段；已完成只能继续归档。已完成、已归档活动的基础资料不可编辑。阶段变更使用独立的 `activity:transition` 权限。

**需要理解：** 活动阶段与策划审核状态是两个对象。不能只看到活动进入“策划审核”就认定某版策划已提交，也不能假设所有业务状态都会自动同步。

### 6.3 策划书编写与 Word 文档

**入口：** 活动详情 → 策划书。

**是什么：** 围绕活动保存策划正文、版本、作者和审核记录；现有页面以 DOCX 文档编辑和预览为主要工作方式。

**流程：**

1. 打开策划书页签，创建或选择当前草稿。
2. 在文档编辑器编辑，或导入 `.docx`，也可从模板库导入可用策划模板。
3. 核对正文与活动相关资料后保存。导入只进入未保存内容，仍需主动保存。
4. 需要交付时下载 Word。
5. 准备审核时选择审核人并提交。

**实现结果：** 保存可预览、编辑和下载的策划文档，并保留与活动相关的结构化策划信息。系统存在背景、目的、内容、流程、注意事项、预案、预算等章节数据，供历史兼容、差异展示、知识检索或灵思起草使用。

**规则：** 草稿存在版本冲突校验；其他操作已经更新草稿时，要求保留输入并重新载入。DOCX 正文不能被旧字段接口随意覆盖。同步修改活动基础信息还需活动编辑权限。

### 6.4 策划书多人审核

**流程：**

1. 作者保存当前草稿。
2. 点击提交，选择 1～50 位不重复、具有有效审核资格的人员，不能选择自己。
3. 被选审核人阅读当前提交版本，填写意见并通过或退回。
4. 所有被选审核人通过，当前版本才进入审核通过状态。
5. 任意一人退回，版本进入驳回状态；退回必须填写修改意见。
6. 作者修订时创建新草稿，重新核对并选择审核人。

**实现结果：** 显式指定审核对象、逐人记录结论与时间，避免将“有审核权”视作可以审核任意稿件。

策划版本状态：

```text
草稿 DRAFT → 待审核 PENDING → 审核通过 APPROVED
                         ↘ 退回 REJECTED
待审核 PENDING → 作者撤回 WITHDRAWN → 新版本草稿
已通过或被退回版本 → 保留历史 → 新版本草稿
```

**访问边界：**

- 当前工作版本仅作者及本次选中的审核人可见，还需活动与策划查看权限。
- 当前版本的修改、提交、修订由作者负责，并要求对应操作权限。
- 历史版本在满足查看权限时可以查阅，不能覆盖编辑。
- 作者撤回审核会保留原提交与已有审核决定，并创建新草稿。

### 6.5 策划版本记录与比较

可以切换历史版本，查看版本号、状态、作者及审核信息。具备当前版本访问资格时，可比较所选历史版本与当前已保存版本的章节或文档变化。

**边界：** 对比依据已保存内容；编辑器中尚未保存的输入不等于已经形成新版本。无权查看当前版本时，不显示与其的内容差异。历史版本查看不等于支持一键恢复或覆盖当前策划。

### 6.6 任务分工与甘特图

**入口：** 活动详情中的任务入口，或活动甘特图。

**管理内容：** 任务名称、负责部门、负责人、开始和结束日期、前置任务、里程碑、进度；服务端也保存状态、优先级和说明。

**流程：**

1. 为活动拆分策划、宣传、物资、场地、签到、总结等任务。
2. 给每项任务确定负责部门、负责人和起止日期。
3. 需要时指定前置任务或标记里程碑。
4. 在甘特图查看时间分布、任务条与依赖关系。
5. 执行中更新 0～100 的进度，有管理权限时调整任务安排。

**实现结果：** 把筹备工作从口头分工变成可查看的时间计划；新任务分配可触发站内通知，任务截止可进入工作台。

**权限边界：** 查看、管理和更新进度分别授权。当前只有进度权的账号可更新本组织任务进度，并未实现通用“只准更新本人被指派任务”的可配置范围。前置依赖主要用于记录与展示，不能据此认定有完整的自动关键路径排程或资源冲突优化。

### 6.7 活动议程

**是什么：** 活动现场的步骤顺序表。

**流程：** 活动详情 → 议程 → 新增步骤 → 填写步骤序号、标题、备注 → 保存 → 按活动查看，必要时编辑或删除。

**实现结果：** 将活动流程固化成有序议程，便于筹备和现场执行查阅。当前议程以步骤信息维护为主，没有独立的现场主持倒计时系统。

### 6.8 座位安排与座位模板

**入口：** 活动详情 → 座位表。

**当前主要方式：可视化座位编辑器。** 可配置行列、过道和宽度、颜色区域及区域标签，支持点击或拖动批量设置、缩放、撤销重做、保存布局、导出 PNG，以及座位模板复用。

**流程：**

1. 根据场地设置行列和过道。
2. 选择区域颜色与标签，设置嘉宾、工作人员、观众等区域。
3. 在格子上编辑座位内容，必要时批量选择。
4. 保存到活动，导出图片供现场使用。
5. 有模板权限时，保存为模板或从已有模板创建布局。

**兼容方式：** 旧座位数据仍可按区域、排、列、就座人和座位类型查看；没有新版布局时保留旧矩阵和 Excel 式编辑。

**边界：** 一个活动启用新版布局后，旧版座位表转为只读归档。不是两套可同时随意编辑并自动互相同步的数据。

### 6.9 活动评分

**流程：** 活动详情 → 评分 → 建立评分维度及满分 → 按队伍／小组录入各维度得分 → 保存 → 查看总分、名次和备注。

**实现结果：** 保存活动评分规则及评分记录，自动将维度分数求和得到总分；页面按总分计算名次，同分采用并列名次（例如 1、2、2、4）。录入界面会检查维度分数是否在 0～该维度满分之间。页面提供新增与删除，服务端另外提供规则和记录更新接口。

**边界：** 当前总分是维度分数相加，页面名次根据当前成绩计算；虽然服务端也保存名次字段，但页面展示使用计算结果。当前没有完整的权重计分、去掉最高最低分、多评委独立打分或匿名评审流程。

### 6.10 应签名单与核验字段

**入口：** 活动详情 → 签到 → 名单与字段配置。

**流程：**

1. 准备 `.xlsx`／`.xls` 应签名单，以姓名、学号、班级等作为表头，包含名称为“姓名”的列。
2. 上传名单，每次上传形成分组，默认以文件名作为分组名称。
3. 打开“核验字段配置”，从已上传名单表头中勾选需要填写的信息，保存。
4. 保留名称为“姓名”的核验字段；当前扫码处理依赖该字段。主页面将勾选字段保存为必填文本。
5. 查看分组人数、已签／未签情况，跨分组搜索、重命名、删除分组或人员，必要时批量处理。

**实现结果：** 将签到对象和字段集中管理，可统计应签、已签、未签和签到率。

**边界：** 应签名单用于匹配与统计；其存在本身不等于所有扫码提交都会按名单强制拒绝非名单人员。字段模型和扫码渲染还支持数字、手机号等类型，但当前主要配置面板是勾选表头，不是完整的自定义表单设计器。当前主要签到页采用分组管理；服务端还保留旧名单和批量补签接口。

### 6.11 二维码签到与签到记录

**流程：**

1. 管理人员生成活动统一签到码并展示。
2. 参与者扫码打开公开页面，无需先登录。
3. 按活动配置填写信息并提交。
4. 管理人员查看签到记录、搜索人员、补录或删除记录，有导出权限时下载 CSV。
5. 结束签到时关闭；刷新生成新码会使旧码作废。

**实现结果：** 保存姓名、学号、班级、身份、签到方式、签到时间等现场记录；支持动态字段，记录可用于后续统计和加分核对。

**实际规则：**

- 一个活动使用统一码，当前生成的令牌有效期为 24 小时。
- 令牌保存在后端内存，后端重启后需要重新生成。
- 当天存在带人员的已发布活动排班时，会匹配排班人员、检查重复签到，并尝试联动对应班次考勤。
- 当天没有这类排班人员时，走纯活动签到记录流程，不自动产生班次到岗结果；当前这一路径没有相同的排班式重复拦截。
- 扫码填写信息是公开表单，不等于使用已登录账号认证本人，也没有完整的定位防代签能力。
- 公开扫码当前接受浏览器提交时间，未提交时用服务器时间；不能将其与登录后的本人打卡时间校验混为一谈。

### 6.12 活动关联材料与宣传

活动详情中的“材料”和“推文”页签分别复用材料归档与推文业务：可以在活动上下文中查询、上传或维护相关成果。它们仍遵守对应模块的权限和状态规则。活动基础查看权不会自动赋予材料读取、策划审核或宣传发布权限。

## 7. 排班、课表与无课信息

### 7.1 常规排班

**是什么：** 管理常规值班或例行事务，按周次、星期、时段、地点和人员建立安排。

**流程：**

1. 进入排班页，选择排班类型、周次或星期查看安排。
2. 新增班次，填写时间、地点、值班人员及相关说明。
3. 保存为草稿，核对后由有发布权的人员发布。
4. 发布后进入个人排班并建立考勤数据；需要撤销时取消发布。
5. 有导出权时，将筛选范围导出为 Excel。

**实现结果：** 将常规排班从即时生效改为“草稿—核对—发布”的受控流程。

**边界：** 草稿不进入个人有效排班。修改或删除已生效班次还需排班发布权限。当前文档依据包含这部分最新未提交实现，既有部署是否具备该流程需看部署版本。

### 7.2 我的排班与本人打卡

**入口：** 我的排班。

**流程：**

1. 查看周视图或全部安排，按关联活动筛选。
2. 核对日期、时段、地点和主班等工作信息。
3. 到班次日期和允许时间窗口后，使用本人打卡。
4. 到考勤页查看自己的结果。

**实现结果：** 从组织排班中取出与当前账号 ID 关联、状态为已发布或已结束的安排。

**规则：**

- 只按账号 ID 认领本人安排，同名不构成身份凭据。
- 没有关联本人账号的历史姓名记录，需要经办人先核对关联。
- 本人打卡仅限已发布班次；服务端校验日期、人员和时间窗口。
- 当前窗口通常从开始前 30 分钟到班次结束；开始后打卡记为迟到。
- 不能通过请求中的姓名、目标人员或状态替别人打卡，也不能自行指定正常／补签结果。

### 7.3 我的课程表

**入口：** 课表制作 → 我的课程表。

**流程：** 选择学期 → 在星期与节次网格中录入课程／占用情况 → 保存。

**实现结果：** 保存个人课表，作为共同空闲分析的数据来源。个人课表维护使用 `course:self:manage`，不代表可以批量管理组织课表。

### 7.4 共同空闲分析

**流程：** 课表制作 → 共同空闲分析 → 选择人员与学期 → 发起分析 → 查看热力图、各格空闲人数和推荐时段。

**实现结果：** 根据成员保存的个人课程表，找出参与者可共同参加会议或工作的时间。

**重要区别：** 该分析读取个人课程表，不读取批量导入形成的带周次部门无课表。没有个人课表数据时，不能用一次部门 Excel 导入推断该分析已经具有完整数据。

### 7.5 批量课表导入与部门无课表制作

**入口：** 课表制作 → 批量导入，需组织课表管理权。

**流程：**

1. 选择目标部门和学期。
2. 批量选择成员课表 `.xls`／`.xlsx` 文件。
3. 核对人员、课表格式和目标信息后确认生成。
4. 系统解析课程及周次，计算每个节次的无课人员与可用周次。
5. 查看成功文件数、失败文件及原因，修正后重导。
6. 核对结果，可下载 Excel、复制 Markdown。

**实现结果：** 生成部门、学期维度的持久化无课结果，供无课查询和活动自动排班使用；同一部门与学期重新生成后，后续使用最新结果。

**边界：** 依赖当前解析器可识别的课表格式；不代表能识别任意学校的任意 Excel 版式。文件部分失败时需要查看结果，不能只凭“生成完成”认定全部人员已纳入。

### 7.6 无课表查询

**流程：** 无课表 → 选择部门、学期和教学周 → 查看周一至周五各节次的空闲人员与周次标注 → 必要时返回批量导入更新。

**实现结果：** 为开会、活动岗位与临时协调提供可查的人员时间依据。

### 7.7 活动自动排班

**入口：** 活动排班 → 从无课表生成。

**流程：**

1. 选择已有活动，或填写自定义活动名称。
2. 选择日期范围和每天的时间段。
3. 选择参与部门、无课表学期；需要周次过滤时填写第一教学周的周一。
4. 设置每节次人数，留空表示不限。
5. 生成草稿，查看每天、每个节次的安排和人员缺口。
6. 核对或人工调整后，再发布。

**当前算法做了什么：**

- 将活动时段拆到相交的课程节次。
- 按部门无课结果，分别寻找每个节次可用的人。
- 有开学日期时按教学周过滤；未给该日期时跳过周次过滤。
- 多部门候选合并并按姓名去重。
- 在本次生成范围内，优先使用已安排次数较少的人，同次数按姓名排序。
- 没有候选的节次不创建空班次，结果可展示缺口。

**实现结果：** 创建活动排班草稿和排班人员，降低逐格人工选人的工作量。

**限制：**

- 自动匹配依赖已生成的部门无课表，当前只覆盖工作日；周末需人工排班。
- 均衡只针对本次生成范围，不是跨历史全部班次的全局最优。
- 当前不能据此认定已排除其他活动重叠、工作偏好、连续值班、技能等级等全部冲突。
- 自动账号关联依据姓名唯一命中，同名或未命中可能留下未绑定人员，需要人工核对。
- 自定义名称会尝试复用同名活动；没有时创建基础活动，后续仍应补全活动档案。

### 7.8 人工活动排班与重新生成

**流程：** 新增人工班次 → 选择活动、日期、时段、地点、备注和人员 → 保存草稿 → 复核发布。

已有班次可编辑、删除或按无课表重新生成人员。已发布班次的修改、删除与重新生成还要求发布权。人员变化会影响相应考勤，操作前应核对实际工作安排。

### 7.9 发布、取消与现场签到

排班状态包括草稿、已发布、已结束、已取消。当前提供单条发布、活动草稿批量发布及取消能力。

**发布结果：** 为排班人员预建待签到考勤；成员可以在本人入口查看有效安排。活动排班页还提供签到现场，可生成、刷新或关闭活动统一签到码，并查看与该活动相关的签到情况。

**边界：** 灵思或页面生成草稿不等于发布。生成权、草稿维护权、发布权、导出权分别授权。

## 8. 考勤管理与人工核对

### 8.1 组织考勤与本人考勤

**入口：** 考勤中心。

**流程：**

1. 选择“考勤管理”或“我的考勤”；只具备本人权限时只显示本人范围。
2. 按活动、日期或日期范围、人员、状态、活动类型等条件筛选。
3. 查看当前记录、已签到、待签到、缺勤／迟到等汇总。
4. 打开记录核对班次、签到时间、结果来源和审计记录。

**实现结果：** 将班次到岗情况集中为可查台账，组织管理和本人查看分开授权。

### 8.2 考勤如何产生

| 来源 | 当前行为 |
| --- | --- |
| 排班发布 | 为排班人员建立待签到记录 |
| 登录后的本人打卡 | 依据本人账号、服务端日期和时间确定结果 |
| 活动扫码 | 在当天有匹配已发布活动班次时，尝试将现场签到对应到考勤 |
| 自动考勤任务 | 活动班次结束后，将仍为自动来源的待签到记录置为缺勤 |
| 人工管理 | 经办人修正结果或补签，记录处理人和原因 |

**判定口径有差异：** 本人打卡以班次开始时间判断迟到；当前活动公开扫码的联动逻辑按时段归属，并在签到时刻晚于归属班次结束时间时记迟到。业务使用时应理解这两条路径，不能写成全系统统一的“开始后即迟到”。

### 8.3 人工修正与补签

**流程：** 选中异常考勤 → 查看记录 → 选择修正状态或补签 → 填写原因 → 确认 → 查看操作记录。

**实现结果：** 保存修改前后结果、原因、操作人和时间；修正后的人工来源结果不会被后续自动签到或缺勤处理随意覆盖。

当前可表达待签到、正常、迟到、请假、缺勤、早退、补签、取消等结果。记录“请假”不等于实现了成员提交申请、负责人审批的完整请假流程。

**权限：** 组织查看、本人查看和人工管理是不同能力。本人打卡权不能用于读取组织考勤、修正他人结果或删除记录。

## 9. 成员名册、届别与批量开户

### 9.1 届别管理

**流程：** 成员管理 → 届别管理 → 新增届别名称与备注 → 设为当前届 → 按届维护花名册。

**实现结果：** 将不同年份／届次的组织成员分开管理，保留历届资料。

一届结束时，可执行归档，将该届在职成员批量置为往届。此操作改变成员档案状态，**不自动等于停用其登录账号**；离任交接还需在用户管理核对账号状态和授权。

### 9.2 成员档案与日常维护

**管理资料：** 姓名、性别、学号、班级、联系方式、政治面貌、届别、部门、职务、状态和备注。

**流程：** 选择届别 → 按部门、职位、状态或关键词筛选 → 新增或编辑成员 → 进入详情核对资料与关联履历。

支持成员状态：在职、往届、退部、开除、离职；职务包括主任、副主任、部长、副部长、干事。支持单条和批量删除，界面筛选变化会清理已选行，减少跨届误处理。

**实现结果：** 形成按届别组织的正式成员名册，并展示人数、部门和职务构成。

### 9.3 Excel 导入导出

**流程：** 下载成员导入模板 → 按模板准备资料 → 选择目标届别 → 导入 → 查看成功／失败结果及行级问题 → 修正数据 → 需要时导出当前筛选范围。

**实现结果：** 批量建立或维护名册，减少重复录入；导出用于交接、核对和线下业务。

导入成员不会自动创建登录账号。模板下载和名单导出也有独立权限要求。

### 9.4 成员详情与工作履历

详情展示身份、任职、届别和状态，以及关联的排班次数、考勤记录数量、素拓累计等汇总。

**边界：** 汇总依赖有效关联和各业务数据，不是从姓名推导全部真实工作量的自动绩效考核。档案、账号和党务成员属于不同业务对象，需要正确关联和分别维护。

### 9.5 从花名册批量开户

**入口：** 成员或用户工作区中的“从花名册导入账号”。

**流程：**

1. 选择届别，系统列出有有效学号、在职且未开户的候选成员。
2. 勾选成员，单次最多 200 人。
3. 系统根据任职推荐可分配角色；经办人可逐人调整或批量设置。
4. 点击预览，逐人核对用户名、部门、角色和将获得的业务权限。
5. 确认创建，形成待设密账号和开户批次。
6. 下载包含一次性设密链接的 Excel，逐人交付。
7. 成员完成本人设密后激活。
8. 可重新打开本人最近 20 次开户结果，为未激活账号重新签发凭证。

**实现结果：** 将名册、业务角色和登录账号衔接，提供可核对的批量开户流程。

**规则：** 需要成员开户、用户管理、角色分配等治理能力；只能分配允许范围内的已发布角色。开户只赋予业务主角色，不同时授予组织管理员身份。角色或数据变化导致预览失效时，需重新核对。

## 10. 党务台账

### 10.1 党务成员资料

**入口：** 党务台账 → 成员。

**内容：** 姓名、性别、民族、出生日期、籍贯、学历、班级、学院、学号、支部、政治面貌、联系方式、身份证、家庭地址和备注等。

**流程：** 按姓名／学号／班级或发展阶段筛选 → 新增人员 → 维护资料 → 查看个人发展详情。

**实现结果：** 为党员发展业务建立个人档案。学号有重复校验；敏感字段有额外访问和脱敏处理，不能只凭入口可见认定可读取全部个人资料。

### 10.2 发展阶段与历程

阶段包括：入党申请人 → 入党积极分子 → 重点发展对象 → 预备党员 → 正式党员。

**流程：** 选中成员 → 记录阶段流转 → 填写期次、日期和备注 → 保存 → 在个人详情查看时间线。

**实现结果：** 保存阶段历史，将旧当前记录转为历史，维持新的当前阶段，同时更新人员政治面貌显示。

**规则：** 已有流转记录后只能推进到下一个阶段，不能任意跳级或回退；当前是台账记录和顺序校验，不是完整的法定发展程序审批或材料合规审查系统。

### 10.3 函调记录

在个人详情中维护父亲、母亲和其他社会关系人的姓名、所在党支部、党支部地址等资料，支持新增、编辑、删除。

**结果：** 形成个人函调相关资料台账。维护函调记录不代表已经自动生成、寄送或收到正式函件。

### 10.4 申请登记

维护申请人基本资料、联系信息、申请书日期、谈话人、条件情况和备注。

**流程：** 人员详情 → 登记 → 新增／编辑 → 核对信息 → 保存。

**结果：** 保存申请与谈话等登记事实，便于查阅和跟踪。

### 10.5 组织关系转移

维护预备／正式党员身份、线上／线下发起方式、签署日期、接收组织、电话、微信和备注等。

**结果：** 形成组织关系转移台账。当前没有与外部党务组织关系系统的自动办理、回执对接或在线转接承诺。

### 10.6 党务专项名单与 Excel 导入

**名单类型：** 推优、通过、汇总、发展对象、转移。

**流程：** 选择类型及期数 → 单条维护姓名、性别、学号、班级、支部和备注，或上传 Excel → 查看新增数和跳过重复数 → 核对名单。

**结果：** 将分散的阶段性名单集中为可检索台账；导入按名单类型、姓名、学号进行重复判断。

**边界：** 专项名单与个人发展历程分别存储。导入一份名单不等于自动为所有人建立账号、修改成员任职或推进党务发展阶段。

## 11. 内容宣传：推文与新闻稿

### 11.1 推文任务与草稿

**入口：** 内容宣传 → 推文，或活动详情 → 推文。

**管理资料：** 标题、所属活动、类型、负责人、截止时间、摘要、正文底稿、长图截图、封面 URL 等。

**流程：** 新建推文 → 指定活动与负责人 → 填写摘要和底稿，上传排版长图 → 保存草稿 → 预览核对。

**实现结果：** 把宣传任务与活动、人员和截止时间关联，支持稿件查找、负责人跟进和审阅。

### 11.2 推文审核与发布登记

```text
草稿 DRAFT → 待审核 PENDING → 已通过 APPROVED → 已发布 PUBLISHED
                         ↘ 已驳回 REJECTED → 修改并重新提交
```

**流程：**

1. 草稿准备完成后提交审核。
2. 有资格的人员审阅内容并通过或驳回。
3. 作者修改被驳回的稿件并重新提交。
4. 已通过后，在外部渠道完成发布，再回系统填写公众号链接并标记发布。
5. 发布后手动更新阅读量和在看数。

**实现结果：** 形成从写作、审稿到发布链接和传播数据的闭环台账。

**权限和状态规则：**

- 创建、编辑、提交、审核、发布、统计、删除分别授权。
- 编辑和删除仅对草稿／驳回状态开放；提交、发布、统计也检查对应状态。
- 编辑、提交、发布、统计和删除涉及作者限制；维护他人稿件还需额外 `article:manage`，且仍需具体操作权限。
- 有编辑权不代表有审核或发布权。
- 当前属于外部发布登记，不直接向公众号或社交平台发布，也不自动抓取阅读量。

### 11.3 新闻稿

**流程：** 新闻稿 → 新建 → 填写标题、副标题、正文、关联活动 → 保存草稿 → 预览／编辑 → 发布登记。

**实现结果：** 保存新闻稿内容和发布日期，支持关键词搜索、草稿维护、发布与删除。

**与推文的区别：** 当前新闻稿主要是草稿／已发布两阶段，不套用推文的完整审核状态机。稿件维护权和发布权分开。没有独立官网或校站自动投稿接口。

## 12. 材料档案、模板与文件访问

### 12.1 材料归档

**入口：** 材料与档案 → 材料库，或活动详情 → 材料。

**流程：**

1. 上传文件，填写材料名称、业务类型、标签和说明。
2. 关联活动及所属部门，保存归档。
3. 按分类、活动或关键词查找。
4. 打开归档详情，核对上传者、分类、关联信息。
5. 有权时预览／下载，必要时修改归档信息或删除记录。

**实现结果：** 为策划、总结、照片、表格等材料形成有业务归属的档案索引，减少文件散落。

**边界：** 上传文件与创建材料归档是两个步骤；仅上传成功不等于已经在材料库完成归档。当前没有完整的档案借阅审批、保管期限、销毁审批或电子签章流程。

### 12.2 模板资产

模板分类覆盖策划书、座位表、议程表、签到表、水牌、Logo、党徽、新闻稿等。

**流程：** 管理者上传模板并填写分类与用途 → 使用者按分类查找 → 下载使用；策划书可从业务编辑入口导入可用模板，座位布局使用专门的布局模板能力。

**实现结果：** 保存组织可复用资产，减少每次活动重复找文件。

**边界：** 通用模板库主要提供文件复用。不同类型是否能直接导入业务编辑器取决于具体功能，不能将“下载模板”统一描述成“自动套版并完成业务数据导入”。

### 12.3 文件上传、读取与敏感边界

当前支持受控的 Office 文档、图片、文本、压缩包等常见类型，采用允许扩展名清单及危险扩展名拦截；具体允许类型、文件大小还受组件和部署配置限制。

文件读取同时检查：组织、文件查看资格、敏感文件资格、上传归属或组织读取资格，以及策划附件的对象访问规则。

**实际效果：**

- 跨组织文件不能凭 ID 或旧地址直接读取。
- 有材料列表权限，不代表可以读取每个文件正文。
- 普通文件可受上传者及其部门归属限制；组织读取权另行授权。
- 敏感资料需要额外资格；策划附件沿用该版本的可见性约束。
- 文件不存在和无权读取可能呈现相同提示，避免暴露资源是否存在。

## 13. 素拓加分

### 13.1 单条加分台账

**入口：** 素拓加分。

**流程：** 新增加分 → 填写人员姓名、学号、关联活动、项目、分值、依据和备注 → 保存 → 按人员／项目或活动查询。

**实现结果：** 形成第二课堂／素拓加分流水，统计当前查询结果的人次和分值；分值按两位小数保存。服务端支持记录维护与删除。

**边界：** 当前是组织内加分台账，不自动同步学校第二课堂、教务或综测系统，也没有成员申请—老师审批—校级入账的完整链路。

### 13.2 按活动批量加分

**页面流程：**

1. 选择已完成或已归档活动。
2. 选择该活动的名单分组。
3. 从汇总人员中勾选加分对象。
4. 填写项目、分值和原因，核对人数与总分。
5. 预览后确认，批量写入并形成批次。

**结果：** 保存来源活动、批次及操作人，返回新增和跳过数量，便于核对。

**关键区别：** 页面人员池来自活动名单分组，不能仅凭进入该向导就认定“只给实际已签到人员加分”。应由经办人核对对象；灵思的批量加分工具另有签到人员预览逻辑。

**重复与撤销：** 当前按来源活动下姓名与学号检查已有记录；不等于同一活动可以无条件多次发放不同项目。后端和前端 API 封装提供按批次撤销能力，但当前加分列表没有完整的批次管理／撤销按钮流程。需要经有权维护流程调用对应接口，撤销会删除该批次流水，不是完整的财务式冲正记账。

## 14. 通知公告与群聊资料

### 14.1 通知公告

**流程：** 通知公告 → 有权人员填写标题和内容并发布 → 成员打开详情阅读 → 系统按账号记录已读；有管理资格者可删除。

**实现结果：** 将面向组织成员的公告形成统一列表，与站内通知联动。公告已读跟随账号保存，不只存在于浏览器。

服务端提供公告内容更新接口；当前主页面以发布、查看、已读和删除为主。旧页面部分说明仍使用“部长以上”等职位文案，实际操作应按当前权限执行。

### 14.2 群聊资料管理

**管理内容：** 群名称、分类、活跃／解散／归档状态、用途说明、关联活动、多个关联部门、群主或负责人、二维码和备注。

**流程：**

1. 建立或维护群聊分类。
2. 新增群资料，关联活动与部门，指定负责人，上传二维码。
3. 使用卡片或列表查找，按关键词、分类、状态、部门筛选。
4. 查看二维码和用途，群停止使用后归档或更新状态。

**实现结果：** 集中维护组织工作群的资料目录，降低交接中找不到群、二维码和负责人的问题。

**边界：** 这是群资料台账，不是微信消息客户端；不自动建群、拉人、读取聊天记录或发送微信消息。

## 15. 通知中心与业务提醒

### 15.1 个人消息处理

**流程：** 点击顶栏通知或进入通知中心 → 按消息类型查看 → 打开关联业务 → 单条或全部标记已读 → 设置接收偏好。

**实现结果：** 显示未读数量，支持分页、类型筛选、账号级已读和通知偏好；WebSocket 将业务更新推送到当前页面。

### 15.2 目前覆盖的业务事件

| 事件组 | 已接入事件 |
| --- | --- |
| 任务 | 任务指派 |
| 策划 | 提交、通过、退回、修改 |
| 宣传 | 新闻材料上传，推文指派、提交、通过、退回、发布、截止提醒 |

## 16. 灵思智能助手与自动协作

### 16.1 灵思工作区

**入口：** 灵思 `/agent`，所有登录用户可进入，实际能力按当前有效业务授权过滤。

工作区把任务列表、会话、过程、确认清单和工作成果放在同一界面。支持新建会话、回看历史、删除本人会话、查看能力清单、停止进行中的回答，以及对最后一轮进行重新生成等操作。

**典型流程：**

1. 新建任务，选择运行模式。
2. 描述业务目标；有需要时附加活动上下文，当前最多 5 个。
3. 阅读过程信息和查询结果，或补齐结构化表单中的缺项。
4. 发生写入前，核对待确认清单与工作成果。
5. 确认执行，查看成功、失败、跳过及业务链接。
6. 回到对应业务页继续审核、发布或核对。

### 16.2 三种运行模式

| 模式 | 能做什么 | 适用情况 |
| --- | --- | --- |
| 标准模式 | 查询并准备支持的写操作，确认后执行 | 创建活动、生成草稿、发布公告、批量加分等 |
| 只读模式 | 查询业务，不允许写工具 | 了解进度、核对记录、查找资料 |
| 资料问答 | 使用独立知识检索和引用回答流程 | 查询制度、操作指引、历史做法和可见资料 |

附加活动上下文是选择已有业务对象，不是上传任意本地附件；也不意味着灵思能任意读取电脑文件或任意操作外部网站。

### 16.3 当前查询工具清单

| 工具 | 当前用途 | 提问示例 |
| --- | --- | --- |
| `queryActivityOverview` | 查询活动与状态概况 | “最近有哪些执行中的活动？” |
| `queryActivityTasks` | 查询筹备任务和进度 | “这次活动还有哪些任务没完成？” |
| `queryMyPendingWork` | 汇总当前待处理任务 | “我现在有哪些待办？” |
| `queryAttendance` | 按本人或组织资格查询考勤 | “查一下我的考勤。” |
| `queryCommonFreeTime` | 根据个人课表分析空闲时段 | “这些人什么时候共同有空？” |
| `queryCreditRecords` | 查询素拓记录 | “这个活动有哪些加分记录？” |
| `queryNotifications` | 查询本人站内通知 | “我有哪些未读通知？” |

这些是当前注册工具的业务范围。用户能否调用、能返回多少内容，仍取决于工具权限、对象范围与敏感数据策略；自然语言理解效果还取决于真实模型和输入是否明确。

### 16.4 当前写入与草稿工具清单

| 工具 | 确认后形成什么 | 后续人工步骤 |

### 16.5 写入确认、信息补全与回执

**实现机制：** 写工具先进行准备和校验，生成表单或变更预览；用户确认后才执行。确认使用一次性凭证与并发／幂等处理，并在执行时重新检查权限。

缺少信息时，会要求补齐必要字段；补全后重新校验。发生权限变化、预览过期、对象改变或执行失败时，应按当前提示重新准备或核对回执。

**排班特别规则：** 预览不写库；确认时重算候选并核对指纹，人员和条件变化后要求重新生成。确认成功仍只写草稿，需要独立发布。

### 16.6 工作成果与版本

工作成果面板可集中展示本任务产物和版本，支持全文预览和复制、与前一版的变化比较、查看参考资料及上游成果版本。对支持编辑的字段进行修改时，会保留编辑输入，并在保存后产生新版本和相应待确认任务；不能把产物预览编辑理解成已直接修改正式业务记录。

执行后可沿业务链接查看结果。历史会话、任务和引用仍按归属、当前权限和敏感级别检查；权限被收回后，旧会话不是继续访问原资料的通行证。

### 16.7 自动多 Agent 协作

标准模式提供“自动协作”开关，后端根据任务需要选择专家分工，将进度和审查信息内联展示在会话过程区。

当前实现包含持久化运行、工作项、事件、依赖调度，以及顺序、依赖并行、审查／反思等编排能力。停止请求或取消协作会在执行边界处理，不能将点击停止理解为已提交业务自动回滚。

协作内容进入确认前可以接受独立模型的辅助审查，展示问题位置、原文、原因和依据；审查问题绑定具体成果版本。它提供质量检查线索，不替代人工核对，也不等同于自动通过业务审核。断线重连时可拉取请求和运行快照、补齐后续事件；当前可靠运行与恢复主要面向项目既有单 JVM 部署，不能据此认定多实例故障切换已经验证。

**边界：** 不再有独立的 `/agent/team` 页面。用户无需自行管理一组聊天窗口；专家可使用的工具仍受同一业务授权约束。

### 16.8 真实模型与规则降级

当前有 DeepSeek 提供方接入以及 stub 规则模式。未配置模型密钥，或调用失败发生降级时，会提示规则模式。

规则模式可用于部分固定查询与流程验证，不能替代真实模型的开放式理解、写作和资料综合能力。模型、超时、输出长度等由部署配置决定；系统设置页没有完整的模型供应商和密钥管理界面。

模型上下文与历史保存还经过数据分级策略：普通内容可正常使用，敏感内容执行相应脱敏／摘要处理，受限内容可以被阻止进入外部模型上下文，并引导到业务页面查看。这些规则与工具本身的读取权限同时执行。

## 17. 知识库与资料问答

### 17.1 知识库是什么

知识库是灵思可检索资料的台账与管理工作区，提供内容来源、正文分块、引用位置、事实快照和本人检索记录。

**它与材料库不同：** 材料库管理业务文件；知识库收录的是已接入来源和人工录入文档。上传一个文件到材料库，不等于系统已自动 OCR、抽取全文并让灵思检索。

### 17.2 已接入知识来源

| 来源 | 收录内容 | 主要边界 |
| --- | --- | --- |
| 人工文档 | 制度、上级文件、操作指引、FAQ 的正文与条款 | 按可见范围及附加访问条件读取 |
| 公告 | 组织公告内容 | 沿用公告来源资格 |
| 推文与稿件 | 已发布推文的正文与相关信息 | 草稿不等于已进入公共历史资料源；不代表独立新闻稿表全部收录 |
| 活动策划书 | 当前适配器支持的策划章节与正文数据 | 沿用策划版本可见性；不保证任意 DOCX 内容均已完整抽取 |
| 事实快照 | 成员构成、活动概况、党务结构等计数叙述 | 有截至时间，不等于实时数据库 |
| 成员名册投影 | 姓名、职务、部门、届别、状态 | 排除学号、手机号、政治面貌及备注等字段 |

当前使用关键词检索，MySQL 可用时使用 ngram 全文索引，必要时降级 LIKE。不是向量数据库方案。

### 17.3 内容台账浏览与检索

**流程：** 知识库 → 选择来源 → 搜索标题、正文或条款 → 按全文／标题匹配筛选 → 打开条目 → 查看来源、版本、最近索引与分块位置。

**结果：** 可以核对灵思究竟依据哪份资料回答，以及当前账号能查到哪些内容。T1 资料参与正文检索，T2 条目主要按标题匹配，二者不是同一检索深度。

### 17.4 人工文档维护

**流程：** 录入文档 → 填写标题、类型、分类、版本、摘要、正文 → 设置全员或受限可见范围 → 保存并建立索引 → 在内容台账核对。

**结果：** 将制度和操作手册转为有章节与条款结构的可引用内容。服务端还提供编辑和删除文档能力；当前页面主要突出录入与编辑。

文档维护权与重建索引权分开，维护资料不会自动扩大其他人的来源访问资格。

### 17.5 事实快照

当前注册的主要快照：

1. **成员构成：** 按届别汇总总人数及部门、职务、状态分布。
2. **活动开展情况：** 各活动阶段的数量分布。
3. **党员发展结构：** 政治面貌／发展结构的汇总数量。

**流程：** 事实快照 → 按模板或关键词查找 → 打开快照 → 查看内容、数据截至、生成时间、可见范围和更新说明。

**实现结果：** 给资料问答提供可核对时间口径的统计叙述。快照只包含计数汇总，不是全量成员个人明细。日常有定时生成，部分成员变更还触发重建；有维护权时可以手动刷新。

### 17.6 资料问答与引用

**流程：** 灵思切换资料问答 → 提出制度或历史资料问题 → 系统检索当前可见内容 → 根据命中片段回答 → 打开引用核对原始来源。

**结果：** 将答案与证据关联；查不到或证据不足时保留相应结果记录。

**边界：** 资料问答不执行业务写入。引用读取会实时检查来源资格，历史命中不保证当前仍可见。

### 17.7 本人检索记录与索引维护

本人检索记录可按提问与结果类型筛选，查看命中数、可用片段、耗时、回答提供方、降级及未答复情况。

维护工具提供：

- **重建全部检索索引：** 修复或重建检索副本，不修改来源正文或授权。
- **刷新业务快照：** 重新计算汇总、更新数据截至时间并执行历史保留清理。

页面统计基于当前账号可见范围；“我的未答复记录”不能解释为全部组织用户的检索质量报表。

## 18. 用户、业务角色与组织治理

### 18.1 当前授权模型

系统把业务访问与治理管理分开：

| 概念 | 表达什么 |
| --- | --- |
| 业务主角色 | 账号在活动、考勤、宣传等业务中可以执行哪些操作 |
| 组织所有者 | 组织治理来源，可管理委派及相关组织治理事项 |
| 组织管理员 | 所有者委派的管理能力和可授权上限，有期限及版本信息 |
| 对象约束 | 策划作者／指定审核人、推文作者、本人账号、文件归属等限制 |
| 已发布授权 | 真正参与运行时鉴权的角色配置 |
| 工作稿 | 尚未发布的权限编辑结果，不改变实际权限 |

当前是**一个业务主角色 + 独立治理身份**，通用授权范围只开放本组织 `ORG`。业务内存在本人、作者、指定审核人等规则，不代表已经提供通用 SELF、ASSIGNED 或节点子树范围编辑器。

### 18.2 用户账号管理

**流程：** 用户管理 → 按姓名／用户名／学号、部门、角色、状态或管理身份筛选 → 查看账号详情和有效授权 → 新增或编辑账号资料。

可维护用户名（创建后不可改）、姓名、学号、电话、部门、主角色和账号状态。新建账号需要至少 8 位初始密码。

用户管理提供启用、停用、批量状态处理（每次选择最多 100 个）和受保护的删除；删除需要输入用户名确认，系统所有者、管理身份和本人等对象有额外保护，不能把列表中出现的人都视作可删除对象。

**结果：** 管理登录资格和归属；停用保留历史业务及成员档案。

### 18.3 替换业务主角色

**流程：** 编辑用户 → 选择允许分配的角色 → 生成替换预览 → 查看实际生效权限的新增、撤销、范围和重点影响 → 确认替换并保存。

**结果：** 用户采用新角色授权，原业务角色权限不叠加保留。预览通常有效 5 分钟，角色或授权变化后需重新生成。角色变更和账号资料保存是可分别成功的步骤，遇到失败应阅读实际结果，避免以为整次操作必然全部回滚。

### 18.4 角色创建与职责模板

**入口：** 权限管理 → 业务角色。

支持搜索职责／名称、按状态和是否有工作稿筛选，查看来源、有效权限数、最近更新和关联账号。

可以空白新建、复制已有角色、从职责模板创建或组合模板。当前新增了九个职责模板；组合结果仍是一个独立角色，不是给账号叠加多个角色。

### 18.5 权限编辑与依赖

**流程：**

1. 选中角色，核对当前已发布配置和职责。
2. 按中文业务分组查找权限，查看操作说明、依赖、重点影响和不可授权原因。
3. 勾选操作时，确认必要依赖；撤销依赖时，核对连带撤销项。
4. 保存服务器工作稿。
5. 检查差异，准备发布。

支持搜索、仅看已授权、仅看改动、重点影响筛选。依赖超出管理员可授权上限时整次调整被拒绝；管理者不能通过组合勾选绕过自己的上限。

### 18.6 发布、停用、归档与删除

**发布流程：** 保存工作稿 → 填写原因 → 生成预览 → 核对中文差异、有效期及账号／岗位／有效邀请影响 → 确认应用 → 查看发布记录。

**实现结果：** 生成实际生效授权和不可变发布快照，并触发授权版本更新。

其他生命周期能力：

- 启用／停用／归档角色。
- 查看角色被哪些账号、岗位和有效邀请引用。
- 真正放弃服务器工作稿，使旧预览失效。
- 删除未发布且满足引用条件的角色。

受保护角色和只读用户默认查看已发布配置。停用角色即使存在历史发布内容，也不等于继续提供有效业务授权。

### 18.7 管理员委派与撤销

**流程：** 管理身份 → 选择对象 → 设置委派状态、可授权清单、期限及原因 → 预览 → 确认应用。

**结果：** 将组织管理能力授予指定账号，记录期限、版本和最近调整。旧的直接 PUT 变更入口已关闭，必须走预览确认。

**边界：** 委派管理员不等于自动获得全部业务数据读取权；当前管理能力沿用组织管理员预设，尚未完成任意细粒度受限管理员预设体系。

### 18.8 有效授权查询与对象级解释

可在用户详情和权限工作区查看有效权限及来源，并对以下操作给出对象级解释：

- 策划审核。
- 排班发布。
- 人工考勤修正。
- 文件读取。

**结果：** 帮助理解“为什么这个人不能对这条记录执行某操作”。解释接口不返回对象正文，也不执行目标动作。

### 18.9 审计、历史与迁移核对

治理记录支持按操作人／对象、动作和日期筛选，分页查看差异、原因、变更编号和结果。角色历史可以与当前生效配置比较，历史保持只读。

迁移核对用于检查旧授权到新权限目录的映射。当前已有只读预检、所有者确认、逐角色考勤保留／撤销决策，以及受指纹保护的切换和授权回退工具。

**部署边界：** 真实业务库是否已升级需要单独核实；已有落地记录明确说明正式业务库切换尚未执行。迁移预检、批准、应用和恢复涉及部署工具，不全部是管理页面内的一键业务流程。历史查看不等于已提供通用的一键历史恢复或审计导出。

### 18.10 主要细分业务权限

| 业务 | 当前拆分方式 | 对使用者的意义 |
| --- | --- | --- |
| 活动 | 查看、创建、编辑、阶段变更、删除 | 能改基本信息不一定能推进阶段 |
| 任务 | 查看、管理、进度更新 | 能更新进度不一定能增删任务 |
| 策划 | 查看、编辑、提交、审核 | 审核资格之外还检查作者／指定审核人 |
| 议程与评分 | 各自查看、管理 | 活动查看不直接开放全部子模块 |
| 座位 | 查看、编辑、模板 | 布局编辑与模板维护分别受控 |
| 排班 | 查看、维护、生成、发布、导出、本人查看、打卡 | 草稿生成不直接生效 |
| 课表 | 本人维护、组织管理、无课表查看 | 个人课表不扩大为组织管理权 |
| 考勤 | 本人查看、组织查看、人工管理 | 打卡权不能改他人结果 |
| 签到 | 查看、管理、导出 | CSV 导出也检查后端权限 |
| 宣传 | 创建、编辑、提交、审核、发布、统计、删除、维护他人稿件 | 编辑、审核、发布可由不同职责承担 |
| 新闻 | 稿件维护、发布 | 可写草稿不一定可发布 |
| 知识 | 阅读、文档维护、索引维护 | 可录文档不一定可全量重建 |
| 文件 | 查看、组织读取、敏感读取等 | 列表可见不保证文件正文可读 |
| 治理 | 用户、角色、分配、委派、审计等管理能力 | 管理权与业务访问权分别配置 |

## 19. 系统设置与协作实验

### 19.1 系统设置

| 分类 | 当前提供的功能 | 边界 |
| --- | --- | --- |
| 运行概览 | 应用版本、所属组织、当前身份、基础响应、知识检索模式、文件目录配置 | 基础响应正常不代表数据库和磁盘全部正常 |
| 组织与功能 | 组织名称、简称、类型、品牌色、领域包和管理入口 | 实际修改组织资料应进入组织管理 |
| 使用偏好 | 浅色／深色、用户列表标准／紧凑密度及预览 | 保存在当前浏览器 |
| 存储与诊断 | 上传目录、基础连接信息、刷新诊断 | 不提供完整磁盘空间、备份或读写验证 |

当前没有在此提供数据库密码修改、服务重启、备份恢复、模型密钥管理或存储迁移等完整运维控制台。

### 19.2 单 Agent 与多 Agent 评估

**入口：** 协作实验，且仅对显式启用的隔离组织开放；页面与接口还需满足相应管理／审计资格。

**流程：** 选择 P1 顺序或 P2 依赖并行 → 运行预览评估 → 查看本次与历史样本。

**实现结果：** 在相同任务和授权条件下比较通才与专家分工的运行情况，包括样本数、成功率、待处理、耗时、步骤、工具调用、实际模型、可用 token 用量、失败和降级等。

**边界：** 评估只采集预览，待确认操作采样后取消，不作为真实业务写入。运行成功率不等于业务完成率；业务质量未自动评分，未知费用不会伪造。离开页面不会自动取消后端评估。

## 20. 典型业务的完整操作流程

### 20.1 新组织首次投入使用

1. 注册组织，建立部门／小组和首个管理账号。
2. 登录后核对组织资料、主题和领域包。
3. 检查所有者与管理员身份，准备适合本组织的业务角色。
4. 保存并发布角色权限，避免停留在工作稿。
5. 建届别、导入成员名册，核对学号、部门与职务。
6. 从花名册预览并批量开户，逐人交付设密凭证。
7. 成员激活后，核对本人安排入口和实际授权。
8. 录入制度与指引，准备课表和常用模板，开始业务。

### 20.2 一场活动从立项到归档

1. 创建活动，明确名称、目标、日期、地点、负责人。
2. 拆分任务并在甘特图安排日期、部门和负责人。
3. 作者编写策划，保存后选择审核人提交。
4. 根据审核意见修订，全体指定审核人通过形成定稿。
5. 安排议程、座位、评分规则、应签名单和字段。
6. 如有岗位要求，准备无课表，生成／人工维护排班草稿并发布。
7. 执行现场签到，跟进任务与人员到岗。
8. 活动完成后核对考勤异常，整理评分、宣传与材料。
9. 宣传稿按流程审阅并登记外部发布。
10. 核对加分名单后办理活动加分，保存总结材料。
11. 人工推进活动到已完成、已归档，留存供后续查阅。

阶段、策划审核、排班发布和推文发布分别操作；上述步骤之间不是全部自动触发。

### 20.3 从课表到考勤

1. 批量收集支持格式的课表，按部门和学期生成无课表。
2. 检查失败文件与人员遗漏，核对教学周。
3. 设定活动范围、时段、参与部门和每节次人数，生成草稿。
4. 核对候选及账号关联，补齐缺口，周末使用人工排班。
5. 发布草稿，建立待签到考勤。
6. 成员本人打卡或通过活动现场签到联动。
7. 班次结束后核对自动缺勤，人工修正需填写原因。
8. 通过个人入口、考勤统计和审计记录完成复核。

### 20.4 宣传内容闭环

1. 关联活动并指定稿件负责人及截止时间。
2. 撰写底稿、摘要，上传排版长图。
3. 提交审阅，通过或按意见修改。
4. 在公众号等外部渠道实际发布。
5. 回系统登记链接、标记已发布。
6. 手动更新阅读与在看数据，归集相关素材。

### 20.5 换届与人员交接

1. 整理旧届成员、未完成任务、班次、宣传与档案。
2. 归档旧届成员，使在职转为往届。
3. 分别核对离任人员账号是否停用、主角色是否替换、管理员委派是否撤销。
4. 创建新届别并设为当前届，导入新成员。
5. 预览开户及主角色分配，交付设密链接。
6. 核对架构负责人、群资料、模板与制度文件。

当前不支持完整的组织所有者交接流程；“更改部门负责人”也不会自动完成管理身份移交。

### 20.6 使用灵思协助准备活动

1. 在标准模式附加目标活动。
2. 提出明确目标，例如“为该活动准备筹备任务和策划草稿”。
3. 补全缺少的日期、人员或内容要求。
4. 查看自动协作过程、工作成果及变更预览。
5. 逐项核对并确认支持的写入。
6. 根据回执进入业务页，继续人工审核、发布和核对。

灵思帮助准备和执行已接入操作，正式审核与发布状态仍由相应业务流程控制。

## 21. 当前能力边界与易混淆事项

| 容易误解的表述 | 当前准确含义 |
| --- | --- |
| “代码里有”就是“线上已可用” | 本文按当前工作区记录，包含未提交功能；部署与数据库需另行验证 |
| 注册组织就是加入已有组织 | 注册创建新组织；加入已有组织应由管理员开户 |
| 邀请码可直接入组 | 仅能生成，兑换入组未开放 |
| 部门负责人就是管理员 | 负责人、业务主角色和治理身份分开 |
| 多个职责模板就是多个角色叠加 | 模板组合生成一个角色，账号仍一个主角色 |
| 保存权限就生效 | 工作稿不生效，必须预览并发布 |
| ORG 权限能绕过作者限制 | 仍执行策划作者、指定审核人、推文作者和文件归属规则 |
| 活动归档会自动归档全部关联对象 | 活动阶段、文件、稿件、排班等有独立状态和处理流程 |
| 进入策划审核阶段就提交了策划 | 活动阶段与策划提交是独立操作 |
| 有策划查看权能看所有当前草稿 | 当前版本另限作者与所选审核人 |
| 任务进度有通用本人范围 | 当前进度权作用于本组织可用任务，未提供通用指派范围编辑器 |
| 自动排班已解决全部冲突 | 当前按无课节次与本次次数均衡，需要人工检查其他资源冲突 |
| 保存排班立即进入个人安排 | 当前保存为草稿，发布后生效 |
| 同名就可以看到个人班次 | 本人入口按账号 ID 关联，不按姓名冒领 |
| 活动扫码就是登录账号打卡 | 公开表单与已登录本人打卡是两条路径，认证和判时不同 |
| 到场签到就自动完成所有班次考勤 | 联动需匹配当天已发布班次和归属时段，不保证覆盖多个班次 |
| 已配置应签名单就强制名单准入 | 当前主要用于匹配、分组和统计；排班准入另有条件 |
| 选择“请假”就是完成请假审批 | 当前是考勤状态记录，没有完整个人请假审批流 |
| 所有加分对象都自动筛为已签到人员 | 页面批量向导取名单分组，需要人工核对实际加分对象 |
| 推文已发布代表系统替我发到公众号 | 这里登记外部发布链接和状态 |
| 阅读量是自动抓取的 | 当前由人员手动登记 |
| 材料上传后灵思都能读全文 | 知识库只索引已接入来源，不自动理解所有上传文件 |
| 事实快照代表实时数据 | 快照带数据截至时间 |
| 灵思可任意操作全系统 | 只调用注册工具，受当前权限、确认和对象规则限制 |
| 停止灵思会回滚已执行动作 | 停止在执行边界生效，已提交结果应查看回执 |
| 志愿包／社团包已交付完整专用系统 | 现有配置项不代表专用业务闭环已实现 |
| 系统诊断通过代表备份和数据库安全 | 当前主要是基础响应与配置展示，没有完整专项监测 |

尚不应算作当前完整业务功能的内容还包括：通用审批流设计器、多业务角色叠加、个人额外授权、通用节点子树范围、完整所有者交接、通用历史恢复／审计导出、外部教务和第二课堂自动对接，以及完整平台级多组织运营治理后台。
